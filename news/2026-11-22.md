## 1. dev.to 11-22 CleanBit — AI 코딩 에이전트는 대화 기록(base64 스크린샷), 옛 실행 파일, git worktree 복제본, 로컬 모델 가중치 네 군데에서 디스크를 먹고, `~/.claude/projects`가 11GB까지 갔다는 사례도 있다
- 날짜: 2026-11-22
- 출처: https://dev.to/fastlog/claude-code-cursor-and-codex-eating-disk-space-on-your-mac-heres-where-it-goes-51a7
- 요약: 글쓴이는 개발자 맥 한 대에서 읽기 전용 `du`로 재 보니 `~/.claude`가 1.9GB, `~/.local/share/claude`(옛 바이너리)가 902MB, `~/.codex`가 5.2GB였다고 적는다. 헤비 유저의 사례로는 256GB 맥에서 `~/.claude/projects`가 11GB, 스크린샷이 박힌 `.jsonl` 세션 하나가 262MB, 에이전트 worktree가 작업 공간을 95GB로 키운 경우가 든다. 지울 곳과 지우면 안 되는 곳(설정·인증 토큰·프로젝트 메모리)이 같은 폴더에 섞여 있으니 먼저 읽기 전용으로 측정하라는 것이 핵심이다. 글은 자기 앱(CleanBit)의 홍보를 겸하므로 숫자는 한 사람의 측정으로만 읽는다.
- 현실 적용:
  - 맥북 저장 공간이 부족한 개인 개발자 → `du -sh ~/.claude/projects ~/.claude/worktrees ~/.local/share/claude/versions`를 먼저 돌려 어느 폴더가 큰지 표로 본다 → 폴더 통째로 지우다 인증·메모리까지 날리는 일 없이 큰 곳만 정한다
  - 스크린샷을 자주 붙여 작업하는 디자인·QA 담당 → 지난 한 달 세션 `.jsonl`을 크기순으로 20개 뽑아 base64 이미지가 몇 MB인지 센다 → 이미지가 박힌 세션만 골라 정리하고 코드 위주 세션은 `--resume` 가능하게 둔다
  - `claude --worktree`·`EnterWorktree`로 병렬 작업을 돌리는 팀 → 3주 넘게 수정이 없는 `.claude/worktrees/*` 폴더를 나열하고 그 안의 `node_modules` 크기를 합친다 → 쓰지 않는 worktree를 한 번에 정리해 수십 GB를 되찾는다
  - CI 러너나 클라우드 개발 환경에 Claude Code를 올려 두는 플랫폼 팀 → 이미지 빌드 단계에서 `~/.local/share/claude/versions`의 옛 버전 개수를 찍고 최신 둘만 남기는 한 줄을 넣는다 → 업데이트가 쌓이며 컨테이너 이미지가 불어나는 것을 막는다
  - 이 저장소의 `/daily-lab` 루틴 → Actions 러너에서 끝난 뒤 `~/.claude` 크기를 로그에 한 줄 남기는 점검을 넣는다 → 매일 도는 자동화가 러너 디스크를 얼마나 쓰는지 숫자로 안다
  - 맥북 둘로 같은 프로젝트를 작업하는 사람 → 두 기기의 상위 세션 크기 표를 나란히 놓고 한쪽만 이미지가 많은 이유(캡처 습관)를 찾는다 → 이미지를 파일 경로로 넘기는 습관으로 바꿔 대화 기록이 불어나는 속도를 줄인다

## 2. dev.to 11-22 cybermax — 강제 푸시를 막는 20줄짜리 PreToolUse 훅: 정규식 세 개와 exit 2, 그리고 Claude 없이 `echo '{...}' | python3`로 시험하는 법

- 날짜: 2026-11-22
- 출처: https://dev.to/cybermax/stop-claude-code-from-force-pushing-a-20-line-hook-with-a-test-4b7e
- 요약: Bash 도구 호출 직전에 명령 문자열을 정규식 목록(`git push --force`, `git reset --hard`, `curl | sh`)과 대조해 걸리면 stderr에 이유를 쓰고 exit 2로 막는 훅을 보인다. exit 0은 허용, 2는 차단, 나머지는 막지 않는 오류이며, JSON 파싱이 깨지면 exit 0으로 빠져 세션이 잠기지 않게 하라는 조언이 붙는다. 시험은 Claude를 띄우지 않고 JSON 한 줄을 파이프로 넣어 종료 코드를 본다. 글은 스타터 키트 판매를 겸하는 비공식 글이다. 우리가 같은 정규식을 돌려 보니 `git push -fu origin b`, `git push origin +main`, `git -C . push --force`, `git push --mirror`는 통과하고, `--force-if-includes`는 막혔다.
- 현실 적용:
  - 팀 공용 저장소에 가드 훅을 넣으려는 리드 → 글의 정규식을 그대로 넣기 전에 위 통과 4건과 오탐 1건을 `echo … | python3 guard.py`로 확인하고 `-[a-z]*f` 형태·`+refspec`·`git -C` 접두를 보강한다 → 가드가 "막은 줄" 알았는데 짧은 옵션 한 글자로 뚫리는 일을 배포 전에 찾는다
  - 개인 `~/.claude/settings.json`에 위험 명령 훅을 쌓는 개발자 → 훅마다 `tests/` 폴더에 막을 것 5개·통과시킬 것 5개를 JSON 줄로 두고 `bash test.sh`로 돌린다 → 정규식을 고칠 때마다 이전에 막던 것이 풀리는 회귀를 잡는다
  - 훅 오류로 세션이 잠긴 경험이 있는 사람 → 훅 스크립트 맨 위를 `try: data=json.load(...) except: sys.exit(0)`로 감싸고 깨진 JSON을 넣어 exit 0인지 본다 → 훅 하나의 버그가 작업 전체를 막는 일을 없앤다
  - 무인 `claude -p`로 배포 스크립트를 돌리는 팀 → 같은 훅에 `git push origin main`(보호 브랜치 직푸시)도 한 줄로 추가하고 CI에서 가짜 호출로 시험한다 → 사람이 없는 자리에서 보호 브랜치로 밀어 넣는 사고를 훅이 먼저 막는다
  - 이 저장소의 `disaster-guard`·`hook-manners`·`prefix-guard` → 각 훅의 정규식에 위 4가지 우회 형태를 입력으로 넣어 보는 "우회 시도 목록"을 `test.sh`에 더한다 → 지금까지 "막는다"만 시험하고 "빠져나간다"는 시험하지 않았던 빈틈을 본다
  - 훅 대신 `permissions.deny`로 `Bash(git push --force*)`를 쓰는 사람 → 같은 우회 4건에 deny 규칙이 어떻게 반응하는지 `claude -p`로 한 번씩 시험한다 → 훅과 권한 규칙 중 어느 쪽이 더 촘촘한지 내 명령으로 비교한다

## 3. dev.to 11-22 r3v3rs3 — cmc 플러그인: 에이전트가 일하는 동안 `;;`로 시작한 말을 쌓아 뒀다가 턴이 끝나면 한 번에 전달하고, `>>`로 별도 git worktree의 서브에이전트에게 맡긴다 (Claude Code 2.1.330+ 필요)

- 날짜: 2026-11-22
- 출처: https://dev.to/r3v3rs3/cmc-stop-interrupting-claude-code-hold-your-messages-hand-tasks-to-subagents-25m6
- 요약: 에이전트가 일하는 중에 생각난 "테스트도 추가해 줘" 같은 말을 Enter로 끼워 넣으면 작업이 흔들리고, 기다리면 잊는다는 문제에서 출발한 플러그인이다. `;;`를 앞에 붙인 메시지는 보류되고 턴이 끝나면 순서대로 한 메시지로 전달되며, `/held`로 보내기·고치기·순서 바꾸기·지우기, `/cmc` 허브 패널로 서브에이전트에게 넘기기가 된다. `>> -m haiku -e low …`는 모델·노력도를 정해 별도 worktree에서 서브에이전트를 돌리고, 권한은 최대 `acceptEdits`다. 설치는 `/plugin marketplace add`로 하고 빌드 단계·런타임 의존성이 없다.
- 현실 적용:
  - 긴 리팩터링을 에이전트에게 맡겨 두고 다른 일이 떠오르는 개인 개발자 → 작업 중 생각난 요청을 `;; `로 시작해 두었다가 턴이 끝나면 `/held`로 순서를 고쳐 한 번에 보낸다 → 진행 중인 작업을 끊지 않고도 잊어버리는 요청이 없다
  - 서브에이전트에 CHANGELOG 정리 같은 곁가지를 맡기는 팀 → `>> -m haiku -e low -w`로 대화 전체를 컨텍스트로 주고 별도 worktree에서 돌린다 → 메인 작업 트리를 건드리지 않고 값싼 모델로 곁가지를 처리한다
  - 플러그인을 설치하기 전에 검토하는 보안 담당 → `plugin.json`과 훅 모듈에서 `acceptEdits` 상한이 지켜지는지, 네트워크·파일 접근이 있는지를 `grep`으로 먼저 본다 → 키 입력 중간에 끼는 플러그인이라 더 신중하게 설치 여부를 정한다
  - 모델 호출 비용을 따지는 사람 → `>>` 서브에이전트 한 개를 haiku·low로 돌리고 끝난 뒤 트랜스크립트의 usage를 합친다 → "곁가지는 값싼 모델에게"가 실제로 얼마나 싼지 내 숫자로 본다
  - 이 저장소의 `/daily-lab` 루틴 → 수집 중 떠오른 후속 주제를 `;;`로 쌓는 대신, 이미 있는 "다음 주제 선정" 절에 적는 방식과 비교해 하나만 남긴다 → 같은 일을 하는 두 도구를 쌓지 않는다
  - 서브에이전트가 별도 worktree를 만들어 쓰는 구조를 쓰는 팀 → 1번 항목의 worktree 디스크 점검을 같이 돌려 `>>`가 만든 worktree가 정리되는지 본다 → 보류와 위임을 쓸수록 늘어나는 복제본이 디스크에 쌓이는 것을 일찍 안다
