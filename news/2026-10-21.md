## 1. 테스트가 넘긴 진짜 홈 디렉터리를 스크립트의 `rm -rf`가 지웠다 — 가드는 Claude가 친 명령 한 줄만 보지, 그 명령이 부르는 스크립트 안은 못 본다
- 날짜: 2026-10-20
- 출처: https://dev.to/ryodevapp/my-macs-files-were-deleted-while-claude-code-was-building-a-guard-against-deleting-files-df9
- 요약: 글쓴이는 auto 모드로 밤새 앱을 만들게 둔 사이 맥 홈 디렉터리의 파일이 대량 삭제됐고, 푸시하지 않은 약 9일 치 커밋이 로컬 `.git`과 함께 사라졌다고 쓴다. 가장 가능성 높은 원인은 "인자가 홈이면 멈추는 가드"를 서브에이전트가 추가하는 중, 가드를 쓰기 전에 테스트(TDD의 RED 단계)를 돌렸고 그 테스트가 실제 홈을 인자로 `rm -rf`하는 스크립트에 넘긴 것이다(단정은 못 한다고 밝힌다). 권한 규칙·치명 경로 보호·auto 분류기는 명령 한 줄만 보므로 스크립트 안의 삭제를 못 막았고, 처방은 OS 수준 샌드박스(`sandbox.enabled`), 맥 밖 백업, 삭제 로직 테스트는 임시 폴더에서만 돌리기다.
- 현실 적용:
  - 셸 스크립트를 Claude에게 고치게 하는 개인 개발자 → `rm -rf "$1"` 같은 변수 삭제가 있는 `.sh`를 찾아 인자 검사(빈 값·`/`·`$HOME`) 유무를 표로 만든다 → 가드 없는 삭제 스크립트가 어디 있는지 오늘 안에 안다
  - 삭제·정리 스크립트에 테스트를 붙이는 팀 → 테스트를 `HOME`을 빈 임시 폴더로 바꾼 채 돌리는 래퍼(미끼 파일을 심어 두고 끝나고 확인)로 감싼다 → 가드를 쓰기 전 RED 단계에서 진짜 홈이 아니라 미끼가 지워진다
  - 서브에이전트에 TDD를 시키는 사람 → 프롬프트 대신 `settings.json`에 `sandbox.enabled: true`·`allowUnsandboxedCommands: false`를 넣고 쓰기 범위를 작업 폴더로 제한한다 → 테스트가 밖의 경로를 지우려 하면 OS가 거부한다
  - 푸시 안 한 커밋이 쌓이는 야간 작업 담당 → 에이전트가 커밋하는 즉시 `git push`(또는 `git bundle`을 다른 디스크로) 하는 훅을 하나 둔다 → 로컬 `.git`이 날아가도 잃는 건 마지막 커밋뿐이다
  - 이 저장소의 `disaster-guard`·`hook-exit-audit` → "명령 텍스트 가드는 스크립트 내부를 못 본다"는 한계 절과 정적 검사 후보를 README 6절에 적는 이슈를 남긴다 → 가드를 만능으로 믿는 오해를 막는다

## 2. Claude Code 2.1.305 — 무인 재시도 모드가 풀린 한도를 다시 확인하고, Linux 샌드박스에 중첩 사용자 네임스페이스 옵션이 생겼다
- 날짜: 2026-10-20
- 출처: https://github.com/anthropics/claude-code/releases/tag/v2.1.305
- 요약: `CLAUDE_CODE_RETRY_WATCHDOG`로 도는 무인 재시도가 사용 한도가 리셋 전에 풀렸는지 `CLAUDE_CODE_RETRY_WATCHDOG_USAGE_LIMIT_RECHECK_MS` 간격으로 다시 확인한다. `sandbox.allowNestedUserNamespaces`는 샌드박스 명령이 사용자 네임스페이스(Chromium, rootless podman)를 만들게 하는데, 그만큼 샌드박스의 파일 보호를 우회할 수 있다고 릴리스 글이 밝힌다. 2.1.304 회귀(도구 검색을 거부하는 Vertex·Bedrock·게이트웨이에서 모든 요청 실패)와 Workflow 재개 시 끝난 `pipeline()`·`parallel()`을 다시 돌리던 문제가 고쳐졌고, `allowedMcpServers`가 `${VAR}`를 env에만 쓰는 `managed-mcp.json` stdio 서버를 걸러내지 않게 바뀌었다. Agent SDK는 Python 0.2.169·TypeScript 0.3.305로 CLI 2.1.305를 번들했다. (10-20 news 2번 2.1.304의 후속)
- 현실 적용:
  - cron으로 `claude -p`를 돌리는 개인 개발자 → 래퍼의 환경 변수에 `CLAUDE_CODE_RETRY_WATCHDOG_USAGE_LIMIT_RECHECK_MS=600000`(10분)을 더한다 → 한도가 일찍 풀린 날 다음 창까지 헛되이 자지 않는다
  - Vertex·Bedrock이나 사내 게이트웨이를 쓰는 팀 → 2.1.304로 올린 뒤 모든 요청이 실패했는지 `claude -p "ping"`으로 확인하고, 실패했으면 2.1.305로 올려 같은 명령을 다시 돌린다 → 회귀 구간에서 끊긴 CI를 오늘 되살린다
  - Linux 러너에서 Chromium 스크린샷·rootless podman을 쓰는 팀 → `sandbox.allowNestedUserNamespaces`를 켜기 전에 켜면 우회되는 경로를 적은 승인 문서를 만든다 → 편의 때문에 샌드박스 보호를 말없이 푸는 일을 막는다
  - `Workflow` 스크립트로 에이전트 수십 개를 도는 사람 → 중간에 일부러 중단하고 `resumeFromRunId`로 재개해 완료된 agent가 다시 도는지 센다 → 재개가 비용을 두 번 쓰지 않는 것을 확인한다
  - 이 저장소의 `mcp-rule-audit` → `allowedMcpServers`가 `managed-mcp.json`의 `${VAR}`-in-env stdio 서버를 더는 거르지 않는다는 변경을 점검 규칙(allowlist 우회 가능성)으로 추가하는 이슈를 쓴다 → 업그레이드만으로 허용 목록 밖 서버가 켜지는 일을 감사 도구가 잡는다

## 3. Inference hooks가 Claude Enterprise에서 정식 출시 — 모든 프롬프트를 조직의 AI 보안 서버에 보내 allow/deny를 받고, 서버가 죽으면 차단·허용을 조직이 고른다
- 날짜: 2026-10-20
- 출처: https://platform.claude.com/docs/en/release-notes/overview
- 요약: Inference hooks는 사용자가 프롬프트를 보내면 Anthropic이 대화 기록을 조직이 운영하는 HTTPS 서버(Standard Webhooks 서명)에 보내 판정이 올 때까지(기본 5초) 기다리고, deny면 모델에 닿지 않는다. 이벤트는 `prompt`와 `tool_call`(Validate tool calls 켠 경우) 두 가지이며 claude.ai·Cowork·Claude Code·Claude Tag 등 한 설정이 전부 덮고 Bedrock·Google Cloud에서는 안 된다. 서버 오류·시간 초과 시 차단/허용 설정이 결과를 정하고, 섀도 모드·적용 비율·역할 제외로 점진 도입한다. 이미지 바이트는 검사되지 않고 판정은 allow/deny뿐 재작성은 안 된다.
- 현실 적용:
  - Enterprise 보안 담당 → 처음 한 주는 섀도 모드로 켜고 deny 후보가 하루 몇 건인지 센다 → 막기 전에 오탐 규모를 숫자로 안다
  - AI 보안 서버를 직접 만들어 보는 개발자 → 주민번호·API 키 정규식만 deny하는 50줄짜리 서버(서명 검증 포함)를 로컬에서 만들고 샘플 POST로 시험한다 → 판정 지연이 5초 제한 안에 드는지 먼저 잰다
  - 내부 DLP 도구를 이미 가진 회사 → 전사 보관용으로 항상 `allow`만 돌려주며 기록하는 서버로 시작한다 → Compliance API 폴링 없이 프롬프트를 실시간 보관한다
  - Claude Code를 쓰는 개발팀 → deny 시 `/rewind`로 되돌리는 절차를 팀 위키 한 장에 적어 둔다 → 막힌 대화가 이어서 계속 막히는 이유를 몰라 헤매는 시간이 줄어든다
  - 이 저장소의 `agent-scope-lint`·`spend-gate` → "서버가 죽었을 때 열기/닫기(fail-open/closed)"를 훅 설계 점검표에 항목으로 추가한다 → 가드의 장애 시 동작을 명시하지 않은 훅을 찾는다

- 날짜: 2026-10-20
- 출처: https://github.com/anthropics/anthropic-sdk-python/releases/tag/v1.17.0
- 요약: 1.16.0은 Admin API에 워크스페이스 레이트 리밋 갱신을 넣고, User Profiles를 정식으로 올리고, 분석 리포트 페이지에 `data_refreshed_at`·`has_more`를 붙이고, 클라이언트가 이름을 모르는 서버 전송 이벤트도 그대로 내보내게 했다. 1.17.0은 조직 웹훅 엔드포인트와 사용자 프로필 강제 이벤트, RBAC 그룹 소유자 접근 오류 코드를 추가했다.   - 사용량 리포트를 매일 내려받는 사람 → `has_more`가 참인 동안 다음 페이지를 이어 받게 반복문을 고치고 `data_refreshed_at`을 CSV에 같이 적는다 → 갱신이 덜 된 데이터를 최종 수치로 착각하지 않는다

  - 스트리밍 응답을 직접 파싱하는 개발자 → 새 이벤트 이름이 추가돼도 죽지 않도록 `else: log.debug(event.type)` 분기를 하나 넣는다 → 서버가 새 이벤트를 보내는 날 파서가 조용히 멎는 일을 막는다
  - 이 저장소의 `otel-tap`·`model-caps` → 두 폴더의 README 7절에 걸린 SDK 버전 번호를 1.17.0 기준으로 갱신해야 하는지 점검하는 이슈를 쓴다 → 오래된 버전 표기가 남는 것을 알린다

## 5. 무인 Claude Code 권한 템플릿 — 규칙은 deny → ask → allow 순으로 먼저 맞는 것이 이기고, 범위가 넓은 deny 하나가 좁은 allow를 이긴다
- 날짜: 2026-10-20
- 출처: https://dev.to/aobaworks/claude-code-permissions-best-practices-headless-template-28gc
- 요약: 글은 야간·cron 작업의 모든 도구 호출이 `settings.json`에서 확정된 allow/deny로 끝나야 하고 프롬프트가 남으면 안 된다고 한다. 처음에는 `dontAsk` 모드에 짧은 allow 목록, 일상 작업은 `auto`에 deny 목록, `bypassPermissions`는 비밀이 없는 일회용 컨테이너에서만 쓰라고 권한다. `Bash(aws *)` deny는 `aws s3 ls` allow가 있어도 그것을 막고, glob으로 못 쓰는 규칙(예: `bot/*` 브랜치에만 푸시)은 PreToolUse 훅으로 쓰라고 한다. 글쓴이는 공식 문서가 "권한 프롬프트에 답할 사람이 없을 때" `--permission-prompts none`을 권한다고 인용한다.
- 현실 적용:
  - 첫 야간 작업을 준비하는 개인 개발자 → `--permission-mode dontAsk`에 `Read`·`Bash(git status)`·`Bash(npm test)` 세 줄만 allow한 `.claude/settings.json`을 만들어 실행한다 → 규칙이 빠진 날 위험한 실행 대신 단계 건너뜀으로 끝난다
  - 이미 `Bash(git *)`를 allow한 팀 → 같은 파일에 `Bash(git push --force*)` deny를 더하고 `claude -p`로 강제 푸시를 시켜 거부되는지 본다 → "넓은 allow 안에 좁은 deny" 구성이 실제로 작동하는 것을 확인한다
  - 규칙 순서가 헷갈리는 관리자 → 규칙 목록을 deny/ask/allow로 나눠 출력하고 서로 가리는 쌍(넓은 deny가 좁은 allow를 무력화)을 찾는 스크립트를 짠다 → 쓸모없는 allow 줄을 지운다
  - `--dangerously-skip-permissions`로 CI를 돌리는 사람 → 러너에 비밀이 있는지 `env | grep -i key`로 확인하고 있으면 `dontAsk`로 바꾼다 → 비밀이 있는 곳에서 권한 우회를 쓰는 일을 끊는다
  - 이 저장소의 `.github/workflows/daily-lab.yml` → 현재 쓰는 권한 모드와 allow/deny 목록을 읽어 위 표 기준으로 한 줄씩 점검 메모를 남긴다 → 무인 실행 권한이 의도한 범위인지 매일 06:45 실행 전에 확인한다

## 6. 당신의 CLAUDE.md는 아마 너무 길다 — Claude가 규칙을 무시하면 더 쓰지 말고 줄여라, 파일당 200줄 이하
- 날짜: 2026-10-20
- 출처: https://dev.to/iggredible/your-claudemd-is-probably-too-long-17bi
- 요약: Claude Code는 시작할 때 현재 폴더부터 위로 올라가며 모든 CLAUDE.md를 읽고, 하위 폴더의 것은 그 폴더 파일을 처음 읽거나 고칠 때 로드하며, `/compact` 뒤에도 다시 주입된다. 글은 공식 문서의 "파일당 200줄 이하" 권고를 인용하며 규칙을 안 따를 때 `IMPORTANT`를 덧붙이면 더 길어져 역효과라고 한다. 넣을 것은 Claude가 추측 못 하는 명령·예외적 스타일·환경 함정이고 뺄 것은 코드를 읽으면 아는 것, 파일별 설명, 자주 바뀌는 정보다. 모노레포에서 남의 CLAUDE.md가 섞이면 `claudeMdExcludes`로 거른다.
- 현실 적용:
  - CLAUDE.md가 300줄 넘는 개인 프로젝트 → 줄마다 "지우면 Claude가 실수할까?"를 물어 아니면 삭제하고 `wc -l` 전후를 적는다 → 매 세션 고정 비용이 줄고 남은 규칙의 준수율이 오른다
  - 규칙을 대문자로 도배한 팀 → `grep -c 'IMPORTANT\|YOU MUST' CLAUDE.md`로 세어 한 줄만 남긴다 → 강조가 많아 아무것도 눈에 안 띄는 상태를 푼다
  - 모노레포의 서비스팀 → 서비스 폴더마다 짧은 CLAUDE.md를 두고 루트에는 공통 명령만 남긴다 → 해당 폴더를 건드릴 때만 읽혀 다른 팀 컨텍스트가 섞이지 않는다
  - 다른 팀 CLAUDE.md가 섞이는 사람 → `claudeMdExcludes`에 남의 경로를 넣고 `/memory` 목록이 줄었는지 본다 → 무관한 지침이 내 세션에 끼는 일을 없앤다
  - 이 저장소의 루트 `CLAUDE.md` → 현재 줄 수와 규칙 수를 세어 본다(`wc -l CLAUDE.md RULES.md`) → 매일 실행되는 루틴이 읽는 고정 컨텍스트 크기를 기록해 둔다
