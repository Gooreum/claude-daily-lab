## 1. 훅 매처 `mcp__lab`은 42번 중 0번 — 훅 매처와 권한 규칙은 문법이 다르다
- 날짜: 2026-10-11
- 출처: https://dev.to/rulestack/claude-codes-hook-matcher-mcplab-fired-0-times-in-42-calls-though-the-same-string-worked-as-a-250o
- 요약: 도구 3개짜리 MCP 서버와 로깅 훅으로 매처 22가지를 등록하고 헤드리스 세션 14번을 돌려 어느 매처가 실제로 발화하는지 셌다. 서버 접두사만 적은 `mcp__lab`은 권한 규칙으로는 서버 전체를 덮지만 훅 매처로는 0/42였다. 훅 매처는 정규식 문자가 없으면 도구 이름과 **정확히** 비교하기 때문이다. 동작한 형태는 `mcp__lab__.*`, `mcp__lab__ping`, `mcp__lab__ping|mcp__lab__echo`이고, 플러그인에 묶인 서버는 `mcp__plugin_labkit_lab__.*`처럼 플러그인 접두사가 붙는다.
- 현실 적용:
  - MCP 서버를 여럿 쓰는 팀 → `settings.json`의 PreToolUse 매처를 전부 `mcp__<server>__.*` 형태로 고치고, 훅이 "한 번도 안 울린" 것을 로그로 확인 → 가드가 켜진 줄 알고 안 켜진 상태를 끝낸다
  - 이 저장소 → 훅 매처·권한 규칙 문자열을 읽어 도구 이름과 대조하는 린터(어제 disaster-guard 옆에) → 매처 오타를 설정 시점에 잡는다
  - 플러그인 작성자 → README의 훅 예시에 `mcp__plugin_<plugin>_<server>__.*`를 명시 → 설치한 사람이 매처를 베껴 쓰고도 안 울리는 문의를 줄인다
  - 보안 감사 → "훅이 등록돼 있다"가 아니라 "훅이 발화한 횟수"를 증빙으로 → 설정 파일 리뷰만으로 통과시키는 감사를 막는다
  - 온보딩 문서 → 권한 규칙(`mcp__lab`)과 훅 매처(`mcp__lab__.*`) 비교표 한 장 → 같은 문자열을 두 곳에 복붙하는 실수 예방

## 2. 권한 규칙 예시 — `npm run`은 자동, `git push`는 묻고, force push는 거부
- 날짜: 2026-10-10
- 출처: https://dev.to/aicoding-guide/claude-code-permissions-by-example-auto-allow-npm-scripts-confirm-git-push-block-force-push-4blb
- 요약: 완성된 `settings.json`을 보여 준다. allow는 `Bash(npm run:*)`·`Bash(npm test)`·`Bash(npx tsc:*)`·`Bash(git diff:*)`·`Bash(git commit:*)`, ask는 `git push`·`npm install`·`npm uninstall`, deny는 `git push --force`·`-f`·`--force-with-lease`·`git push * --force`. 규칙은 deny → ask → allow 순으로 보니 allow가 ask를 못 덮고, "다시 묻지 않기"를 눌러도 ask 규칙이 남아 다음 push에 또 묻는다. `cd repo && git push --force`나 스크립트 안의 push는 문자열 규칙을 비껴가므로 원격 브랜치 보호가 결국 필요하다고 못 박는다.
- 현실 적용:
  - 프런트 팀 공통 설정 → pnpm·yarn·bun 변형까지 포함한 allow/ask 목록을 저장소 `.claude/settings.json`으로 → 새 팀원이 첫날부터 승인 피로 없이 테스트를 돌린다
  - 이 저장소 → 어제 disaster-guard의 훅 차단과 이 글의 deny 규칙을 비교해 "훅이 먼저냐 deny가 먼저냐"를 실측 → 두 겹 방어의 순서를 README에 적는다
  - 배포 담당자 → `git push`를 ask로 두되 `git push origin feature/*`만 allow로 → 기능 브랜치는 빠르게, main은 사람이 누른다
  - 파이썬 팀 → `pip install`·`uv add`는 ask, `pytest`·`ruff`는 allow → 공급망 위험이 있는 설치만 사람이 본다
  - 플랫폼팀 → 규칙 평가 순서(deny→ask→allow)를 사내 위키 한 줄로 → "allow를 넣었는데 왜 묻나" 문의를 없앤다

## 3. 비밀값이 트랜스크립트에 찍힌다 — 훅 리댁션으로는 부족하다
- 날짜: 2026-10-10
- 출처: https://dev.to/_d5c89c19f4997b0bdab27/claude-code-keeps-printing-my-secrets-why-hook-redaction-isnt-enough-58nb
- 요약: 에이전트가 설정을 확인하려고 `env`나 `cat .env`를 치는 순간 키가 대화에 들어가고, 거기서 답변·커밋·도구 호출 URL·로그로 번진다. 훅 리댁션은 값이 이미 환경에 들어온 뒤에 돌고, 모델이 도구 인자에 직접 적은 값은 못 잡고, 접두사 블록리스트는 새 키 형식을 놓친다. 대안은 값을 아예 컨텍스트 밖에 두는 것이다. 모델은 비밀값을 **이름**으로만 부르고, MCP 서버가 OS 키체인에서 값을 꺼내 그 명령의 자식 프로세스에만 주입한다. 명령마다 네이티브 승인 창을 띄우고, 알려진 값(base64 변형 포함)으로 사후 리댁션을 백스톱으로 둔다.
- 현실 적용:
  - 이 저장소 → "이름으로 부르는 비밀값" MCP 서버를 작게 만들어(키체인/환경변수 백엔드, 출력 리댁션) 어제 onfailure-secret-guard와 짝을 맞춘다 → 쓰기 차단 + 읽기 차단 (오늘의 선정)
  - 백엔드 팀 → `.env`를 읽는 대신 `secret-run DB_URL -- psql`처럼 이름을 넘기는 래퍼를 표준으로 → 트랜스크립트·세션 공유 링크에 값이 안 남는다
  - 보안팀 → `claude` 세션 로그(`~/.claude/projects`)를 알려진 값으로 주기 스캔 → 이미 샌 값을 회전할 목록이 나온다
  - CI → `-p` 배치의 `--output-format json` 결과를 저장하기 전에 값 기반 리댁션 → 아티팩트에 키가 남는 사고 방지
  - 개인 개발자 → `env`·`printenv`·`cat .env`를 deny 규칙으로 → 가장 흔한 유출 경로 하나를 0원에 막는다

## 4. 권한 프롬프트를 끄는 대신 마이크로 VM에 넣었다 — Mudroom
- 날짜: 2026-10-10
- 출처: https://dev.to/kernelhunter/i-run-claude-code-with-permission-prompts-off-so-i-put-it-in-a-vm-2eam
- 요약: 무료 오픈소스 Mac 앱·CLI Mudroom은 프로젝트 폴더의 APFS 복제본을 Linux 마이크로 VM에 넣고 에이전트를 돌린다. 실제 폴더는 마운트되지 않고, 결과는 파일별 diff를 보고 고른 것만 적용되며 되돌릴 수 있다. `~/.claude`는 마운트하지 않고 토큰은 키체인에, 네트워크는 허용 호스트만 로깅 프록시로 나간다. 일반 샌드박스는 프로젝트를 읽기·쓰기로 마운트해 작업 중 실제 파일이 바뀌고 git이 untracked·ignored 파일을 못 돌린다는 게 이유다. macOS 26·Apple silicon 전용, 미공증, 락파일 diff가 시끄럽다.
- 현실 적용:
  - 외부 저장소를 처음 열 때 → Mudroom처럼 복제본에서 돌리고 diff만 받기 → 클론 직후 설정 파일을 검사하지 않아도 된다(어제 YOLO 글의 반대 방향)

  - 플랫폼팀 → "에이전트가 바꾼 untracked 파일"을 git이 못 돌린다는 점을 근거로 작업 전 스냅샷 규칙 → 되돌리기 실패 사고 예방
  - 보안팀 → 네트워크 허용 호스트 로그를 검토 항목으로 → 에이전트가 어디로 나갔는지 사후 증빙
  - 개인 개발자 → 락파일을 diff 검토에서 자동 접기 → 적용 판단 시간을 줄인다

- 날짜: 2026-10-10
- 출처: https://dev.to/rulestack/two-claude-code-hooks-make-our-agent-wait-10-s-between-browser-calls-to-one-site-measured-at-2g19
- 요약: 같은 사이트에 너무 빨리 요청하다 계정이 정지된 뒤, 브라우저 도구 호출에 PreToolUse와 PostToolUse 훅을 같은 스크립트로 걸었다. Pre는 그 사이트의 직전 요청이 끝난 지 10초가 될 때까지 기다리고 120초 동안 바쁨 표시를 남겨 실패한 호출이 간격을 줄이지 못하게 한다. Post는 실제 종료 시각을 기록하고, 상태는 사이트별 잠금 디렉터리와 JSON 파일로 디스크에 둬 세션이 달라도 공유된다. 손으로 쓴 훅 이벤트를 흘려 넣어 01:18:18.058 → 01:18:28.058, 정확히 10,000ms를 확인했다. 한 머신만 덮고, 페이지 자체의 요청은 못 세며, `XMLHttpRequest`는 정규식이 놓친다.
- 현실 적용:
  - 스크래핑이 있는 팀 → 사이트별 최소 간격을 훅으로 강제하고 `claude -p` 배치 여러 개가 같은 디스크 상태를 공유 → 병렬 세션이 합쳐서 제한을 넘는 사고 방지
