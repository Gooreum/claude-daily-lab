## 1. Anthropic 11-10 "Your apps can now open in Claude, and Claude can work in them" — Asana·Notion·Confluence 같은 파트너 앱이 Claude 화면 안에서 열리고, Claude가 열려 있는 페이지·행·파일을 직접 고친다
- 날짜: 2026-11-10
- 출처: https://claude.com/resources/articles/interactive-connectors-full-tool
- 요약: 커넥터가 지원하면 도구를 대화 옆에 띄우거나 전체 화면으로 키우고, Claude에게 열려 있는 페이지·행·파일을 같이 고치게 할 수 있다. 변경은 도구 안에 실시간으로 보이고, 승인 방식은 기존 커넥터 행동과 같다. 웹과 데스크톱 앱 전 플랜에서 풀리는 중이며 Asana·Canva·Carta·Dropbox·monday.com·Smartsheet·Vercel·Webflow가 첫 묶음이다. 기술적으로는 MCP Apps(MCP 서버가 자기 화면을 들고 오는 확장)의 app tools·embedded sites 지원이 개발자 공개 프리뷰로 열렸다.
- 현실 적용:
  - 위키를 Confluence에 두는 개발 팀 → 장애 회고 문서를 열어 둔 채 "타임라인 표 아래에 재발 방지 항목 세 개를 쓰고 담당자 칸을 비워 둬"라고 시키고 변경을 그 자리에서 본다 → 문서를 복사해 붙여넣고 되돌리는 왕복이 없어진다
  - 사내 도구를 MCP 서버로 이미 만든 팀 → 가장 많이 쓰는 조회 화면 하나를 MCP App으로 감싸 프리뷰로 띄운다 → 결과를 텍스트 표로 읽는 대신 필터·정렬이 되는 화면을 대화 옆에서 쓴다
  - 회사 관리자 → 새 Claude(채팅+Cowork 통합)로 계정이 올라가기 전에 어떤 커넥터를 켤지 목록과 승인 정책을 정해 둔다 → 조직 설정이 켜지는 날 의도하지 않은 앱이 Claude 안에서 열리는 일을 막는다
  - 디자인을 하는 개인 → Canva 앱을 열어 사진 한 장을 "배경 정리하고 가로 1200으로"라고 고치게 한 뒤 전후를 비교한다 → 별도 도구로 옮겨 다니는 시간을 재 본다
  - 이 저장소의 매일 루틴 → 소식 항목 한 개를 Notion 문서로 열어 "현실 적용" 다섯 줄을 Claude와 같이 고치는 시험을 한 번 해 본다 → 사람이 눈으로 고치는 방식이 지금의 스크립트 점검(idea-grader)을 보완하는지 판단한다
  - 계약·정산 문서를 Box에 두는 사무 팀 → 계약서 사본을 열어 Claude에게 수정본을 만들게 하고 원본과 나란히 비교한 뒤 채택한다 → "수정했다"는 말이 아니라 바뀐 부분을 눈으로 확인하고 받아들인다

## 2. dev.to 11-12 "Claude Code below 2.1.251 let code in its Bash sandbox redirect an Edit outside the workspace on macOS (CVE-2026-88968)" — 파일 쓰기 경합 공지가 3주 사이에 두 번, 고쳐진 버전이 각각 2.1.129와 2.1.251
- 날짜: 2026-11-12
- 출처: https://dev.to/rulestack/claude-code-below-21251-let-code-in-its-bash-sandbox-redirect-an-edit-outside-the-workspace-on-2gp4 (원 공지: https://github.com/anthropics/claude-code/security/advisories/GHSA-5xjx-9qx6-jcrv, 앞선 공지 GHSA-5j29-h97v-84ch)

- 현실 적용:

  - 맥북으로 개인 프로젝트를 하는 개발자 → `~/.claude/settings.json`에 자동 업데이트가 꺼져 있는지 보고, 꺼져 있다면 주 1회 `claude update`를 일정에 넣는다 → 이번처럼 3주 간격으로 반복되는 공지를 놓치지 않는다

  - 이 저장소 → 공지 표(GHSA·수정 버전)를 한 파일로 두고 현재 버전과 대조하는 도구를 만든다 → 새 공지가 나올 때 표에 한 줄만 더하면 되는 점검이 남는다
  - 샌드박스를 켜 둔 팀 → 샌드박스가 셸 명령만 감싸고 Read·Edit·Write는 밖에서 권한 규칙으로 돈다는 구분(이 저장소 sandbox-lint에서 다룬 점)을 팀 문서에 적고, Edit 허용 규칙을 워크스페이스 안으로 좁힌다 → 샌드박스를 믿고 Edit 권한을 넓게 열어 둔 설정을 줄인다

- 날짜: 2026-11-12

## 4. dev.to 11-11 "Why Claude Code skips your CLAUDE.md rules, and what doesn't get skipped" — 긴 세션에서 규칙 한 줄은 수만 토큰 속에 묻히니, 잃으면 하루가 드는 규칙은 PreToolUse 훅으로 옮기라는 기준
- 날짜: 2026-11-11
- 출처: https://dev.to/clemcube/why-claude-code-skips-your-claudemd-rules-and-what-doesnt-get-skipped-gek
- 요약: 저자는 "`git add -A` 금지", ".env 출력 금지", "배포가 살아 있는지 URL로 확인" 같은 규칙을 CLAUDE.md에 두었는데도 몇 달 사이 한 번씩은 어겨졌다고 쓴다. 이유는 세션이 길어지며 규칙이 읽은 파일·출력·정정 속에 묻히고, 가장 가까운 신호가 "지금 커밋해 달라"여서 가장 짧은 길(`git add -A`)이 이기기 때문이라고 본다. 기준은 "한 번 어겼을 때 1분이면 고칠 수 있나"로, 아니라면 규칙을 모델 밖에서 도는 열 줄짜리 훅으로 옮기고 막을 때는 이유와 안전한 대안을 출력하라고 한다. 댓글은 `git add --all` 같은 별칭과 연쇄 서브셸로 패턴 매처를 우회할 수 있다고 지적한다.
- 현실 적용:
  - CLAUDE.md의 "절대 하지 마" 줄이 열 개 넘는 개발자 → 각 줄에 "어겼을 때 복구 비용: 1분/하루"를 적어 하루짜리만 PreToolUse 훅 후보 목록으로 뽑는다 → 훅으로 옮길 규칙이 정해진다
  - `git add -A`를 막고 싶은 팀 → 훅이 `-A`·`--all`·`.`를 모두 잡고 "이름으로 추가하라"는 이유를 출력하게 만든다 → 이 저장소 daily-lab 스킬의 "git add . 금지"가 문장이 아니라 장치가 된다
  - 훅 차단 문구를 "Blocked"로만 쓴 팀 → 문구를 "이유 + 해야 할 명령"으로 바꿔 한 주 동안 재시도 횟수를 세어 본다 → 막힌 뒤 같은 명령을 반복하는 낭비가 줄어드는지 본다
  - 보안 담당 → 우회 경로(별칭·연쇄 명령·Edit로 쓴 스크립트)를 훅 테스트 케이스로 먼저 적는다 → 댓글이 짚은 틈이 있는 훅을 배포 전에 걸러낸다
  - 규칙이 길어진 프로젝트 → 훅으로 옮기고 남은 CLAUDE.md를 절반으로 줄여 규칙이 지켜지는 비율을 같은 작업 3번으로 본다 → 줄인 문서가 오히려 더 잘 읽히는지 확인한다

- 요약: 건강보험사 Curative는 병원·의원과의 계약을 협상하는 에이전트 "Gwen"을 만들어 계약 한 건의 첫 연락부터 서명까지 맡겼다. 에이전트가 표준 요율표를 넘으려 하면 그 이유를 적게 하고 Sonnet 검토 에이전트가 승인 여부를 정하며, 비표준 건만 CEO가 본다. 글은 승인 대기열을 두는 것보다 두 번째 에이전트가 검토하게 하는 쪽이 더 잘 돌았고, 요율 검토 에이전트가 약 3분의 2를 처리한다고 쓴다. 주당 2,000~2,400건이 서명되며 2025년 한 해 2,100건과 비교된다.
- 현실 적용:
  - 고객지원 팀 → 환불 응답을 쓰는 에이전트 앞에 "환불 한도를 넘는 건은 이유를 적게" 하고 별도 검토 에이전트가 승인하도록 한다 → 사람 승인 대기열이 길어지는 문제를 줄이면서 예외는 사람에게 남긴다
  - 영업 팀 → 견적을 만드는 에이전트가 할인율 상한을 넘을 때만 사유 한 문단을 첨부하게 하고 검토 에이전트가 통과·반려를 정한다 → 영업 담당이 모든 견적을 보지 않고 예외만 본다
  - 이 저장소의 루틴 → 소식 항목을 쓰는 패스와 "현실 적용" 5개 규칙을 보는 검토 패스(idea-grader)를 분리해, 검토가 반려한 항목만 다시 쓰게 한다 → 수집과 점검을 한 번에 하다 생기는 느슨한 항목이 줄어든다
  - 계약서 검토를 맡은 법무 팀 → 검토 에이전트가 표준 조항과 다른 곳만 표로 뽑고 사람은 그 표만 본다 → 전체 계약서를 읽는 시간을 줄인다
  - 개인 프로젝트로 여러 에이전트를 쓰는 개발자 → 실행 에이전트는 Opus, 검토 에이전트는 Sonnet처럼 모델을 나눠 같은 작업 5건의 비용과 오류 수를 비교한다 → 검토만 작은 모델에 맡겨도 되는지 숫자로 정한다

## 오늘의 선정
- 2번의 "현재 Claude Code 버전을 보안 공지의 수정 버전과 대조"를 만든다. 공지 표(GHSA·CVE·수정 버전)를 JSON으로 두고, `claude --version`이 수정 버전 미만이면 알려 주는 CLI이자 SessionStart 훅 `cc-advisory`. 모델·키·네트워크 없이 검증한다.
- 이유: 두 공지를 GitHub 페이지로 직접 확인해 표가 사실이고, 오늘 당장 내 기기에 적용할 수 있다. 이 저장소에는 샌드박스 설정(sandbox-lint)·모드 점검(mod-audit)은 있어도 "버전 자체가 수정 버전 이상인가"를 보는 도구는 없다.
