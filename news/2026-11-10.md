## 1. Anthropic 11-09 "Introducing Claude Fable 5.2 and Claude Mythos 5.2" — 같은 모델을 안전장치 유무로 나눈 두 이름, Fable 5.1보다 출력이 최대 30% 빠르고 값은 입력 $8·출력 $40으로 내렸다
- 날짜: 2026-11-09
- 출처: https://www.anthropic.com/claude-fable-and-mythos-5-2 (보조: Simon Willison llm-anthropic 0.31 https://simonwillison.net/2026/Nov/9/llm-anthropic/, GeekNews 11-10 https://news.hada.io/topic?id=36910)
- 요약: Fable 5.2와 Mythos 5.2는 같은 모델이고, 사이버·생물 안전장치가 강한 쪽(Fable)이 모든 사용자에게, 검증 프로그램을 통과한 조직에는 Mythos가 열린다. Fable 5.1 대비 출력 속도가 최대 30% 빠르고 가격은 백만 토큰당 입력 $8·출력 $40으로 낮아졌으며, 속도를 최대 2.5배로 올리는 선택형 fast mode는 $16/$80이다. 대부분의 코딩·지식 작업은 Opus 5.5로 시작하고 필요할 때 Fable로 올리라고 권하며, Fable 5.2를 "조언자"나 작은 모델에 일을 나눠 주는 "오케스트레이터"로 쓰는 용도도 제시한다. Simon Willison이 다섯 단계 effort로 같은 그림 요청을 돌렸더니 max에서만 생각에 토큰 12.8만 개를 다 쓰고 이미지를 못 냈다고 적었다.
- 현실 적용:
  - 이 저장소의 매일 루틴 → 같은 날 소식으로 Opus 5.5와 Fable 5.2(xhigh)를 한 번씩 돌려 `run-receipt`(10-27)로 비용·소요 시간을 비교한다 → 하루 루틴 같은 중간 크기 작업에 값이 내린 Fable이 맞는지 추측이 아니라 숫자로 정한다
  - 월말 지출을 보는 팀 리드 → `cost-top`(10-30)으로 지난 30일 Fable 5.1 지출을 뽑아 입력 20%·출력 20% 인하분을 곱한 절감 예상액을 보고서에 적는다 → 5.2로 옮길지 결정하는 회의에서 근거 숫자를 바로 낸다
  - 스크립트에서 `effort`를 max로 박아 둔 개인 개발자 → 저장소에서 `grep -rn '"max"'`로 찾아 xhigh로 낮추고 같은 입력 3개를 다시 돌린다 → 생각 토큰이 상한(12.8만)에 닿아 빈 응답으로 끝나는 호출을 없앤다
  - 서브에이전트를 여러 개 정의한 사람 → 메인 세션만 Fable 5.2로 두고 탐색·요약 서브에이전트는 `model: claude-haiku-5-5`로 고정해 하루 써 본다 → 글이 제시한 오케스트레이터 구성을 값싼 쪽으로 먼저 시험한다
  - 보안팀 담당자 → 우리 팀 업무(취약점 분석 등)가 Mythos 접근 신청 대상인지 검증 프로그램 조건 문서와 대조해 한 장으로 정리한다 → Fable의 안전장치에 막히는 업무가 실제로 있는지 확인한 뒤에만 신청한다
  - 지연이 문제인 사내 코드 리뷰 봇 운영자 → fast mode를 켠 호출과 끈 호출의 응답 시간·단가를 PR 20건에서 비교한다 → 속도 2.5배가 두 배 단가($16/$80)를 낼 만한지 판단한다

## 2. platform.claude.com 11-09 "What's new in Claude Fable 5.2" — 이전 대화를 고쳐 보내면 400을 내는 검사(prefix check)가 모든 계정에 적용되고, 강제 tool_choice·thinking 끄기·옛 computer 도구도 400이 된다
- 날짜: 2026-11-09
- 출처: https://platform.claude.com/docs/en/models/fable-5-2/whats-new-fable-5-2 (릴리스 노트: https://platform.claude.com/docs/en/release-notes/overview)
- 요약: 요청을 직접 만드는 코드가 시스템 프롬프트·도구 목록·이전 메시지를 바꾼 뒤 Fable 5.2의 thinking 블록을 돌려보내면, "The block is bound to a different conversation"이라는 400이 난다. 이 검사는 계정 생성일과 상관없이 적용되고, 임시 해결로 베타 헤더와 `drop_block` 설정을 쓰면 블록이 버려지는 대신 출력 토큰이 늘 수 있다. 그 밖에 `thinking`의 enabled(budget_tokens)·disabled와 `tool_choice`의 any·tool은 400, 옛 `computer_20251124` 도구는 Bedrock을 뺀 모든 플랫폼에서 400이고, Fable 5.2 실행기의 advisor는 Fable 5.2나 Mythos 5.2여야 한다. Claude Code·claude.ai·Managed Agents·Agent SDK가 요청을 만드는 경우는 바뀌는 것이 없다고 한다.
- 현실 적용:
  - 대화 기록을 DB에 저장했다가 요약·삭제로 줄여 다시 보내는 챗봇 팀 → 지난 요청 로그를 이어 붙여 앞 요청의 메시지가 다음 요청에 그대로 들어 있는지 비교하는 점검을 오늘 돌린다 → 모델을 바꾸기 전에 400이 날 대화를 찾는다
  - 시스템 프롬프트에 오늘 날짜·사용자 이름을 매 턴 갱신해 넣는 서비스 → 그 줄을 마지막 user 메시지 앞쪽으로 옮긴다 → 앞부분이 안 바뀌어 prefix check도 통과하고 캐시 적중도 유지된다
  - `tool_choice: {"type":"tool"}`로 JSON을 뽑는 추출 파이프라인 → `auto`로 바꾸고 도구 정의에 `strict: true`를 넣거나 JSON 출력 방식으로 옮긴다 → 5.2로 올리는 날 400으로 파이프라인이 멈추지 않는다
  - Bedrock이 아닌 곳에서 `computer_20251124`를 쓰는 화면 자동화 팀 → `computer_toolset_20260801`로 이전하는 작은 PR부터 만든다 → 모델 교체와 도구 교체를 분리해 문제 원인을 가린다
  - advisor 도구로 Opus를 실행기로 쓰던 개발자 → 실행기를 Fable 5.2로 올리는 같은 커밋에서 advisor `model`도 `claude-fable-5-2`로 바꾼다 → 실행기만 올리고 advisor를 두는 구성이 400이 되는 실수를 막는다
  - 사용자별로 다른 API 계정을 쓰다 대화를 다른 계정으로 옮겨 이어 주는 SaaS → 옮긴 뒤 첫 요청의 `input_transformations`에 버려진 블록이 있는지 로그를 남긴다 → 계정을 넘으면 추론 맥락이 조용히 사라지는 구간을 알아낸다

## 3. Claude Code 2.1.321·2.1.322 (11-09·11-10) — Fable 5.2가 기본 Fable 모델이 되고, 쓰기 권한 검사 구멍 여럿과 MCP 로그인 토큰 유출 경로가 막혔다
- 날짜: 2026-11-10
- 출처: https://code.claude.com/docs/en/changelog (GitHub: https://github.com/anthropics/claude-code/releases/tag/v2.1.321)
- 요약: 2.1.321은 Fable 5.2를 기본 Fable 모델로 올리고, 저장된 Fable 5.1 선택을 Pro·Max에서는 바로 옮긴다(되돌리려면 `/model claude-fable-5-1`). 권한 쪽 수정이 많다: MCP 서버가 리다이렉트할 때 리프레시 토큰이 다른 호스트로 새던 문제, 읽기 전용 Bash 명령이 샌드박스 밖에서 묻지 않고 실행되던 경우, `cp`·`mv`가 디렉터리 안에 쓰는 파일에 deny 규칙이 안 걸리던 경우가 고쳐졌다. `claude remote-control`에 `--settings <file>`이 생겼고, 2.1.322는 Vertex(global·us·eu)에서 fast mode를 지원한다.
- 현실 적용:
  - 팀 `.claude/settings.json`에 `Write(...)`·`Edit(...)` deny 규칙을 둔 곳 → `cp x protected/`·`mv x protected/`로 규칙을 우회해 보는 시험을 2.1.321 전후 두 버전에서 돌려 결과를 비교한다 → deny 규칙이 실제로 막는다는 것을 버전별로 증명하고 최소 버전을 정한다
  - 사내 MCP 서버를 운영하며 OAuth 리다이렉트를 쓰는 개발자 → 모든 개발자 PC에서 `claude --version`이 2.1.321 이상인지 확인하는 한 줄을 온보딩 점검에 넣는다 → 리프레시 토큰이 다른 호스트로 새는 구버전을 쓰는 사람을 찾는다
  - 모델 ID를 문서에 적어 둔 팀 → `/model` 선택이 자동으로 5.2로 바뀐 사람과 5.1을 고정한 사람이 섞였는지 CI 변수·문서의 Fable 5.1 표기를 `model-stale`(10-25)로 훑어 고친다 → 같은 팀 안에서 모델이 달라 결과가 다른 일을 막는다
  - 원격에서 `claude remote-control`을 띄워 쓰는 개인 개발자 → 허용 명령을 최소로 줄인 설정 파일을 만들어 `--settings`로 넘긴다 → 휴대폰에서 시작한 세션도 항상 같은 권한 범위로 열린다
  - Vertex AI로 Claude Code를 쓰는 회사의 플랫폼팀 → 2.1.322로 올린 한 대에서 `/fast`를 켜고 같은 리팩터링 작업 시간을 재 본다 → 별도 계약 없이 지연이 실제로 줄어드는지 보고 개발자 전체에 열지 결정한다
  - 이 저장소의 훅 모음 → `deny-preview`(11-07)에 `cp`·`mv` 경로 형태(`/bin/cp` 등)를 입력해 보는 시험 케이스를 추가한다 → 이번 수정이 만든 새 동작을 미리보기 도구가 어떻게 판단하는지 확인한다

## 4. SDK 릴리스 11-09 — Python v2.7.0·TypeScript sdk-v1.7.0이 `claude-fable-5-2`를 넣고, 구조화 출력의 `const`를 보존하며, 비용 리포트에 상위 조직 묶음이 생겼다
- 날짜: 2026-11-09
- 출처: https://github.com/anthropics/anthropic-sdk-python/releases/tag/v2.7.0 (TypeScript: https://github.com/anthropics/anthropic-sdk-typescript/releases/tag/sdk-v1.7.0, Agent SDK: https://github.com/anthropics/claude-agent-sdk-python/releases/tag/v0.2.180)
- 요약: 두 SDK 모두 모델 목록에 `claude-fable-5-2`·`claude-mythos-5-2`가 들어갔고, 사용량·비용 리포트에 상위 조직 필터와 묶음, Admin API 쓰기에 `sandbox_egress_restricted` 오류가 추가됐다. 수정 쪽에서는 구조화 출력 스키마에서 `const`를 유지하고 `const`·`enum` 옆의 `type`만 지우도록 바뀌었다. Python은 Bedrock·Vertex 클라이언트가 `ANTHROPIC_CUSTOM_HEADERS`를 읽게 됐고 Bedrock 서명 오류도 고쳤다. Agent SDK(Python v0.2.180, TypeScript v0.3.321·0.3.322)는 릴리스 본문이 설치 링크뿐이라 변경 내용을 확인하지 못했다.
- 현실 적용:
  - 하위 조직이 여럿인 회사의 재무 담당 → 비용 리포트 호출에 상위 조직 묶음을 넣은 월말 스크립트를 한 번 돌려 본다 → 조직별 합계를 손으로 합치던 작업이 호출 한 번으로 끝난다
  - `{"type": {"const": "invoice"}}` 같은 판별 필드로 문서 종류를 구분하는 추출 서비스 → SDK 업그레이드 뒤 같은 입력 5건에서 판별 필드 값이 스키마대로 나오는지 회귀 테스트를 추가한다 → `const`가 빠진 스키마로 잘못된 종류가 나오는 경우를 잡는다
  - 사내 프록시 헤더가 필요한 Bedrock·Vertex 사용 팀 → 코드에 흩어진 `default_headers`를 `ANTHROPIC_CUSTOM_HEADERS` 환경변수 한 곳으로 모은다 → 클라이언트별 설정 차이로 어느 서비스만 프록시를 못 타는 일이 줄어든다
  - Python 버전을 고정해 둔 개인 프로젝트 → `pip install -U anthropic==2.7.0` 뒤 `model-stale`(10-25)을 다시 돌려 모델 ID 표시를 갱신한다 → 새 모델 이름을 코드에서 오타 없이 쓰는지 확인한다
