## 3. 의존성 없이 한 파일로 만드는 MCP 서버 — 도구 서버에 필요한 메서드는 `initialize`·`tools/list`·`tools/call`·`ping` 넷이고, 모르는 도구는 `isError` 결과가 아니라 JSON-RPC 오류로 답해야 한다
- 날짜: 2026-10-31
- 출처: https://dev.to/skibuff/a-zero-dependency-mcp-server-in-one-file-what-the-protocol-actually-needs-khj
- 요약: 글쓴이는 `node:fs`와 `node:readline`만 쓰는 119줄짜리 stdio MCP 서버로 프로토콜의 최소 요건을 보인다. 한 줄에 JSON-RPC 메시지 하나를 stdin으로 받아 stdout으로 한 줄씩 답하고, 로그는 stderr로만 보내며, `id`가 없는 알림(`notifications/initialized`)에는 답하지 않는다. 첫 버전은 모르는 도구와 빠진 인자를 `isError` 결과로 돌려줬는데 명세상 이는 프로토콜 오류(-32601, -32602)이고, 도구 실행 중의 실패만 `isError`로 둔다는 점을 고쳐 배웠다고 한다.
- 현실 적용:
  - 사내 도구(배포 상태 조회, 티켓 검색)를 Claude Code에 붙이려는 개발자 → SDK 없이 한 파일 서버를 만들고 `claude mcp add`로 붙인 뒤 첫 도구 호출까지 한 시간 안에 끝낸다 → 의존성 설치·버전 충돌 없이 먼저 가치를 확인한다
  - 직접 만든 MCP 서버를 동료에게 나눠 주는 사람 → 배포 전에 서버 프로세스를 띄워 메시지를 파이프로 넣는 점검 스크립트를 돌려 stdout에 로그가 섞이는지, 알림에 답하는지, 모르는 메서드에 -32601을 내는지 확인한다 → 클라이언트가 "서버가 멈췄다"고 보고하는 흔한 원인을 사전에 없앤다
  - MCP 서버를 쓰는 팀의 리뷰어 → PR에 "stdout에는 JSON-RPC만" 체크 항목을 넣고 `print()`·`console.log` 호출이 서버 파일에 있으면 막는다 → 디버그 출력 한 줄이 연결을 끊는 사고를 막는다
  - 서버를 비동기로 만드는 개발자 → 요청 두 개를 동시에 보내 응답이 `id`로 정확히 매칭되는지 시험하는 케이스를 추가한다 → 응답 순서가 바뀌어도 클라이언트가 틀린 결과를 받지 않는지 확인한다
  - 이 저장소의 `secret-envoy`(10-11)·`mcp-rule-audit`(10-17) → 둘 다 MCP를 다뤘지만 서버가 명세를 지키는지 검사하는 도구는 없으니 stdio 서버 적합성 점검 도구를 오늘의 후보로 올린다 → 직접 만든 서버의 프로토콜 실수를 키 없이 잡는다

## 4. 에이전트 PR을 위험 등급별로 나눠 리뷰하고, 명령 문자열을 훑는 훅 대신 PATH 맨 앞의 `gh` 래퍼로 `gh pr ready`를 막았다 (dev.to 주간 회고)
- 날짜: 2026-11-01
- 출처: https://dev.to/kompiro/from-requests-to-mechanisms-a-week-of-risk-tiered-review-and-a-gh-wrapper-for-agent-prs-karasu-36d0
- 요약: 글쓴이는 PR이 건드린 경로로 네 등급(High: 리뷰 도구·CI·락파일, Design, Medium, Low)을 나누고 등급별로 자동 리뷰 횟수와 사람이 diff를 읽는 여부를 다르게 둔다. High를 뺀 등급은 PR 본문에 로컬 리뷰 기록을 요구하고, 그 기록이 최신 커밋과 맞는지는 필수 체크가 확인한다. 명령 텍스트를 해석하는 Claude Code 훅은 우회를 계속 놓쳐서, 세션의 PATH 맨 앞에 둔 `gh` 래퍼가 실제로 받은 인자를 보고 리뷰 기록이 없으면 `gh pr ready`를 막는 방식으로 바꿨다고 한다.
- 현실 적용:
  - 에이전트가 PR을 자주 올리는 개인 프로젝트 소유자 → `.github/`·락파일·`package.json`을 건드린 PR은 반드시 직접 diff를 읽고, 테스트만 바꾼 PR은 CI 통과로 병합하는 규칙을 PR 템플릿 맨 위에 쓴다 → 읽는 시간을 위험이 큰 곳에 몰아 준다
  - 에이전트에게 `gh`를 쓰게 하는 팀 → 셸 PATH 앞에 `gh` 래퍼 스크립트를 두고 `pr ready`·`pr merge` 호출에서 리뷰 기록 파일이 없으면 exit 1로 막는다 → 훅의 정규식 우회(`g""h`, 변수 치환)와 무관하게 실제 인자로 판단한다
  - 훅으로 `git push --force` 같은 명령을 막고 있는 플랫폼 담당자 → 우회 입력 열 가지(따옴표 삽입, `$(...)`, 별칭)를 훅에 던져 막히는 수를 세고, 놓치는 것은 같은 이름의 래퍼로 옮긴다 → 명령 문자열 해석이 얼마나 새는지 숫자로 본다
  - 코드 리뷰 봇의 비용이 신경 쓰이는 리드 → 경로별 등급표를 만들어 High에서만 자동 리뷰를 여러 번 돌리고 Low에서는 끈 뒤 한 달간 놓친 결함 수를 비교한다 → 리뷰 비용을 위험에 비례하게 쓴다
  - 이 저장소의 `review-gate`(10-16)·`disaster-guard`(10-10) → 훅 우회가 어디서 생기는지 래퍼 방식과 비교한 메모를 남긴다 → 기존 훅의 한계를 기록으로 둔다

## 오늘의 선정
- 3번 "의존성 없는 MCP 서버"의 마지막 적용안을 고른다. 서버가 명세를 지키는지(알림 무응답, -32601·-32602, stdout 청결, `id` 매칭) 키 없이 검사하는 `mcp-probe`를 만든다.
- 이유: 앞선 MCP 결과물(`secret-envoy`, `mcp-rule-audit`)은 서버 제작과 허용 규칙을 다뤘고 서버 적합성 점검은 비어 있다. 요금제(1번)·차단 사례(2번)는 공식 근거가 약해 도구로 굳히기에 이르다.
