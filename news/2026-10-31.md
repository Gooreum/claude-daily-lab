## 1. Claude Code 2.1.316 — 서브에이전트 effort를 `CLAUDE_CODE_SUBAGENT_EFFORT`로 따로 정하고, `ultrathink`를 끄는 변수가 생겼으며, 모델 차단 설정에 걸린 요청은 400으로 이유를 알려 준다
- 날짜: 2026-10-31
- 출처: https://github.com/anthropics/claude-code/releases/tag/v2.1.316
- 요약: `CLAUDE_CODE_SUBAGENT_EFFORT`는 아무도 effort를 지정하지 않았을 때 서브에이전트가 쓸 수준을 세션 것과 따로 정한다. `CLAUDE_CODE_DISABLE_ULTRATHINK`는 `ultrathink` 키워드를 꺼 주고, `availableModels`·`deniedModels`로 막힌 모델을 부르면 어느 필드 때문인지 담은 400을 돌려준다. Claude apps gateway에는 그룹 공동 월 예산(`pooled_budget`)과 `managed.policy_mode: layered`가 들어왔고, PowerShell 훅이 `param`·타입 캐스트로 시작하는 명령에서 `exit 2`로 막지 못하던 버그와 `--restricted` 세션이 Read 허용 규칙 때문에 작업 폴더 밖 파일을 올리던 문제가 고쳐졌다. TS SDK 0.3.316은 2.1.316과 같은 기능을 맞추고 `permissions.blockReadsExemptPaths` 설정 타입을 더했다.
- 현실 적용:
  - 코드 리뷰 서브에이전트를 여러 개 돌리는 개인 개발자 → 셸 프로필에 `export CLAUDE_CODE_SUBAGENT_EFFORT=low`를 넣고 메인 세션은 `high`로 둔다 → 탐색용 서브에이전트가 매번 깊이 생각하며 토큰을 쓰는 것을 줄인다
  - 프롬프트에 "ultrathink"가 들어간 오래된 팀 템플릿을 가진 리드 → CI 러너 환경에 `CLAUDE_CODE_DISABLE_ULTRATHINK=1`을 넣고 같은 PR 리뷰의 토큰 사용량을 하루 전과 비교한다 → 문서에 박힌 키워드가 비용을 몰래 키우는지 확인한다
  - Windows에서 PowerShell 훅으로 위험 명령을 막는 팀 → `param(...)`이나 `[string]$x = ...`로 시작하는 명령으로 훅이 `exit 2`를 내는지 2.1.316에서 다시 시험한다 → 이전 버전에서 조용히 뚫려 있던 구멍이 닫혔는지 직접 본다
  - `availableModels`로 허용 모델을 제한한 플랫폼 팀 → 막힌 모델 이름으로 `claude -p --model <차단 모델>`을 돌려 400 메시지에 필드 이름이 나오는지 보고 사내 문서의 오류 해설에 붙인다 → 개발자가 "왜 안 되죠" 문의를 보내기 전에 스스로 원인을 찾는다
  - 이 저장소의 `sandbox-lint`(10-29)·`dir-trust`(10-28) → 새 설정 키와 환경 변수를 점검 규칙 후보 목록에 한 줄씩 적는다 → 무인 작업 점검 기준이 최신 릴리스를 따라간다

## 3. Cursor 마켓플레이스의 Claude Code 확장에 SSH 백도어 — 변조 확장이 자동 업데이트로 퍼져 공격자 SSH 키를 사용자 인증 파일에 넣고 역방향 터널을 만들려 했다 (GeekNews 전달, 독립 검증 못 함)
- 날짜: 2026-10-31
- 출처: https://news.hada.io/topic?id=36288
- 요약: GeekNews가 전한 내용으로, Cursor가 쓰는 OpenVSX의 Claude Code 확장이 변조됐고 Cursor 공지는 macOS·Windows용 2.1.312·2.1.313을 영향 버전으로 든다. 자동 업데이트로 설치된 변조본은 공격자의 SSH 키를 `authorized_keys`에 더하고, macOS는 사용자 LaunchAgent, Windows는 SYSTEM 권한 예약 작업(실패 시 시작 프로그램 스크립트)으로 남으며, 약 60초마다 연결을 재시도하고 호스트 정보를 8099번 포트로 보낸다고 한다. 영향은 최대 5,000명이라는 댓글 인용이 있고 Anthropic은 자사 시스템과 공식 채널은 영향이 없다고 밝혔다. 웹 검색으로는 이 버전·사건을 확인하는 별도 보도를 찾지 못해 침해 지표는 보도 내용 그대로 "미검증"으로 다룬다.
- 현실 적용:
  - Cursor로 Claude Code 확장을 쓰는 개인 개발자 → `ls ~/.cursor/extensions | grep -i claude-code`로 `2.1.312`·`2.1.313` 폴더가 있는지 보고, 있으면 네트워크를 끊은 뒤 3번 아래 항목을 점검한다 → 감염 가능성을 오늘 안에 가린다
  - 감염 의심 PC를 가진 사람 → `~/.ssh/authorized_keys`의 마지막 수정 시각과 낯선 키 줄을 확인하고, macOS는 `~/Library/LaunchAgents/`의 최근 plist를 연다 → 확장을 지워도 남는 백도어를 찾는다
  - 개발자 노트북을 관리하는 보안 담당 → 에디터의 확장 자동 업데이트를 끄고 승인된 버전만 쓰는 정책 초안을 만든다 → 마켓플레이스가 뚫려도 하루 만에 전 직원에게 퍼지지 않게 한다
  - 감염을 확인했거나 의심하는 팀 → `~/.ssh`의 개인 키, 저장소 토큰, 클라우드 자격 증명을 새로 발급하는 순서표를 만들어 둔다 → 초기 대응 때 무엇부터 바꿀지 헤매는 시간을 줄인다
  - 이 저장소의 `mod-audit`(10-18)·`dir-trust`(10-28) 옆 → 설치된 에디터 확장 폴더와 지속성 위치(authorized_keys·LaunchAgents·systemd 사용자 유닛·크론·시작 프로그램)를 한 번에 훑는 로컬 점검 CLI를 만든다 → 사건 공지를 기다리며 손으로 `ls`하던 확인을 한 명령으로 줄인다

- 출처: https://dev.to/ramdai_bista/a-claude-code-sub-agent-followed-614-windows-junctions-out-of-a-test-mirror-deleting-48000-live-2h23

- 현실 적용:

  - 서브에이전트에게 "폴더 정리해 줘"를 시키는 사람 → 작업 전에 대상 폴더 안의 링크 수와 가리키는 곳을 먼저 보고하게 하는 한 줄을 프롬프트에 넣는다 → 삭제 범위를 사람이 먼저 눈으로 본다
  - 아직 원격에 푸시하지 않은 프로젝트가 있는 사람 → 오늘 `git remote add`로 비공개 저장소를 만들어 푸시하거나 외장 디스크에 `git bundle`을 만든다 → 삭제 사고가 나도 내용을 되살릴 수 있다
  - 에이전트 실행용 샌드박스 폴더를 만드는 팀 → 실제 프로젝트를 링크하지 않고 `cp -r`로 복사해 쓰는 규칙을 문서에 쓰고, 복사본에 링크가 있으면 거부하는 스크립트를 둔다 → "작업 복사본"이 진짜를 가리키는 틈을 닫는다
  - 이 저장소의 `home-canary`(10-21) → 미끼 파일이 있는 가짜 HOME 안에 바깥을 가리키는 심볼릭 링크를 두고 `rm -rf`가 링크를 따라가지 않는지 보는 사례를 추가 이슈로 쓴다 → 삭제 가드 시험에 링크 따라가기가 빠져 있던 곳을 메운다

## 5. Claude Code가 `git add -A`를 못 하게 하려면 CLAUDE.md 규칙이 아니라 PreToolUse 훅으로 — 세션 두 개가 한 저장소를 쓸 때 한쪽이 상대의 미완성 리팩터링까지 커밋했다
- 날짜: 2026-10-30
- 출처: https://dev.to/clemcube/how-to-stop-claude-code-from-running-git-add-a-1ik6
- 요약: 글쓴이는 한 저장소에서 두 세션이 돌다 한쪽의 `git add -A && git commit`이 다른 쪽 작업을 끌어안아 이력이 엉킨 일을 겪었다. CLAUDE.md에 "이름으로만 add"라고 적었지만 긴 세션에서는 가끔 잊어버려, `git add`에 `-A`·`--all`·단독 `.`이 붙으면 stderr에 대안을 적고 `exit 2`로 막는 Bash용 PreToolUse 훅으로 바꿨다. 막는 문구에 "이름으로 추가하라"는 대안을 적어야 재시도나 포기를 피하고, 종료 코드는 1이 아니라 2여야 한다고 강조한다. 정상 명령(`git add .gitignore`)이 통과하는지도 시험하라고 한다.
- 현실 적용:
  - 병렬 세션을 한 저장소에서 돌리는 개인 개발자 → `~/.claude/hooks/`에 훅을 두고 `git add -A`·`--all`·`.`와 `git commit -a`를 막되 `git add .gitignore`는 통과시킨다 → 상대 세션의 미완성 파일이 내 커밋에 섞이지 않는다
  - CLAUDE.md에 "이렇게 하지 마"를 열 줄 넘게 쌓아 둔 팀 → 그중 어기면 사고가 나는 한두 줄을 골라 훅으로 옮기고 나머지는 그대로 둔다 → 지켜지면 좋은 규칙과 반드시 지킬 규칙을 나눈다
  - 훅이 막았을 때 에이전트가 같은 명령만 반복하는지 걱정하는 사람 → 차단 메시지에 "`git status`로 확인한 뒤 파일 이름을 직접 넣어 add 하라"를 적고 한 번 시험한다 → 에이전트가 대안으로 바로 넘어가는지 눈으로 확인한다
  - 훅 종료 코드를 점검해 본 적 없는 팀 → 10-19의 `hook-exit-audit`로 이 훅을 `exit 1`로 잘못 쓴 변형과 비교한다 → 막는다고 믿었지만 실행되는 경우를 가려낸다
  - 이 저장소의 `session-bulkhead`(10-14) → 같은 작업 트리의 `git checkout` 차단 규칙 옆에 `git add -A` 차단 규칙을 더하는 후속 이슈를 쓴다 → 병렬 세션 충돌 방지 목록이 하나 늘어난다

## 오늘의 선정
3번(Cursor 확장 SSH 백도어)을 고른다. 공급망 사고에서 가장 급한 일은 "내 PC에 그 확장이 있었나, 백도어가 남았나"를 몇 분 안에 가리는 것이고, 확장 폴더·`authorized_keys`·지속성 위치를 읽기 전용으로 훑는 CLI는 가짜 HOME 하나로 키·네트워크 없이 시험할 수 있다. 사건의 버전과 지표는 미검증 보도라 기본값으로 두되 인자로 바꿀 수 있게 한다.
루트 README의 `mod-audit`은 설치 전 모드 폴더를, `dir-trust`는 열려는 폴더를 보는 도구라 이미 설치된 확장과 PC 지속성은 겹치지 않는다. 후보로 남기는 것: 4번(링크 따라가기 삭제 가드 훅), 5번(`git add -A` 차단 훅), 2번(fast mode 폐기 린트).

### 1. sweep ← 5. `git add .` 금지 규칙을 훅으로

### 2. design-bounce ← 5. 게이트 훅의 종료 코드와 차단 문구를 시험으로 고정
