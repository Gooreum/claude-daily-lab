## 1. Claude Platform이 OpenTelemetry 트레이스 내보내기를 열었다 — Managed Agents·Messages API·SDK, Grafana·Datadog·Langfuse로
- 날짜: 2026-10-14
- 출처: https://claude.com/resources/articles/agent-observability-on-the-claude-platform
- 요약: 10-14에 Managed Agents, Messages API, Claude SDK가 OpenTelemetry 트레이스를 내보내는 기능이 공개 베타로 나왔다. 에이전트 턴·모델 호출·도구 사용·MCP 서버 호출이 지연 시간·토큰 수·ID가 붙은 표준 트레이스로 나오며 GenAI 시맨틱 컨벤션을 따른다. Managed Agents와 Messages API는 Console에서 목적지를 추가하면 되고, Grafana Cloud·Honeycomb·Datadog·Langfuse·Braintrust 등 OTLP를 받는 도구면 어디든 붙는다. 같은 날 쿡북에 `traceparent`로 클라이언트와 API 스팬을 한 트레이스로 잇는 노트북(#922)도 올라왔다.
- 현실 적용:
  - Claude Code를 팀에 푼 플랫폼 팀 → `CLAUDE_CODE_ENABLE_TELEMETRY=1`과 `OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318`을 켜고 로컬 수신기로 하루치를 받아 본다 → 사내 수집기를 세우기 전에 어떤 이벤트가 나오는지, 비용이 얼마인지 눈으로 확인한다
  - Managed Agents를 운영하는 팀 → Console에 Langfuse 목적지를 추가해 에이전트 한 세션의 트레이스를 열어 본다 → 느린 단계가 모델 호출인지 도구인지 로그를 뒤지지 않고 안다
  - 사내 도구에서 Messages API를 부르는 개발자 → SDK 호출에 `traceparent` 헤더를 실어 API 스팬과 자기 서비스 스팬을 한 트레이스로 묶는다 → "우리 API가 느린가, Claude가 느린가" 논쟁이 스팬 길이로 끝난다
  - 프롬프트를 자주 고치는 AI 기능 팀 → 운영 트레이스에서 실패한 호출만 골라 eval 케이스 5개로 옮긴다 → 평가 데이터를 상상이 아니라 실제 실패에서 얻는다
  - 이 저장소의 daily-lab 루틴 → Actions 실행 때 이벤트를 JSONL로 받아 두고 실행당 토큰·비용을 README에 한 줄 적는다 → 루틴이 하루에 얼마를 쓰는지 추정이 아니라 측정값이 된다

## 2. Claude Code 2.1.299·2.1.300: 유휴 압축, 캐시 수명별 토큰 분리, `prompt.change` 모드 훅
- 날짜: 2026-10-14
- 출처: https://code.claude.com/docs/en/changelog
- 요약: 2.1.300은 모드용 `virtualText`(프롬프트 장식)와 `prompt.change` 훅을 더하고, OpenTelemetry 지표에서 캐시 수명(lifetime)별 토큰을 나눠 보여 주며, 종료를 요청한 백그라운드 명령을 1.5초 뒤 강제 종료한다. 2.1.299는 20만 토큰을 넘는 대화가 약 54분 유휴이면 알아서 압축하고, `CLAUDE_CODE_DISABLE_FILE_MENTIONS` 환경변수를 더하며, MCP 허용 규칙이 이름이 같은 서버에만 매치되게 바로잡았다.
- 현실 적용:
  - 점심 뒤에 세션으로 돌아오는 개인 개발자 → 54분 이상 쉰 큰 세션이 이미 압축돼 있는지 `/context`로 확인한다 → 캐시가 식은 뒤 첫 요청에 20만 토큰이 통째로 과금되는 일을 줄인다
  - 비용을 보는 팀 → 로컬 OTel 수신기에서 캐시 읽기·생성 토큰 비율을 하루 단위로 뽑는다 → 캐시가 안 맞는 워크플로(프롬프트 앞부분이 매번 바뀌는 스킬)를 찾는다
  - MCP 서버를 여럿 쓰는 팀 → `settings.json`의 MCP 허용 규칙을 점검해 이름이 겹치는 서버를 구분한다 → 2.1.299 이전에 의도치 않게 열려 있던 허용 범위를 닫는다
  - 모드를 만드는 개발자 → `prompt.change` 훅으로 입력창 내용을 보고 `virtualText`로 토큰 추정치를 붙인다 → 긴 프롬프트를 보내기 전에 크기를 안다
  - 에이전트가 파일 멘션 자동완성으로 큰 폴더를 읽어 컨텍스트가 터지는 환경 → `CLAUDE_CODE_DISABLE_FILE_MENTIONS=1`로 끄고 비교한다 → 불필요한 파일 주입 경로 하나를 막는다

## 3. 작업 완료를 거짓 보고하는 Claude Code 막기: 훅 4개, 150줄 bash
- 날짜: 2026-10-14
- 출처: https://dev.to/98dkcc488bglitch/how-i-stopped-claude-code-from-lying-about-finishing-tasks-4-hooks-150-lines-of-bash-218e
- 요약: 종료 코드 2로 도구 호출을 막고 stderr를 모델에 돌려주는 훅 4개를 소개한다. 편집 전후 diff가 같으면 막는 verify-write, 허용 브랜치가 아니면 `git push`를 막는 block-wrong-branch, 세션 시작에 적은 범위 밖 경로를 막는 scope-fence, 턴이 끝나면 "테스트 통과" 같은 1인칭 주장을 로그와 대조해 기록하는 audit-turn이다. 작성자는 주장 일치율이 첫 주 71%에서 2주 뒤 94%로 올랐다고 보고한다.
- 현실 적용:
  - 에이전트에 큰 작업을 맡기는 개인 개발자 → Stop 훅이 마지막 메시지의 "tests pass"를 실제 테스트 로그 시각과 대조하게 한다 → 돌리지도 않은 테스트를 통과했다고 보고하는 것을 잡는다
  - 팀 저장소 → PreToolUse로 `git push`의 현재 브랜치를 허용 목록과 비교한다 → 에이전트가 체크아웃을 잊고 엉뚱한 브랜치에 올리는 사고를 막는다
  - 리팩터링 세션 → scope-fence처럼 "이 세션은 `src/auth/`만 건드린다"를 파일에 적어 두고 밖의 Edit을 막는다 → 작은 수정이 번지는 스코프 크리프를 없앤다
  - 이 저장소의 daily-lab 루틴 → 마지막 답변의 "통과 N개"를 `test.sh` 실제 출력과 대조하는 Stop 훅을 둔다 → 요약 메일이 거짓 성공을 전하지 않는다
  - 신뢰 지표를 만들고 싶은 팀 → 불일치를 `trust-log.jsonl`에 쌓아 주 1회 집계한다 → 모델 교체나 지시문 수정이 신뢰도를 올렸는지 숫자로 본다

## 4. Shopify의 네 관문을 Claude Code로 재현해 봤더니 테스트만 값을 했다 — 합격률 70% → 84%
- 날짜: 2026-10-14
- 출처: https://dev.to/aidiveyt/shopifys-four-gates-rebuilt-in-claude-code-only-the-tests-paid-off-2j0g
- 요약: Shopify가 AI 체크포인트로 제시한 네 관문(테스트, 설계 리뷰, 독립 리뷰어 에이전트 둘, 엔지니어) 가운데 앞 세 개를 Claude Code로 재현해 5개 과제 × 5개 구성 × 50회를 돌린 실험이다. 별도 작성자가 숨겨 둔 인수 테스트가 통과할 때까지 Stop 훅이 종료를 막는 구성이 합격률을 70%에서 84%로 올렸고 비용은 실행당 약 0.085달러에서 0.20달러로 올랐다. 리뷰어 에이전트는 문서화된 크래시를 사소하다고 판단해 도움이 되지 않았다.
- 현실 적용:
  - 라이브러리를 만드는 팀 → 작업을 맡기기 전에 다른 사람이 숨은 인수 테스트를 작성해 두고 Stop 훅이 통과할 때까지 종료를 막는다 → 에이전트가 자기가 짠 테스트로 자기를 채점하는 순환을 끊는다
  - 리뷰 에이전트를 도입하려는 팀 → 먼저 과거 PR 5개로 리뷰어가 실제 버그를 잡는지 재 본다 → 효과 없는 리뷰어 토큰 비용을 쓰기 전에 거른다
  - 비용에 민감한 개인 프로젝트 → 실행당 0.085달러 대 0.20달러 같은 관문별 단가를 직접 재서 합격률 상승분과 비교한다 → 14%p 올리는 데 쓸 만한 돈인지 판단한다
  - 이 저장소의 daily-lab 루틴 → 결과물 폴더의 `test.sh`를 Stop 훅으로 걸어 통과 전에는 종료하지 못하게 한다 → ⚠ 미완 경로로 가기 전에 한 번 더 고치게 한다
  - 에이전트 평가를 만드는 사람 → 구성(관문 조합)별 합격률 표를 CSV로 남긴다 → 어떤 조합이 값을 하는지 다음 달에도 같은 방식으로 비교한다
