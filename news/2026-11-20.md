## 1. dev.to 11-20 rulestack — PreToolUse 훅 둘이 같은 호출에 서로 다른 답을 내면 `deny > defer > ask > allow`로 합쳐지고, 2.1.319에서는 defer가 먼저 끝나면 ask가 사라져 명령이 확인 없이 실행됐다
- 날짜: 2026-11-20
- 출처: https://dev.to/rulestack/on-claude-code-21319-one-hooks-defer-erased-another-hooks-ask-and-the-command-ran-21322-2b7p
- 요약: 같은 Bash 호출에 걸린 PreToolUse 훅 두 개가 병렬로 돌며 각자 다른 결정을 내면, 문서의 우선순위(deny > defer > ask > allow)로 합쳐진다. 글쓴이는 settings 한 줄씩 지연 시간을 다르게 준 훅 쌍으로 18개 print 세션과 3개 대화형 세션을 2.1.319와 2.1.322에서 돌렸고, 2.1.319의 대화형 세션에서만 "defer가 먼저 끝나고 ask가 늦게 끝나면" 허용 규칙이 살아 있어 확인 창 없이 명령이 실행됐다. 2.1.321이 이 문제와 "내장 앱 훅의 ask 사유가 다른 훅의 사유를 덮는" 문제를 고쳤다. defer는 `claude -p`에서 도구 호출이 하나일 때만 지켜지고, 대화형에서는 경고만 남기고 무시된다.
- 현실 적용:
  - 훅 다섯 개 이상을 한 `settings.json`에 쌓아 둔 개인 개발자 → 훅마다 `deny`/`ask`/`defer`/무응답 중 무엇을 내는지 표로 뽑아 같은 호출에 둘 이상 걸리는 쌍을 오늘 찾는다 → 훅을 하나 더 얹었을 때 기존 가드의 답이 합쳐지며 바뀌는 일을 얹기 전에 안다
  - 아직 2.1.321 미만 CLI를 쓰는 팀원이 있는 팀 → `claude --version`을 점검해 `ask`와 `defer`를 같이 쓰는 훅 쌍이 있으면 경고하는 줄을 온보딩 스크립트에 넣는다 → 확인 창이 떠야 할 명령이 조용히 실행되는 구간을 업그레이드 전까지 막는다
  - `claude -p`를 서브프로세스로 감싸 승인을 자기 UI로 받는 도구 제작자 → 훅이 `defer`를 낼 때와 도구 호출이 여럿일 때(무시됨)를 나눠 처리하는 분기를 테스트 두 개로 박는다 → 병렬 도구 호출 턴에서 `defer`가 조용히 사라져 승인 UI가 안 뜨는 버그를 막는다
  - 공용 훅을 PR로 받는 팀 리드 → 새 훅 PR마다 "같은 호출에 걸리는 기존 훅과 결정이 충돌하나"를 CI에서 합성 입력으로 돌려 합쳐진 결과를 PR 댓글로 남긴다 → 리뷰어가 개별 훅은 맞는데 합치면 틀어지는 경우를 코드 읽기 없이 본다
  - 이 저장소의 훅 점검 도구 모음(`hook-exit-audit`·`matcher-lint`) → 훅 하나씩이 아니라 "같은 호출에 걸리는 훅 집합의 합쳐진 결정"을 보여 주는 도구를 하나 더한다 → 이 저장소에 쌓인 가드 훅(verify-gate·spend-gate 등)이 서로 덮어쓰는지 숫자로 본다
  - 프로젝트 훅과 사용자·관리형 훅을 둘 다 쓰는 회사 → 세 곳 설정의 `PreToolUse`를 합쳐 읽고 합쳐진 결정이 어느 파일의 훅 사유로 표시되는지 확인한다 → 확인 창의 `[settings]` 표시만 보고 어느 파일이 막았는지 몰라 헤매는 시간을 줄인다

## 오늘의 선정
- 1번 dev.to 훅 병합 글의 "같은 호출에 걸린 PreToolUse 훅 여럿의 결정이 합쳐지는 방식"을 로컬에서 미리 보는 **`hook-merge`**를 만든다: 설정 파일에서 호출(도구·입력)에 걸리는 훅을 matcher·`if`로 골라 실제로 병렬 실행하고, 훅마다 결정(exit 2·JSON `permissionDecision`)과 끝난 순서를 표로 보이며, 문서 우선순위 `deny > defer > ask > allow`로 합친 결과를 대화형과 `claude -p`로 나눠 보여 준다. `defer`가 대화형에서 무시되는 경우와 2.1.321 미만에서 ask가 사라질 수 있는 `defer`+`ask` 쌍을 경고한다.
- 이유: 기존 `hook-exit-audit`(훅 하나의 종료 코드)·`matcher-lint`(안 맞는 matcher)는 훅을 하나씩 본다. "여러 훅이 합쳐진 결과"는 이 저장소에 쌓인 가드들(verify-gate·spend-gate·disaster-guard 등)이 실제로 겹칠 때 가장 위험한데 지금까지 아무 도구도 보지 않는다. 모델·키 없이 지연이 다른 가짜 훅 스크립트만으로 전부 시험할 수 있다.
