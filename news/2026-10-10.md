## 1. Claude Code 2.1.295 — 훅 `onFailure: "block"`, 터미널 상태 프로토콜
- 날짜: 2026-10-08
- 출처: https://code.claude.com/docs/en/changelog , https://github.com/anthropics/claude-code/releases
- 요약: command/http 훅에 `onFailure: "block"` 옵션이 추가됐다. 훅 스크립트가 실행되지 않거나, 타임아웃되거나, 0/2 이외의 코드로 종료하면 기본값(`continue`)처럼 통과시키지 않고 해당 액션을 차단한다. 같은 릴리스에서 터미널이 Claude Code의 작업 중/대기 중/완료 상태를 표시할 수 있는 Program Status Protocol(OSC 7501) 지원, 무인 재시도 대기 상한 `CLAUDE_CODE_RETRY_WATCHDOG_MAX_WAIT_MS`, 모드용 `$.ui.notify` 등이 들어갔다.
- 현실 적용:
  - 사내 모노레포 → `.env`·클라우드 키·개인키 패턴을 막는 PreToolUse 훅에 `onFailure: "block"` → 훅 스크립트가 지워지거나 경로가 바뀌어도 가드가 조용히 꺼지지 않는다 (오늘의 onfailure-secret-guard)
  - 운영 DB·프로덕션 클러스터 → `psql prod`, `kubectl -n prod`, `terraform apply` 같은 명령을 Bash 훅으로 차단 → 에이전트가 자율 작업 중 운영 환경을 건드리는 사고를 구조적으로 막는다
  - 배포·결제 스크립트 → 실행 전 티켓 번호나 승인자 이름이 커밋 메시지에 있는지 훅으로 확인 → 감사 추적이 자동으로 남는다
  - 터미널을 여러 개 띄우는 개발자 → OSC 7501을 지원하는 터미널(Ghostty, kitty 등)에서 탭마다 "작업 중/대기 중"이 표시 → 어느 세션이 내 입력을 기다리는지 한눈에
  - 야간 무인 배치(`claude -p` 크론) → `CLAUDE_CODE_RETRY_WATCHDOG_MAX_WAIT_MS`로 재시도 대기 상한 → API 장애 때 밤새 기다리며 비용과 시간을 태우지 않는다
  - 긴 리팩터링을 시키고 자리를 비우는 사람 → 모드의 `$.ui.notify`로 30초 넘는 턴이 끝나면 알림 (오늘의 turn-notify-mod) → 화면을 계속 쳐다볼 필요가 없다

## 2. Claude Code 2.1.294 — prompt/agent 훅 판정 수정
- 날짜: 2026-10-08
- 출처: https://code.claude.com/docs/en/changelog
- 요약: "~를 차단하라" 식의 지시문으로 쓴 `prompt`/`agent` 훅이 차단해야 할 것을 통과시키던 문제를 고쳤다. Stop/SubagentStop의 `prompt` 훅 판정도 개선되어 Claude가 너무 일찍 멈추는 경우가 줄었다.
- 현실 적용:
  - 테스트 문화가 약한 팀 → Stop `prompt` 훅에 "변경한 코드의 테스트를 실행하지 않았으면 멈추지 말고 실행하라" → 자연어 한 줄로 "테스트 없이 끝내기"를 막는다
  - DB 마이그레이션이 잦은 서비스 → Stop 훅에 "마이그레이션 파일을 만들었으면 롤백 절차를 요약하지 않은 채 끝내지 마라" → 롤백 계획이 매번 따라온다
  - 서브에이전트를 많이 쓰는 워크플로 → SubagentStop `prompt` 훅에 "결론 없이 질문으로 끝나면 통과시키지 마라" → 반쯤 끝난 결과가 부모에게 올라오지 않는다
  - 커밋 규칙이 복잡한 레포 → `git commit` 전에 `prompt` 훅으로 메시지가 규칙(type, 한글, 50자)을 지키는지 판정 → 정규식으로 쓰기 어려운 규칙을 자연어로 검사
  - 고객 지원 자동 응답 → 응답에 개인정보나 내부 URL이 들어가면 차단하는 `prompt` 훅 → 이번 수정 전에는 "차단하라" 지시문이 통과되는 버그가 있었으니 업그레이드 뒤 재검증 필요

## 3. Claude Dashboards와 Claude Motion 베타 출시
- 날짜: 2026-10-08
- 출처: https://claude.com/resources/articles/dashboards-and-motion
- 요약: Dashboards는 BigQuery·Databricks·Snowflake·Salesforce 같은 데이터 소스에서 계속 갱신되는 대시보드를 만든다. Motion은 프롬프트로 짧은 애니메이션 설명 영상을 만들어 MP4로 내려받게 한다. Dashboards는 유료 플랜, Motion은 Team/Enterprise 플랜 베타다.
- 현실 적용:
  - 주간 경영 보고 → BigQuery/Snowflake에 붙인 Dashboards로 KPI 대시보드가 매주 스스로 갱신 → 스프레드시트 복붙 보고서 제작 시간이 사라진다
  - 신규 입사자 온보딩 → 시스템 아키텍처를 Motion으로 1분 애니메이션 → 위키의 긴 글보다 먼저 보여 줄 수 있다
  - 릴리스 노트 → 주요 변경 3가지를 30초 클립으로 → 사내 공지 채널과 고객 뉴스레터에 같이 쓴다
  - 세일즈·CS 팀 → 기능 설명 영상을 프롬프트로 즉석 제작 → 디자이너 일정을 기다리지 않는다
  - 보안 교육 → 피싱 대응 수칙 같은 짧은 교육 영상 시리즈 → 분기마다 내용만 바꿔 재생성
  - 유료 플랜이 없는 개인·소규모 팀 → 구조화 출력 스토리보드 + 단일 HTML 플레이어로 대체 (오늘의 motion-lite) → 같은 아이디어를 무료로

## 4. 블로그: Building effective agent automations
- 날짜: 2026-10-08
- 출처: https://claude.dev/blog/building-effective-agent-automations/
- 요약: Managed Agents로 Slack 채널과 GitHub PR을 읽어 매일 요약을 올리는 예약 에이전트의 참조 구현을 설명한다. 소스별 북마크로 증분 읽기, 읽기 실패를 "조용한 하루"가 아니라 "불가"로 보고하기, 게시 직전 재확인, 읽기 전용 권한과 실행당 지출 상한을 권장한다. 이 저장소의 일일 루틴 설계와 직접 맞닿는 조언이다.
- 현실 적용:
  - 이 저장소 → 매일 06:45 수집 단계를 소스별 북마크 증분 읽기로 바꾸기 (오늘의 feed-bookmark) → 같은 소식을 다시 읽지 않고, 읽기 실패를 "조용한 하루"로 오해하지 않는다
  - 제품팀 → 고객 피드백 채널(앱스토어 리뷰, 인터콤, 커뮤니티)을 매일 아침 한 장으로 요약하는 Managed Agent → 읽기 전용 권한과 실행당 지출 상한으로 안전하게
  - 플랫폼팀 → 쓰는 라이브러리들의 GitHub 릴리스 피드를 북마크로 추적해 보안 패치만 골라 알림 → Dependabot이 못 보는 "릴리스 노트에만 적힌" 변경을 잡는다
  - 온콜 교대 → 지난 24시간의 알림·인시던트·PR을 요약해 다음 담당자에게 자동 전달 → 인계 회의가 짧아진다
  - 마케팅·채용 → 경쟁사 블로그와 채용 공고의 변화만 증분으로 모아 주간 보고 → 사람이 매주 사이트를 돌지 않아도 된다
  - 모든 크론 봇 공통 → "게시 직전 재확인"과 "실패는 불가로 보고" 원칙을 체크리스트로 → 조용히 틀린 보고가 가장 비싸다

## 오늘의 선정
**훅 `onFailure: "block"`** (소식 1). 훅이 실패하면 통과시키던 기존 동작을 fail-closed로 바꿀 수 있는 옵션이라, 비밀값 커밋 방지 같은 보안 가드 훅에서 바로 쓸모가 있다. 작은 PreToolUse 훅과 설정, 테스트로 하루 안에 만들 수 있다.
