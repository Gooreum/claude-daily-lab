## 1. Claude Enterprise 보안·관리 업데이트 — 설정을 권장 구성과 견주는 보안 센터(베타), 프롬프트·도구 호출 사전 점검 추론 훅 정식 출시, 멤버를 모든 기기에서 로그아웃시키는 Admin API(`POST /v1/organizations/users/{user_id}/sign_out`, 베타 헤더 `admin-user-sign-out-2026-10-08`), 관리자가 직접 쓰는 IP 허용 목록(베타)
- 날짜: 2026-11-05
- 출처: https://claude.com/resources/articles/claude-enterprise-security-updates (API 쪽 공지: https://platform.claude.com/docs/en/release-notes/overview, 사용법: https://platform.claude.com/docs/en/manage-claude/user-management#sign-a-member-out-everywhere)
- 요약: 보안 센터는 채팅·Cowork·Claude Code의 보안 설정 현재값과 권장값을 한 페이지에 나란히 보여 주고 보고서로 내려받게 한다. 추론 훅은 사용자 프롬프트와 도구 호출을 조직의 데이터 유출 방지 도구로 보내 검사하게 하며 정식 출시됐다. `write:members` 범위의 Admin API 키로 멤버의 로그인 세션·신뢰 기기·이 조직 OAuth 토큰을 한 번에 끊을 수 있지만, API 키·클라우드 세션·루틴은 끊지 못하고 주 소유자(primary owner)는 400으로 거절된다. 같은 요청을 다시 보내도 안전(멱등)하고, 진행 중이던 로그인은 5분 뒤 한 번 더 보내야 한다.
- 현실 적용:
  - 퇴사·기기 분실을 맡는 IT 담당 → 멤버 이메일 목록을 받아 조회→로그아웃을 일괄로 보내고, 주 소유자·404·429를 표 한 장으로 돌려주는 CLI를 만든다(`--dry-run` 포함) → 콘솔에서 사람마다 클릭하던 대응이 한 줄 명령이 된다
  - 보안 사고를 맡는 팀 → 로그아웃 5분 뒤 같은 요청을 자동으로 한 번 더 보내고 감사 로그에 로그인이 남았는지 확인하는 점검표를 런북에 붙인다 → 진행 중이던 로그인이 살아남는 틈을 닫는다
  - 사내 Claude Code 도입 담당 → 로그아웃 후에도 살아 있는 것(API 키, 클라우드 세션, 루틴)을 목록으로 뽑아 사람별 후속 조치 체크리스트를 같이 출력한다 → "로그아웃했으니 끝"이라는 착각으로 루틴이 계속 도는 일을 막는다
  - 사내 DLP 도구를 운영하는 보안 엔지니어 → 추론 훅의 사전 점검(pre-tool-call)과 같은 검사를 로컬 PreToolUse 훅으로 먼저 시험해 보고 어떤 패턴이 오탐인지 목록을 만든다 → 정식 훅을 켜기 전에 규칙을 다듬는다
  - 지출·접근 한도를 통제하는 재무·보안 담당 → 셀프서비스 IP 허용 목록에 사무실·CI 고정 IP를 넣고 허용 밖 주소에서 키로 호출해 거절되는지 시험한다 → 유출된 API 키가 외부 주소에서 쓰이는 길을 줄인다

## 2. Python SDK 2.6.0·TypeScript SDK 1.6.0 — 멤버 로그아웃 API 지원, 한도(ramp limit)·외부 키 검증 실패 오류 코드, Bedrock·Vertex 클라이언트에서 오류 코드·상태 예외 클래스, OpenTelemetry 스팬에 샘플링 파라미터 기록 중단
- 날짜: 2026-11-05
- 출처: https://github.com/anthropics/anthropic-sdk-python/releases/tag/v2.6.0 (TS: https://github.com/anthropics/anthropic-sdk-typescript/releases/tag/sdk-v1.6.0)
- 요약: 두 SDK 모두 멤버 로그아웃 엔드포인트와 새 오류 코드 두 가지(ramp limit, External Key 검증 실패)를 담았다. Python은 Bedrock·Vertex 클라이언트도 11-04(2.5.0)에서 도입한 상태·코드별 예외 클래스를 던지게 고쳤고, `copy`·`with_options`로 만든 복사본이 사용자 지정 `http_client`와 `aws_profile`을 유지한다. OpenTelemetry 스팬에는 이제 샘플링 파라미터를 기록하지 않는다. 후속: 11-05 news 1번(2.5.0·1.5.0)의 다음 릴리스.
- 현실 적용:
  - Bedrock 위에서 Claude를 쓰는 백엔드 개발자 → 재시도 래퍼가 Bedrock 클라이언트에서도 `OverloadedError`로 잡히는지 가짜 529 응답 테스트를 하나 추가한다 → 클라우드 공급자를 바꿔도 재시도 규칙이 한 벌로 간다
  - OpenTelemetry로 Claude 호출을 수집하는 SRE → 대시보드가 스팬의 `temperature` 계열 속성을 쓰고 있는지 쿼리를 검색해 보고 쓰고 있으면 지운다 → 업그레이드 뒤 빈 패널이 장애로 보이지 않는다
  - `with_options`로 클라이언트를 복사해 쓰는 개발자 → 프록시용 `http_client`를 넣은 복사본이 2.5.0에서는 풀리고 2.6.0에서는 유지되는지 한 번 재현한다 → 프록시를 건너뛴 호출이 사내망 밖으로 나가는 사고를 막는다
  - 외부 키(자체 암호화 키)를 쓰는 기업의 플랫폼 팀 → 새 `External Key` 검증 실패 오류 코드를 알림 규칙 한 줄로 추가한다 → 키 설정 오류를 일반 400과 구분해 바로 알린다
  - 이 저장소의 `login-watch`(11-04)·`spend-gate`(10-13) → 한도·인증 오류를 `error_code`로 분류하는 후속 모드를 후보로 올린다 → 만료·한도·키 오류를 한 표에서 가른다

- 출처: https://github.com/anthropics/claude-plugins-official/commit/ff920a4094a341f282d5dee00daef2c3b8339c72

- 현실 적용:
  - iOS 앱을 혼자 만드는 개발자 → `claude plugin install xcode@claude-plugins-official`로 설치하고 빌드 실패 로그를 읽어 고치게 하는 첫 시나리오를 돌려 본다 → 빌드 오류를 터미널과 Xcode를 오가며 복사하는 시간이 줄어든다

  - 사내 플러그인을 검토하는 보안 담당 → 설치 전에 `marketplace.json` 항목과 플러그인 소스를 읽고 명령·훅·MCP 서버 정의를 표로 정리한다 → 서드파티 도구가 내 권한으로 도는 범위를 설치 전에 안다

## 4. GeekNews 11-06 "Claude Code가 사용자 이메일 주소를 웹사이트에 전송함" — 로그인한 계정의 이메일이 웹 요청의 User-Agent에 실린다는 보고(GitHub 이슈 78431·101659 인용)와 모델 컨텍스트에 들어간다는 보고가 섞여 있다 (본문 읽기 불가, 독립 검증 못 함)
- 날짜: 2026-11-06
- 출처: https://news.hada.io/topic?id=36676 (본문 403. 웹 검색 결과의 2차 글: https://explainx.ai/blog/claude-code-leaks-your-email-user-agent-header-how-to-stop-it-2026)
- 요약: GeekNews 본문은 403이라 읽지 못했다. 웹 검색에 잡힌 커뮤니티 글들은 Claude Code가 `curl` 같은 웹 요청에 계정 이메일을 User-Agent로 실어 보낸 사례(2.1.285, 연구용 서브에이전트가 Liquipedia에 보냈다가 403)와 계정 이메일이 세션 컨텍스트에 들어간다는 이슈를 전한다. 전부 2차 글·커뮤니티 보고이고 Anthropic의 공식 입장은 찾지 못해 사실로 단정하지 않는다.
- 현실 적용:
  - Claude Code로 웹 조사를 시키는 개발자 → 프록시(mitmproxy)나 `curl -v` 로그로 나가는 헤더에 내 이메일이 있는지 직접 확인한다 → 소문이 아니라 내 설치 버전에서의 사실을 안다
  - 팀 보안 담당 → 사내 프록시 로그에서 `User-Agent`에 이메일 모양 문자열이 있는 요청을 검색하는 쿼리를 한 줄 만든다 → 직원 이메일이 외부 사이트 로그에 남는 일을 탐지한다
  - 계정이 개인 이메일인 프리랜서 → 고객사 사이트를 조사시키기 전 PreToolUse 훅으로 WebFetch·curl 명령에 계정 이메일이 들어가는지 검사한다 → 고객사에 개인 주소가 노출되는 일을 막는다
  - 이 저장소의 `onfailure-secret-guard`(10-10)·`secret-envoy`(10-11) → 비밀값 패턴 목록에 "계정 이메일 일치" 검사를 후보로 올린다 → 개인정보도 키처럼 나가기 전에 걸린다
  - 오픈소스 이슈를 추적하는 메인테이너 → 이슈 78431의 재현 절차를 최신 릴리스에서 돌려 결과를 댓글로 남긴다 → 고쳐졌는지가 이슈에 기록된다
