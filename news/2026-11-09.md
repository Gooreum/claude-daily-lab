## 1. dev.to 11-09 "A SessionStart Hook That Hands Claude Code the Failing Tests Before Its First Turn" — 세션을 열 때 훅이 빠른 테스트를 돌려 실패한 것만 첫 프롬프트 앞에 넣어 준다
- 날짜: 2026-11-09
- 출처: https://dev.to/gabrielanhaia/a-sessionstart-hook-that-hands-claude-code-the-failing-tests-before-its-first-turn-3gl3
- 요약: 새 세션의 Claude는 CI가 왜 빨간지 모르니 첫 턴을 테스트 실행과 출력 읽기에 쓴다. 글은 SessionStart 훅이 찍은 일반 텍스트가 첫 프롬프트 앞 컨텍스트로 들어간다는 점을 이용해, 빠른 테스트 부분집합만 돌려 실패한 줄만 골라 넘기자고 한다. 출력은 1만 자를 넘으면 파일로 빠지고 미리보기만 남으니 15줄·줄당 200자로 자르고, 제한 시간(45초) 안에 못 끝나면 "상태 모름"이라고 사실만 적고, 문구는 "이 테스트가 실패한다"처럼 사실로 쓰고 "고쳐라" 같은 명령은 쓰지 않는다. resume 때 훅이 다시 돌아 낡은 결과가 갱신된다는 점도 짚는다.
- 현실 적용:
  - 주말에 CI가 빨개진 채 월요일 아침 세션을 여는 웹 서비스 팀 → `.claude/settings.json`의 SessionStart(`startup`·`resume`)에 `pytest -m "not slow"` 실패 목록을 넘기는 훅을 건다 → 첫 턴을 "무엇이 깨졌나" 탐색에 쓰지 않고 바로 고치기에 쓴다
  - 이 저장소의 `/daily-lab` 루틴 → 시작할 때 최근 `days/*/test.sh` 몇 개를 돌려 실패한 폴더 이름만 넘긴다 → 어제 만든 도구가 이미 깨졌는데 오늘 새로 쌓는 일을 막는다
  - `package.json`에 `npm test`가 느린 프런트엔드 개인 프로젝트 → 훅 명령을 `npm test -- --bail`로 바꾸고 제한 시간 30초를 둔다 → 세션 시작이 한 번에 몇 분씩 지연되는 사고 없이 실패 정보만 얻는다
  - 컨설팅 때 남의 저장소를 처음 여는 개발자 → 시작 훅이 `git status --short`와 마지막 커밋 제목 3개만 사실로 찍게 한다 → 낯선 저장소에서 "지금 상태가 어떤가"를 묻는 첫 두 턴을 아낀다
  - 훅 관련 사고 사례를 모아 온 보안 담당자 → 시작 훅이 출력하는 문구를 "사실만" 규칙으로 점검하는 검사(명령형 어미 검출)를 팀 훅 리뷰 체크리스트에 넣는다 → 명령조 문구가 프롬프트 주입 방어에 걸려 무시되는 일을 미리 막는다
  - `hook-manners`(11-02) 8규칙을 지키는 훅을 직접 만들어 보려는 사람 → "항상 exit 0·자체 데드라인·출력 상한"을 그대로 적용한 SessionStart 예제를 쓴다 → 규칙을 글로만 읽지 않고 한 훅에서 실제로 시험한다

- 날짜: 2026-11-09

- 현실 적용:
  - 월 구독 한도를 자주 넘기는 개인 개발자 → `~/.claude/projects/*/*.jsonl`에서 같은 가중치로 슬라이스별 비중을 집계해 본다 → 줄일 곳이 도구 출력인지 세션 길이인지 숫자로 고른다
  - 도구 목록에 MCP 서버를 열 개 이상 켜 둔 팀 → 서버별로 켰을 때·껐을 때 "기본" 슬라이스 크기를 비교한다 → 쓰지 않는 서버를 꺼서 매 호출마다 읽는 고정분을 줄인다
  - 이 저장소의 `/daily-lab` 루틴 → 실행 한 번의 호출 수와 토큰을 슬라이스별로 남기는 단계를 `run-receipt`(10-27)에 더한다 → 소스 점검 단계가 전체 비용에서 몇 %인지 보고 수집 방식을 조정한다
  - 하루에 세션 하나를 열어 종일 쓰는 리드 개발자 → 작업 하나가 끝나면 `/clear`하고 CLAUDE.md만으로 다시 시작해 일주일 비용을 비교한다 → 글의 결론("세션을 짧게")이 내 작업 패턴에서도 맞는지 확인한다
  - `cache-break`(10-24)·`cost-top`(10-30)을 이미 쓰는 사람 → 두 도구 출력에 이 글의 비용 가중치 표를 붙여 슬라이스 보고서로 합친다 → 캐시 이탈·조직 비용·내 세션 구성을 한 화면에서 본다

## 3. GeekNews 11-09 "Show GN: Aptly" — 작업에 맞는 서브에이전트 모델·추론 강도를 추천해 PreToolUse 훅으로 기본값을 바꿔 주는 로컬 MCP 서버
- 날짜: 2026-11-09
- 출처: https://news.hada.io/topic?id=36852
- 요약: Aptly는 설정한 모델 후보 중에서 서브에이전트에 맞는 모델과 추론 프로필을 골라 주는 로컬 MCP 서버로, Codex와 Claude Code를 모두 지원한다. Claude Code에서는 PreToolUse 훅이 지원 대상 서브에이전트 호출의 기본 모델을 자동 선택하되, 사용자가 명시한 모델과 effort는 건드리지 않는다. 분류에는 작업 요약만 OpenAI Decisions API로 보낸다고 하며, 목적은 불필요한 토큰과 비용을 줄이는 것이다(GeekNews 소개 기준, 직접 검증하지 않음).
- 현실 적용:
  - 서브에이전트를 열 개 넘게 정의해 둔 개인 개발자 → 각 정의의 `model`·`effort` 줄을 모아 "탐색·요약은 Haiku, 설계는 Opus" 규칙표와 어긋난 곳을 나열한다 → 모든 에이전트가 기본 모델로 도는 낭비를 찾는다
  - 서브에이전트 호출 로그를 갖고 있는 플랫폼 팀 → PreToolUse로 Agent 도구 입력의 `model` 유무만 세어 "모델을 명시하지 않은 호출" 비율을 낸다 → 추천 도구를 붙일 가치가 있는지 도입 전에 숫자로 정한다
  - 작업 요약을 외부 API로 보내는 도구를 검토하는 보안 담당자 → 훅이 외부로 내보내는 필드가 작업 요약뿐인지 네트워크 호출 한 번을 기록해 대조한다 → 사내 코드·경로가 요약에 섞여 나가는지 도입 전에 확인한다
  - 이 저장소의 `agent-scope-lint`(10-12)·`effort-race`(10-10)를 쓴 사람 → 에이전트 정의 점검에 "작업 성격 대비 모델 등급" 휴리스틱 검사를 더한다 → 도구 권한뿐 아니라 비용 설정의 실수도 정의 파일에서 잡는다
  - 월말 비용이 튄 팀 리드 → `cost-top`(10-30)으로 모델별 비용을 보고 상위 모델 비중이 큰 에이전트에 한해서만 추천을 적용해 본다 → 전체를 바꾸는 위험 없이 가장 큰 낭비부터 줄인다
