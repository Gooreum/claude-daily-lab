## 1. Anthropic 엔지니어링 11-06 "The components of agent memory" — 에이전트 기억은 "미래에 필요할 것에 대한 예측"이고, 모델이 스스로 중요도를 판단하게 두는 편이 규칙을 못 박는 것보다 낫고, 드리밍(세션 사이에 노트를 원본 기록과 대조해 고치는 작업)이 틀린 기억을 바로잡는다
- 날짜: 2026-11-06
- 출처: https://www.anthropic.com/research/components-of-agent-memory (GeekNews 소개: https://news.hada.io/topic?id=36775, 11-08)
- 요약: 글은 에이전트의 기억을 세션 사이에 남아 다음에 읽을 수 있는 노트 폴더로 정의하고, 강한 모델일수록 무엇이 중요한지 스스로 판단해 적는다고 보인다. 포켓몬 실험에서 옛 모델은 전투·아이템마다 파일을 만들어 413개를 쌓았지만, 새 모델은 파일 아홉 개와 현재 목표를 적은 `global.md` 하나로 더 멀리 갔다. "실패만 기록하라" 같은 고정 규칙은 강한 모델의 기억 이득을 오히려 깎았고, 드리밍은 노트를 원본 기록과 맞춰 틀린 위치 정보를 고쳐 같은 함정에 세 번 빠지던 에이전트를 통과시켰다. 사내 문서 35만 개 평가에서는 위키형 노트를 더하자 채점 기준 충족률이 올랐다(GeekNews 요약 기준 53%에서 최대 61%).
- 현실 적용:
  - Claude Code 자동 메모리 폴더(`~/.claude/projects/*/memory/`)를 몇 달 쓴 개인 개발자 → 노트 속 파일 경로·함수명·플래그가 지금 저장소에 실제로 있는지 대조하는 스크립트를 한 번 돌린다 → 오래돼 틀린 노트를 에이전트가 사실로 믿고 따르는 일을 막는다
  - 이 저장소의 `/daily-lab` 루틴 → 매일 쌓이는 `news/*.md`·`days/*/README.md`에 적힌 경로가 실제 폴더와 맞는지 주 1회 점검한다 → "다른 날짜 폴더를 참조했다가 이름이 바뀐" 죽은 링크를 푸시 전에 잡는다
  - 팀 리드가 관리하는 공용 CLAUDE.md → "무엇을 기억하라"는 규칙 줄 대신 "메모리 폴더가 있다"는 한 줄만 두고 전후 성공률을 비교한다 → 글의 결과대로 규칙을 줄이는 쪽이 성능을 올리는지 우리 작업에서 확인한다
  - Managed Agents로 야간 배치를 돌리는 플랫폼 팀 → 세션 끝날 때 메모리 폴더의 파일 수·총 크기·날짜 접두 파일 비율을 기록하는 단계를 넣는다 → 파일이 사건마다 하나씩 불어나는 징후(글의 413개 사례)를 한 달 치 추세로 보고 정리 시점을 정한다
  - 사내 문서 검색 봇을 만드는 개발자 → 문서별 위키 페이지를 노트로 쌓게 하고 질문 25개 정도의 소규모 평가로 전후 점수를 잰다 → 위키를 붙일지 말지를 감이 아니라 내 문서 기준 숫자로 정한다
  - 이 저장소의 `dream-lint`(11-05) → 구조 검사에 "노트가 가리키는 외부 사실이 아직 참인가" 검사를 짝으로 둔다 → 형식은 맞는데 내용은 낡은 노트도 걸러낸다

## 오늘의 선정
- 1번의 첫째·둘째 아이디어를 합쳐 메모리 노트의 낡은 주장(없어진 경로·식별자)과 "사건마다 파일" 비대화를 점검하는 `memory-drift`를 만든다. 노트 폴더와 대조할 저장소 폴더를 넣으면 죽은 참조 목록을 내준다. 모델·키 없이 로컬 파일만으로 검증한다.
- 이유: 글의 핵심이 "기억은 틀리거나 낡을 수 있고 원본으로 대조해야 한다"인데, 대조 중 기계가 할 수 있는 부분(경로·이름 존재 여부)을 도구로 만들 수 있다. `dream-lint`는 노트 폴더 안쪽 구조만 보므로 겹치지 않는다.
