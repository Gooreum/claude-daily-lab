## 1. Claude Code(Opus 5.5)에 "기존 게임 재구현" 제한 — 이름을 바꾸거나 독창적이라고 말해도 특정 기존 게임을 다시 만들지 않는다, 서버 플래그로 전달되고 사용자가 끌 수 없다 (GeekNews·Mashable·Tom's Hardware 전달)
- 날짜: 2026-11-01
- 출처: https://news.hada.io/topic?id=36384 (관련: https://news.hada.io/topic?id=36377 → Mashable https://mashable.com/tech/anthropic-takes-steps-to-block-video-game-cloning-and-reverse-engineering)
- 요약: GeekNews가 전한 X 게시물에 따르면 10-27에 Claude Code의 Opus 5.5 프롬프트에 기존 게임의 재구현을 거절하라는 두 문장이 서버 플래그(`tengu_heron_brook`)로 추가됐고, 사용자가 끄는 설정은 없다. Anthropic의 Addy Osmani가 문장 추가를 확인했고 이유는 지식재산권 침해가 이용 정책에 어긋나기 때문이라고 한다. 독창적인 게임·장르 게임·자기 에셋을 쓴 게임은 계속 가능하다고 밝혔지만, 일부 사용자는 진행 중인 게임 프로젝트와 일반 역공학까지 거절당했다고 주장하며 이 거절이 모두 같은 규칙 때문인지는 확인되지 않았다.
- 현실 적용:

## 2. Claude Code 훅 8가지 규칙 — 항상 `exit 0`, 스크립트 안에 자체 데드라인, stdout은 의도할 때만, `Stop` 훅은 `stop_hook_active`가 참이면 다시 막지 않는다 (dev.to 11-01)
- 날짜: 2026-11-01
- 출처: https://dev.to/fxdgif/8-rules-for-claude-code-hooks-that-never-get-in-claudes-way-5ap1
- 요약: 데스크톱 앱이 모든 훅 이벤트마다 작은 Node 스크립트를 실행하는 글쓴이가 직접 겪은 실수에서 규칙 여덟 개를 뽑았다. 파싱 실패·서버 다운이어도 종료 코드는 0(exit 2는 동작을 막고 stderr를 Claude에게 넘기며, 다른 비-0은 훅 오류로 보인다), 설정에 짧은 `timeout`을 두고 스크립트 안에도 별도 데드라인을 둘 것, `SessionStart` 등에서 stdout은 곧 컨텍스트라 불필요한 출력 금지, `PermissionRequest`만 사람의 결정을 기다려도 된다는 예외가 핵심이다. `Stop` 훅이 `{"decision":"block"}`을 낼 때 입력의 `stop_hook_active`가 참이면 다시 막지 말라는 것도 포함되며, 그러지 않으면 Claude가 끝낼 때마다 되돌려 보내지는 루프가 된다.
- 현실 적용:
  - `Stop` 훅으로 "변경한 파일이 있으면 학습 메모를 남겨라"를 시키는 개인 개발자 → 훅 스크립트에 `stop_hook_active`가 참이면 아무것도 내지 않고 `exit 0`하는 첫 줄을 넣고, 같은 입력을 거짓·참으로 두 번 넣어 두 번째에 `block`이 안 나오는지 직접 돌린다 → 세션이 끝나지 않고 계속 돌아가 한도를 태우는 사고를 막는다
  - 훅을 여러 사람에게 배포하는 플러그인 작성자 → 배포 전에 빈 입력·깨진 JSON·알 수 없는 이벤트 이름을 훅에 넣어 종료 코드와 stdout을 확인하는 점검 스크립트를 CI에 둔다 → 설치한 사람의 Claude가 훅 오류 메시지를 달고 일하는 일을 없앤다
  - 훅이 느려서 세션이 굼뜬 팀원 → 모든 이벤트에 `time`을 붙여 훅별 소요 시간을 재고 설정 `timeout`이 비어 있거나 60초 이상인 훅을 목록으로 뽑는다 → 훅 하나가 서버 응답을 기다리며 세션 전체를 붙잡는 곳을 찾는다
  - `SessionStart` 훅에서 상태를 컨텍스트로 넣는 사람 → 디버그용 `echo`·`console.log`가 남았는지 훅 출력의 바이트 수를 세어 의도한 문장 외에 아무것도 없는지 확인한다 → 매 세션 컨텍스트에 쓸데없는 토큰이 영구히 섞이는 것을 막는다
  - 이 저장소의 `hook-exit-audit`(10-19)·`disaster-guard`(10-10) → 둘은 "막아야 할 때 막는가"를 보지만 관찰용·`Stop` 훅의 "방해하지 않는가"는 보지 않으니 이를 재는 점검 도구를 오늘의 후보로 올린다 → 가드 훅 점검과 반대 방향의 구멍을 메운다

## 3. [후속: 10-31 3번] Cursor 마켓플레이스 변조 Claude Code 확장 — 10-29 02:27~13:35(태평양시) 버전 2.1.312·2.1.313이 정식 게시자 이름으로 올라갔고, 제거해도 상주 스크립트가 남을 수 있다 (dev.to 11-01, 2차 정리 글)
- 날짜: 2026-11-01
- 출처: https://dev.to/markorocko/5000-developers-auto-updated-claude-code-last-thursday-the-update-was-carrying-a-backdoor-and-4g23
- 요약: 10-31 3번이 GeekNews 전달만으로 다뤘던 사건의 상세다. 글에 따르면 Cursor 마켓플레이스가 게시자 `anthropic.claude-code`로 변조 버전(Windows·macOS)을 약 11시간 동안 제공했고 Cursor는 영향을 최대 5,000명으로 추정한다. 66줄 로더가 호스트 정보와 이름에 KEY·TOKEN·SECRET이 든 환경 변수를 모으고, 공격자 SSH 키를 `~/.ssh/authorized_keys`에 `svc-telemetry`라는 이름으로 추가하며, 맥은 LaunchAgent·윈도는 예약 작업으로 상주한다. Cursor 공지를 인용한 글은 확장 삭제만으로 충분하지 않을 수 있다고 하며, SSH 서비스 활성화에는 관리자 권한이 필요해 대부분 로그인까지는 이어지지 않았다고 쓴다. 이 내용은 한 블로거의 2차 정리이고 원 보고서(OpenSourceMalware)와 Cursor 공지는 직접 확인하지 못했다.
- 현실 적용:
  - Cursor에서 Claude Code 확장을 쓰던 개발자 → 10-29에 업데이트한 적이 있으면 `~/.ssh/authorized_keys`에서 `svc-telemetry` 주석이 붙은 줄과 맥의 `~/Library/LaunchAgents`·윈도 작업 스케줄러의 낯선 항목을 오늘 확인한다 → 확장을 지운 뒤에도 남는 상주물을 직접 찾는다
  - 회사 보안 담당자 → 직원 노트북 점검 스크립트에 확장 버전 `2.1.312`·`2.1.313` 설치 이력과 `134.209.82.225`로 가는 연결 로그 검색을 넣어 한 번 돌린다 → 영향 범위를 추정이 아니라 숫자로 보고한다
  - 에디터 확장의 자동 업데이트를 켜 둔 팀 → 확장 자동 업데이트를 끄고 주 1회 수동으로 버전과 게시자를 확인하는 체크리스트를 팀 위키에 올린다 → 게시자 이름이 정상이어도 변조 버전이 오는 경로를 한 번 늦춘다
  - 개인 API 키를 환경 변수로 두는 사람 → 환경 변수 이름에 KEY·TOKEN·SECRET이 들어간 것의 목록을 뽑아 쓰지 않는 키부터 폐기하고, 나머지는 셸 시작 파일 대신 필요할 때 읽는 방식(키체인 등)으로 옮긴다 → 같은 로더가 다시 와도 가져갈 값이 줄어든다
  - 이 저장소의 `ext-sweep`(10-31) → 점검 대상에 `authorized_keys`의 낯선 주석 줄과 LaunchAgent 상주물 확인을 추가하는 이슈를 남긴다 → 확장 폴더만 보던 점검이 사건 뒤처리까지 닿는다

## 오늘의 선정
- 2번 "훅 8가지 규칙"의 마지막 적용안을 고른다. 관찰용·`Stop` 훅이 방해하지 않는지(깨진 입력에도 exit 0, stdout 침묵, 데드라인, `stop_hook_active` 루프)를 키 없이 점검하는 `hook-manners`를 만든다.
- 이유: `hook-exit-audit`(10-19)은 차단 훅이 "막는가"를 재고, `stop_hook_active`는 저장소 어디에도 없다. 1번은 서버 플래그라 도구로 굳힐 수단이 없고, 3번은 10-31 `ext-sweep`과 겹친다.
