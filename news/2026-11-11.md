## 1. Anthropic 11-11 "Introducing Claude Whiteboards, Claude Sheets, and Claude Data" — 팀이 Claude와 같은 보드·스프레드시트에서 함께 고치고, 대시보드는 인증된 쿼리로 정식 출시
- 날짜: 2026-11-11
- 출처: https://claude.com/resources/articles/sheets-whiteboards-data (보조: GeekNews https://news.hada.io/topic?id=36958, 도움말 https://support.claude.com/en/articles/18324300-get-started-with-claude-sheets)
- 요약: Whiteboards는 팀원과 Claude가 한 보드에서 아이디어를 정리하고 계획을 담당자·날짜가 있는 타임라인으로 바꾸는 베타 기능이고, Sheets는 탭·수식·드롭다운이 있는 스프레드시트를 프롬프트로 만들고 함께 고치는 베타 기능이다. 10월 베타였던 Dashboards는 Claude Data라는 이름으로 정식 출시되어 데이터팀이 인증한 쿼리(certified)와 최신 숫자를 공유하는 라이브 공유, 캐시·갱신 주기, 변경 이력을 갖췄다. 모두 유료 플랜에서 쓰며, Enterprise는 Whiteboards·Sheets가 기본 꺼짐이고 Claude Data는 11-19부터 기본 켜짐이다.
- 현실 적용:
  - 스프린트 회고를 진행하는 개발 팀 → 회고 때 각자 메모를 Whiteboards에 올리고 Claude에게 주제별로 묶고 사람별 실행 항목 초안을 쓰게 한다 → 회의 뒤 별도 정리 시간 없이 담당자·날짜가 붙은 목록이 남는다
  - Enterprise 관리자 → 11-19 전에 Organization settings > Artifacts에서 Claude Data를 켤지 끌지 정하고, 데이터 연결 범위를 보안팀과 확인한다 → 기본값이 바뀌는 날 승인 없이 웨어하우스 연결이 열리는 일을 막는다
  - 데이터팀 → 월간 매출·이탈률 정의를 certified 쿼리 두 개로 먼저 만들어 공유한다 → 같은 지표가 대시보드마다 다른 숫자로 나오는 다툼을 줄인다
  - 소규모 마케팅 팀 → "캠페인 트래커: 채널·예산·담당자 열, 상태 드롭다운" 한 문장으로 Sheets를 만들게 하고 .xlsx로 내려받아 기존 파일과 열을 비교한다 → 새 시트를 열 이름 짜는 데 쓰던 시간이 줄고 Sheets의 한계(단순 기능)도 첫날 확인된다
  - 이 저장소의 매일 루틴 → 소식 항목의 "현실 적용" 줄을 Whiteboards에 붙여 담당 장면별로 묶는 시험을 한 번 해 본다 → 같은 아이디어 변주를 하나로 치는 규칙(RULES 1절)을 사람 눈으로 점검하는 방법이 된다
  - 프로젝트 관리 도구(Asana·monday.com·Smartsheet)를 쓰는 팀장 → Sheets에서 만든 시트를 그 도구로 내보내는 경로를 샘플 하나로 시험한다 → 옮기는 중 깨지는 서식·수식을 도입 전에 안다

## 2. SDK 릴리스 11-10 — Python v2.8.0·TypeScript sdk-v1.8.0이 Claude Tag 설정·분석 필드를 넣고, Bedrock·Vertex·Google Cloud는 `;`가 들어간 ID를 막거나 인코딩한다
- 날짜: 2026-11-10
- 출처: https://github.com/anthropics/anthropic-sdk-python/releases/tag/v2.8.0 (TypeScript: https://github.com/anthropics/anthropic-sdk-typescript/releases/tag/sdk-v1.8.0, Vertex: …/releases/tag/vertex-sdk-v1.1.3, Bedrock: …/releases/tag/bedrock-sdk-v1.1.2)
- 요약: 두 SDK에 Claude Tag(Slack 안의 Claude)의 사용량 지표가 분석 요약·사용자 리포트에 추가되고 Slack 채널 설정에 `reply_mode`가 생겼다. 클라우드 쪽 패키지는 요청 경로에 들어가는 값을 점검한다: Bedrock은 모델 ID에서 첫 `;` 앞이 비었거나 `.`·`..`이면 거절하고, Vertex는 모델·프로젝트·리전이 비어 있으면 거절하며 `;`를 `%3B`로 보낸다. Google Cloud는 프로젝트·위치·워크스페이스 ID를 퍼센트 인코딩하고 빈 값을 거절한다.
- 현실 적용:
  - 사용자 입력이나 설정 파일로 모델 ID를 받아 Bedrock·Vertex에 넘기는 서비스 → 모델 ID에 `;x`·`..;x`를 넣은 요청이 새 버전에서 오류로 끝나는지 단위 테스트를 한 개 추가한다 → 요청 경로를 바꿔치는 입력을 SDK 업그레이드 뒤에도 막고 있음을 증명한다
  - Python 서비스를 Bedrock으로 돌리는 팀 → `pip install -U anthropic==2.8.0` 후 스테이징에서 기존 모델 ID 3개가 그대로 호출되는지 확인한다 → 새 검증이 정상 ID까지 막는 회귀를 배포 전에 본다
  - Slack에 Claude Tag를 도입한 사내 도구 팀 → 분석 요약 API의 Claude Tag 지표를 주간 보고 스크립트에 넣는다 → 어느 채널에서 쓰이는지 근거 숫자로 남는다
  - Claude Tag를 여러 채널에 둔 관리자 → 채널별 `reply_mode` 설정 값을 조회해 한 표로 뽑는다 → 채널마다 답하는 방식이 제각각인 곳을 찾아 통일한다
  - 이 저장소 → `days/2026-10-22-apiver-lint`와 `model-stale`(10-25)에 "SDK 최소 버전" 점검을 더해 2.8.0 이상인지 검사한다 → 모델 ID 검증이 들어간 버전을 쓰는 프로젝트와 아닌 프로젝트를 구분한다

## 3. dev.to 11-10 "One Sentence Took My Coding Agent from 0/3 to 3/3 on Rejected Decisions" — 기각한 설계 결정을 ADR에 남겨도 상시 규칙에 "설계 전에 과거 결정을 확인하라"는 한 문장이 없으면 읽히지 않는다
- 날짜: 2026-11-10
- 출처: https://dev.to/kompiro/one-sentence-took-my-coding-agent-from-03-to-33-on-rejected-decisions-2179 (같은 저자 앞 글: https://dev.to/kompiro/record-what-you-rejected-and-make-your-agent-check-it-lessons-from-495-adrs-499n)
- 요약: 저자는 자기 저장소(ADR 263개)를 복제해 조건별로 문서를 지우며 에이전트(Claude Code, 모델은 Opus 4.8로 고정)에게 같은 요청을 백여 번 돌렸다. 문서를 지워도 결정이 코드 주석·git 기록·개념 문서에 남아 차이가 나지 않자, 이전에 기각한 제안("중괄호 문법을 YAML로 바꾸자")과 충돌하는 요청을 주고 에이전트가 충돌을 알아채는지를 쟀다. 결론은 기각한 결정은 한 줄 사유와 함께 항상 남기고, 상시 규칙에 확인하라는 문장을 한 줄 넣는 것이 가장 큰 효과였다는 것이다. 글의 수치는 저자 한 명의 저장소에서 잰 결과다.
- 현실 적용:
  - ADR을 `docs/adr/`에 쌓아 온 개발 팀 → `CLAUDE.md`에 "설계 전에 기각된 ADR을 확인하고 닿는 것을 말한다" 한 줄을 넣고 기각 ADR과 충돌하는 요청 3개로 전후를 비교한다 → 글처럼 과거 결정이 읽히는지 우리 저장소에서 직접 잰다
  - 기각한 제안을 슬랙·PR 댓글에만 남겨 온 팀 → 최근 석 달의 "안 하기로 한 것"을 ADR 한 파일에 한 줄 사유와 `Status: rejected`로 옮긴다 → 신입과 에이전트가 같은 제안을 다시 올리는 일을 줄인다
  - 이 저장소 → 프롬프트를 보내는 순간 기각 ADR과 겹치는 단어를 찾아 사실 문장으로 붙이는 `UserPromptSubmit` 훅을 만든다 → 규칙 한 줄에 기대지 않고 겹칠 때만 컨텍스트가 붙는다
  - 상시 규칙 파일이 길어진 개인 개발자 → 확인을 요구하는 문장 하나를 맨 위에 두고 나머지 서른 줄과 효과를 비교해 보는 A/B를 세 번 돈다 → 규칙이 많아 가장 중요한 것이 묻히는 문제를 숫자로 본다
  - 사유 없이 `not_adopted`만 남긴 ADR이 있는 팀 → 사유 한 줄이 비어 있는 기각 ADR을 목록으로 뽑아 채운다 → 글이 한 줄 사유로 충분하다고 한 만큼 가장 싼 보강이 된다
  - 아키텍처 리뷰어 → PR이 열릴 때 기각 ADR 제목과 PR 제목·설명의 겹침을 코멘트로 달게 한다 → 리뷰어가 기억으로 막던 재제안을 기록으로 막는다

## 오늘의 선정
- 3번의 "기각한 결정을 프롬프트 시점에 보여 주기"를 만든다. `UserPromptSubmit` 훅 `adr-guard`가 ADR 폴더(`docs/adr` 등)를 읽어 채택되지 않은 결정과 프롬프트의 단어가 2개 이상 겹치면 제목·사유·경로를 사실 문장으로 붙이고, 겹침이 없으면 아무것도 붙이지 않는다. ADR 점검(`--lint`)과 상시 규칙 한 줄(`--print-rule`)도 함께 낸다. 모델·키 없이 파일만으로 검증한다.
- 이유: 새 소식 중 오늘 당장 만들 수 있는 것은 3번이다(1번은 앱 기능, 2번은 SDK 내부). 훅 중 `UserPromptSubmit`(프롬프트 시점에 컨텍스트 붙이기)은 아직 이 저장소에 없고, `red-start`(11-09)와 짝을 이루는 두 번째 컨텍스트 주입 훅이 된다.
