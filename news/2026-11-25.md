## 1. Claude Code v2.1.332 — 새 훅 이벤트 `PreSkillShellCommand`(스킬·명령 안의 인라인 셸 명령을 불러오기 전에 거부), MCP 서버의 스킬(베타), 훅 출력 폭주로 멈추는 문제 수정

- 날짜: 2026-11-25 (UTC 01:32 릴리스, 한국 시각 11-25 10시 32분)
- 출처: https://github.com/anthropics/claude-code/releases/tag/v2.1.332
- 요약: 스킬 본문에 적은 `` !`명령` `` 한 줄이나 ```` ```! ```` 블록은 스킬을 불러올 때 Claude Code가 먼저 실행해 출력으로 바꾼다. 이번에 이 실행을 앞에서 막는 `PreSkillShellCommand` 훅이 생겼다. Agent SDK 0.3.332의 타입 정의에 따르면 입력에 `tool_name`(Bash·PowerShell)·`tool_input.command`(인자까지 채워진 명령)·`command_name`(그 명령을 품은 스킬)·`invoked_by`(user·claude·other)가 오고, 출력은 `permissionDecision`으로 deny·ask·defer 어느 것이든 명령이 실행되지 않으며 `updatedInput`은 적용되지 않는다. 같은 릴리스에는 MCP 서버가 싣는 스킬(`server:skill` 형태로 `/` 메뉴에 표시, 베타), 끝없이 출력하는 훅·MCP 서버가 터미널을 얼리던 문제의 수정, 훅이 거부 이유를 터미널 Read·Edit 프롬프트에 보여 주지 않던 문제의 수정이 들어 있다. 2.1.331 이하에서 설정 파일에 이 이벤트 이름을 적으면 시작할 때 대화창이 뜬다.
- 현실 적용:
  - 팀 공용 스킬을 `.claude/skills/`로 공유하는 개발팀의 리드 → `PreSkillShellCommand` 훅에서 `curl … | sh`·`rm -rf`·`git push`가 든 인라인 명령을 deny로 거절하는 스크립트를 설정에 건다 → 동료가 올린 스킬이 불러오는 순간 내 컴퓨터에서 위험한 명령을 돌리는 일을 막는다

  - 클라우드 세션에서 `ANTHROPIC_API_KEY`를 환경에 두는 팀 → 인라인 명령이 `env`·`printenv`·`.env`를 읽으면 거절하는 규칙을 훅에 넣는다 → 스킬 출력이 모델 컨텍스트와 대화 기록에 비밀값을 남기는 경로를 줄인다

## 2. MCP 서버가 스킬을 싣는다(Skills over MCP 공개 베타) — Tasks·Elicitation 정식, File Uploads는 곧 출시

- 날짜: 2026-11-24
- 출처: https://claude.com/blog/skills-over-mcp-tasks-and-more
- 요약: 서버가 도구와 함께 스킬을 게시하면 Claude는 필요할 때만 불러와 컨텍스트를 아끼고, 스킬이 서버와 함께 갱신되므로 사용자가 따로 설치할 것이 없다. Claude와 Claude Code에서 공개 베타이며 Pro·Max·Ultra는 기본으로 켜지고 Team은 관리자가 켜야 하고 Enterprise는 곧 열린다. Tasks(도구 호출이 끝나길 기다리지 않고 서버가 긴 작업을 돌림)와 Elicitation(서버가 호출 도중 폼이나 링크로 사용자에게 되물음)은 정식이 됐고, PDF·스프레드시트·이미지를 컨텍스트를 거치지 않고 서버에 보내는 File Uploads는 곧 풀린다. 서버가 이 기능들을 지원하면 Claude 외의 호환 클라이언트에서도 쓸 수 있다.
- 현실 적용:
  - 사내 도구를 MCP 서버로 내놓은 플랫폼 팀 → 도구 설명에 길게 적던 사용 요령(배포 순서·금지 사항)을 서버가 싣는 스킬 한 개로 옮긴다 → 도구 목록이 가벼워지고 요령이 서버 배포와 함께 갱신된다
  - 결제·삭제 같은 되돌릴 수 없는 도구를 가진 서버 개발자 → 삭제 도구에 Elicitation으로 "리포지터리 이름을 입력하세요"를 묻는 단계를 넣는다 → 모델이 잘못 판단해 데이터를 지우는 사고를 사람 확인으로 막는다
  - 수 분 걸리는 리서치·리포트 생성 도구를 가진 데이터 팀 → 그 도구를 Tasks로 바꿔 호출은 바로 돌려주고 결과는 끝나면 가져가게 한다 → 긴 도구 호출 하나에 세션이 묶여 다른 일을 못 하는 시간을 없앤다
  - 도구 정의가 많아 컨텍스트가 빠듯한 개인 개발자 → 쓰는 MCP 서버 다섯 개의 도구 목록 크기를 재서 스킬로 옮길 수 있는 설명을 가려낸다 → 매 세션 앞에 깔리는 토큰을 줄인다
  - 이 저장소의 `mcp-probe`·`secret-envoy` → 서버가 스킬 목록을 제공하는지 확인하는 점검 항목을 하나 더한다 → 새 베타 기능을 지원하는지 점검 도구가 알려 준다
  - 사내 관리자 → Team 플랜에서 Skills over MCP를 켜기 전에 어느 서버가 스킬을 싣는지 목록을 만들고 한 팀에만 먼저 켠다 → 베타 기능이 전사에 한꺼번에 퍼지는 것을 막는다

## 3. 아티팩트를 Mac·Windows 앱으로 설치(베타) — 권한 세 단계, 앱이 Claude와 커넥터를 쓰고 사용량은 요금제에서 차감

- 날짜: 2026-11-24
- 출처: https://claude.com/blog/install-as-app
- 요약: Claude에서 만든 아티팩트를 "Install as app"으로 설치하면 아이콘과 자기 창을 갖는 데스크톱 앱이 되고 공유도 된다. 권한은 기본(브라우저에서 할 수 있는 것만)·앱 권한(항상 위 창·전역 단축키·알림)·전체 컴퓨터 접근(프로그램 실행·파일 읽기·수정·삭제)의 세 단계이며, 권한은 현재 버전에만 적용돼 수정할 때마다 다시 묻는다. 전체 접근은 내가 만들었거나 같은 조직 사람이 만든 앱에만 줄 수 있고 Anthropic은 설치 전에 검수하지 않는다. 모든 요금제에서 베타이고 HIPAA 준비 조직·하이브리드 배포는 쓸 수 없으며 앱의 Claude 요청은 요금제 사용량에 잡힌다. 지원 센터 릴리스 노트에는 같은 날 커넥터와 파일 주고받기(베타)와 월간 회고 정식 전환도 올랐다.
- 현실 적용:

  - 팀 내 도구를 만드는 엔지니어 → 전체 접근 권한이 필요한 도구와 기본 권한이면 되는 도구를 나눠 목록을 만들고 전자만 팀원 검토를 거친다 → 검수 없이 설치되는 앱에 파일 삭제 권한이 가는 일을 막는다
  - 보안 담당 → 앱이 "다른 웹사이트에서 가져온 부분은 다시 묻지 않고 바뀔 수 있다"는 점을 감안해 외부 스크립트를 불러오는 아티팩트를 먼저 점검하는 체크리스트를 쓴다 → 승인한 뒤 원격 코드가 바뀌어도 모르는 상황을 줄인다
  - 이 저장소의 단일 HTML 도구(`idea-grader`·`feed-bookmark` 등) → 그중 하나를 아티팩트로 붙여 앱으로 설치해 본다 → 날마다 쌓이는 결과물이 터미널 밖에서도 쓰이는지 확인한다

## 4. 공식 SDK 2.14.0 — `proxy=`·`trust_env=False`가 환경변수에 지던 문제를 고침(경로가 바뀔 수 있음), 컴플라이언스 검토 API 추가

- 날짜: 2026-11-24
- 출처: https://github.com/anthropics/anthropic-sdk-python/releases/tag/v2.14.0
- 요약: Python v2.14.0과 TypeScript sdk-v1.14.0(둘 다 11-24 21:00 UTC)이 Google Cloud 프로젝트·사용자 프로필의 데이터 관리 설정과 컴플라이언스 검토 케이스·알림·항목 API를 추가했다. Python 쪽에는 동작이 바뀌는 수정이 있다: 기본 httpx 클라이언트가 `HTTP_PROXY`·`HTTPS_PROXY`·`ALL_PROXY`·`NO_PROXY`를 호출자가 넘긴 `proxy=`나 `trust_env=False`보다 우선해 읽던 것을 고쳐, 이제 `proxy=`가 모든 요청에 쓰이고 `trust_env=False`면 환경변수를 무시한다. 그래서 `NO_PROXY`에 적어 직접 접속하던 호스트가 `proxy=`를 쓰는 코드에서는 이제 프록시를 거친다.
- 현실 적용:
  - 코드에서 `proxy=`를 넘기면서 사내 `NO_PROXY`로 내부 호스트를 제외하던 팀 → 업그레이드 전에 `NO_PROXY` 대상 호스트 목록을 뽑아 `mounts={"all://그호스트": None}`을 넣을지 정한다 → 업그레이드 뒤 내부 호스트 요청이 프록시를 거쳐 갑자기 실패하는 일을 막는다
  - 프록시 뒤 CI에서 SDK를 쓰는 개발자 → 스테이징 환경에서 새 버전으로 요청 한 건이 어느 경로로 나가는지 프록시 로그에서 확인한다 → 환경변수 동작이 바뀐 사실을 로그로 확인한 뒤 올린다
  - 요청마다 프록시를 달리 쓰는 서비스 → `trust_env=False`와 명시적 `proxy=`를 조합한 클라이언트를 한 곳에서 만들도록 정리한다 → 환경변수 때문에 어느 프록시로 나가는지 헷갈리던 부분이 없어진다
  - 의존성을 고정해 두는 데이터 팀 → `anthropic>=2.13,<2.14` 같은 상한을 올리기 전에 프록시 사용 여부를 한 번 grep한다 → 자동 업그레이드가 프록시 경로를 바꾸는 것을 막는다

## 5. claude.dev — Addy Osmani의 `/ship` 실전 가이드: PR을 연 뒤의 후속(CI 실패·리뷰 지적·머지 충돌)을 에이전트에 맡기는 방법 (후속: 2026-11-24 항목 1 Claude Ship의 후속)

- 날짜: 2026-11-24
- 출처: https://claude.dev/blog/the-work-after-you-open-a-pr
- 요약: 글은 Claude Ship을 세 에이전트(Code Review·PR Steward·Claude Approvals)로 나누고, 관리자 권한이 없어도 `/code-review`(세션 안에서 버그 찾기), `/ship`(PR을 열고 리뷰한 뒤 돌아온 피드백까지 처리), `/steward`(이미 연 PR을 돌봄)를 지금 쓸 수 있다고 안내한다. `/code-review`는 `--fix`·`--comment`·`ultra` 변형이 있고, 로컬 `/code-review`는 `CLAUDE.md`를 읽지만 `REVIEW.md`는 읽지 않으며, `--fix`가 고친 것은 `/rewind`로 되돌려지지 않을 수 있으니 먼저 커밋하라고 경고한다. 팀이 배운 것은 저장소 파일로 남겨 검토받고, 팀 PR 전체에 자동으로 돌리는 것만 관리자가 켜면 된다.
- 현실 적용:
  - 혼자 일하는 개발자 → 푸시 전에 `/code-review`를 세 번 연속 돌려 같은 지적이 반복되는지 보고 반복되는 것만 `CLAUDE.md`에 규칙으로 옮긴다 → 같은 실수가 리뷰 단계에서 되풀이되는 일을 줄인다
  - 리뷰어 지적이 하루 여섯 건씩 쌓이는 팀원 → 열어 둔 PR 한 개에 `/steward`를 붙이고 돌려받은 변경을 일주일 동안 사람이 다시 열어 본 비율을 센다 → 에이전트에게 후속 작업을 맡겨도 되는 PR 종류를 경험으로 가려낸다
  - `REVIEW.md`가 있는 저장소의 리드 → 로컬 `/code-review`가 `REVIEW.md`를 읽지 않는다는 점을 감안해 핵심 규칙 세 줄을 `CLAUDE.md`에도 복사한다 → 로컬 리뷰와 서버 리뷰의 기준이 어긋나는 일을 막는다
  - `--fix`를 쓰는 사람 → 실행 전에 `git commit`을 습관으로 만들고, 실행 후 `git diff HEAD~1`로 변경을 본다 → `/rewind`에 안 잡히는 수정을 손으로 되돌리는 시간을 아낀다
  - 이 저장소의 일일 푸시 → `bash test.sh` 통과 뒤 푸시 직전에 `/code-review low`를 돌리는 단계를 `/daily-lab` 스킬 6절에 넣을지 비용을 재 본다 → 무인 실행에서 잘못된 README 링크·누락된 섹션을 사람이 보기 전에 잡는다
