## 1. Claude Code 2.1.325 후속 (11-13, 11-14 파일 1번의 후속) — 예약 작업과 `/loop`가 `allowed-tools`·`hooks`를 선언한 스킬은 먼저 묻고, 무인으로 돌리려면 `permissions.allow`에 `Skill(이름)`을 넣어야 한다
- 날짜: 2026-11-13
- 출처: https://github.com/anthropics/claude-code/releases/tag/v2.1.325
- 요약: 11-14 파일(1번)은 샌드박스 Bash 자동 승인 해제와 `hook_no_verdict`를 다뤘고, 같은 릴리스의 다른 변경은 담지 않았다. 이번 릴리스부터 예약 작업과 `/loop`는 `allowed-tools`나 `hooks`를 선언한 스킬을 실행하기 전에 사용자에게 묻고, 무인으로 돌리려면 `permissions.allow`에 `Skill(스킬이름)`을 추가하라고 한다. Desktop·IDE·SDK에서 "항상 허용"은 저장하면 같은 명령이 다시 허용될 때만 규칙 하나로 제안되어, 그 규칙에 기대던 예약 작업이 이제 사람을 기다릴 수 있다고 적혀 있다.
- 현실 적용:
  - 매일 아침 스킬을 예약 실행하는 개인 개발자 → `.claude/skills/*/SKILL.md`에서 `allowed-tools:`·`hooks:`가 있는 스킬을 `grep -l`로 찾아 이름 목록을 뽑고 `permissions.allow`에 `Skill(이름)`을 넣어 둔다 → 새벽 예약 작업이 승인 대기로 멈춘 채 아침을 맞는 일을 막는다
  - `/loop 5m /babysit-prs`처럼 스킬을 반복 호출하는 팀 → 루프에 쓰는 스킬이 `allowed-tools`를 선언했는지 확인하고, 선언했으면 `Skill(babysit-prs)` 허용 규칙을 팀 공용 `.claude/settings.json`에 커밋한다 → 첫 반복에서 질문이 떠 루프 전체가 멈추는 일이 없다
  - 이 저장소의 `/daily-lab`(Routine·GitHub Actions) → `daily-lab` 스킬이 `allowed-tools`를 선언하므로 Routine 환경과 워크플로에서 `Skill(daily-lab)`이 허용돼 있는지 점검 스크립트로 확인한다 → 업그레이드 뒤 매일 06:45 실행이 첫 줄에서 승인 대기에 걸리는 사고를 미리 알아챈다
  - 플러그인으로 스킬을 배포하는 팀 → 플러그인 안 스킬 중 `hooks`를 등록하는 것을 표로 뽑아 설치 문서에 "무인 사용 시 이 규칙을 추가"라고 적어 둔다 → 사용자가 예약 작업에서 처음 겪는 "왜 안 도나" 문의를 줄인다
  - SDK로 사내 봇을 돌리는 플랫폼 팀 → "항상 허용"으로 쌓인 규칙 중 이 릴리스 이후 제안 방식이 바뀐 것을 `settings.local.json`에서 훑어 명시적 규칙으로 옮긴다 → 봇이 사람 승인을 기다리며 조용히 멈추는 장면을 배포 전에 잡는다
  - 보안 담당 → 팀 스킬 저장소에서 `hooks`나 `allowed-tools`를 선언한 스킬이 몇 개인지 세어 "무인 허용 대상" 목록으로 관리한다 → 무인 허용 규칙을 한 곳에서 검토하고 늘어나는 속도를 본다

## 2. dev.to 11-14 "MCP structuredContent: Claude Code Drops Your Text Blocks" — MCP 도구 결과에 `structuredContent`가 있으면 Claude Code가 모델에게 JSON만 주고 텍스트 블록은 버린다는 점검 사례
- 날짜: 2026-11-14
- 출처: https://dev.to/jeremy_longshore/mcp-structuredcontent-claude-code-drops-your-text-blocks-7ja
- 요약: 글쓴이는 Discord 기록을 답하는 읽기 전용 MCP 서버를 만들며, 모델이 따라야 할 규칙·요약 줄·빈 결과 안내는 텍스트에 두고 메시지는 JSON(`structuredContent`)에 넣었다. 확인해 보니 Claude Code는 JSON을 도구 결과로 쓰고 텍스트를 모델에 넘기지 않아서, 평가는 통과했는데 지시가 도달하지 않았다. MCP 명세는 하위 호환을 위해 같은 JSON을 텍스트 블록에도 넣으라고 권하지만 서버가 복사본을 안 보냈던 것이 원인이며, 해법은 지시를 모델이 실제로 받는 채널에 두는 것이다. (글쓴이 한 사람의 관찰이며 독립 검증은 못 했다.)
- 현실 적용:
  - 사내 MCP 서버를 만드는 개발자 → 도구 결과에 `structuredContent`를 쓰는 서버가 있으면 `content`의 텍스트에도 같은 JSON 직렬화를 넣는지 `grep -rn structuredContent`로 확인한다 → 호스트가 어느 쪽을 읽든 같은 정보가 모델에 닿는다
  - MCP 서버 평가를 CI에서 돌리는 팀 → 평가 하니스가 모델이 실제로 본 입력(도구 결과)을 로그로 남기게 하고, 규칙 문장이 그 로그에 있는지 단언 한 줄을 추가한다 → "평가는 통과했는데 지시가 안 닿는" 거짓 통과를 잡는다
  - 이 저장소의 `mcp-probe`(11-01) → 도구 결과에 `structuredContent`가 있는데 같은 내용의 텍스트 블록이 없을 때 경고하는 규칙을 후보로 적어 둔다 → 서버 점검이 한 가지 더 느는 데 코드가 거의 들지 않는다
  - 도구 결과에 "빈 결과면 이렇게 답하라" 같은 규칙을 넣어 둔 팀 → 그 규칙을 텍스트가 아닌 도구 설명(description)이나 시스템 프롬프트로 옮기는 안을 실험해 본다 → 호스트별로 달라지는 채널에 지시를 걸지 않게 된다
  - 여러 AI 앱(Claude Code·다른 호스트)에 같은 MCP 서버를 붙이는 플랫폼 팀 → 두 호스트에서 같은 도구 호출 하나를 돌려 모델이 본 결과를 비교하는 표를 만든다 → 호스트별 차이를 출시 전에 문서화한다
  - 개인 개발자 → 자기 MCP 서버의 빈 결과·오류 응답이 어떤 채널로 가는지 한 번 호출해 확인한다 → 모델이 "결과 없음"을 "실패"로 오해하는 일을 줄인다

## 3. dev.to 11-14 "A Skill Can Run Commands Before Claude Reads It: What to Check First" — 스킬 폴더에서 명령이 실행되거나 권한이 열리는 네 곳과 그것을 찾는 작은 스크립트
- 날짜: 2026-11-14
- 출처: https://dev.to/promptmaster/a-skill-can-run-commands-before-claude-reads-it-what-to-check-first-20b5
- 요약: 남의 스킬을 `.claude/skills/`에 복사하기 전에 볼 곳을 정리한 글이다. 첫째는 느낌표와 백틱으로 쓰는 동적 컨텍스트 주입(스킬이 렌더링될 때 명령을 실행해 출력으로 바꾼다)으로, 글은 문서를 인용해 렌더링 중에는 권한 확인 창이 뜨지 않는다고 하되 deny·ask 규칙에 걸리면 스킬이 중단된다고 한다. 나머지는 `allowed-tools` 사전 승인, `hooks` 등록, `scripts/` 실행 등이며, 이 위치들을 찾는 작은 스크립트를 함께 소개한다.
- 현실 적용:
  - 외부 스킬을 가져다 쓰는 개발자 → 설치 전에 SKILL.md에서 `!` 백틱 줄과 코드 펜스 `!`를 `grep -nE '^!`|^```!'`로 찾아 어떤 명령이 렌더링 때 도는지 읽는다 → 읽기도 전에 실행되는 명령을 모르고 받아들이는 일을 막는다
  - 팀 스킬 저장소를 관리하는 리드 → PR 체크에 "새로 `hooks`·`allowed-tools`·주입 줄이 생긴 스킬"을 코멘트로 알리는 단계를 넣는다 → 권한이 넓어지는 변경을 리뷰어가 놓치지 않는다
  - 이 저장소의 `skill-lint`(10-23) → 주입 줄이 `deny`/`ask` 규칙에 걸릴 때 스킬이 중단된다는 점을 메시지에 보태는 방안을 적어 둔다 → "왜 스킬이 도중에 멈췄나"의 원인을 린터가 먼저 말해 준다
  - 사내 보안 담당 → 스킬이 `hooks`를 등록하는 경우 세션 끝까지 계속 돈다는 점을 설치 체크리스트에 넣는다 → 스킬 한 번 쓰고 지워도 훅이 남는지 점검하는 습관이 생긴다
  - 스킬을 직접 쓰는 개인 → 자기 스킬에서 주입 줄 대신 본문에 "이 명령을 실행하라"고 쓰는 쪽(Claude가 권한 흐름을 거침)과 비교해 어느 쪽이 맞는지 한 스킬로 시험한다 → 권한 확인 없이 도는 경로를 꼭 필요한 곳에만 둔다
  - 무인 작업에서 스킬을 쓰는 팀 → 주입 줄이 있는 스킬이 예약 실행에서 중단되지 않는지 `claude -p`로 한 번 돌려 본다 → 새벽 실행이 첫 줄에서 중단되는 일을 막는다

## 오늘의 선정
- 1번(2.1.325 후속)과 3번을 묶어 **`skill-gate`**를 만든다: 저장소의 스킬을 훑어 `allowed-tools`·`hooks`·`!` 주입 줄을 선언한 스킬을 찾고, 예약 작업·`/loop`에서 무인으로 돌리려면 필요한 `Skill(이름)` 허용 규칙이 `settings.json`에 있는지 대조해 빠진 규칙을 `permissions.allow` 조각으로 출력한다. 모델·키 없이 돈다.
- 이유: 이 저장소의 `/daily-lab` 자체가 `allowed-tools`를 선언한 스킬이라 Routine·Actions 실행이 승인 대기로 멈출 수 있는 직접적인 위험이다. `skill-lint`(10-23)는 규격·위험 패턴을 보지만 "무인 실행에 필요한 허용 규칙이 빠졌나"는 보지 않는다.
