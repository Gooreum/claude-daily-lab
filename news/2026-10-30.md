## 2. Claude Code 2.1.314 — `permissions.blockWritesOutsideWorkingDirectories`로 모든 권한 모드에서 작업 폴더 밖 쓰기를 막고, 큰 대화는 유휴 압축을 하며, 시작 실패 때 `claude -p`가 출력 없이 exit 0으로 끝나던 문제를 고쳤다
- 날짜: 2026-10-30
- 출처: https://code.claude.com/docs/en/changelog
- 요약: 새 설정 `permissions.blockWritesOutsideWorkingDirectories`를 켜면 Write·Edit·NotebookEdit가 작업 디렉터리 밖 경로를 모든 권한 모드에서 거부한다. VS Code와 Desktop은 20만 토큰 넘는 대화가 유휴 상태일 때 요약해 두었다가 캐시가 만료된 다음 메시지에 그 요약을 쓴다. `claude -p`는 시작 실패 시 오류를 찍고 exit 1로 끝나며, 샌드박스가 `claude -p --resume` 워크트리에 적용되지 않던 문제와 Monitor 도구가 시작한 셸 명령에 Bash 훅이 안 돌던 문제도 고쳤다. `sandbox.excludedCommands`는 호출 안의 모든 명령이 항목과 맞아야 제외된다고 설명이 바뀌었다.
- 현실 적용:
  - 밤에 `claude -p`를 크론으로 돌리는 개인 개발자 → `~/.claude/settings.json`에 `permissions.blockWritesOutsideWorkingDirectories: true`를 넣고 `claude -p "write ../x.txt"`가 거부되는지 확인한다 → `bypassPermissions`로 돌려도 작업 폴더 밖 파일을 못 건드리게 한다
  - `claude -p` 종료 코드로 성공을 판정하던 CI 스크립트 → 2.1.312 이하에서 시작 실패가 exit 0이던 곳을 찾아 `claude --version`을 파이프라인 첫 단계에 고정하고 2.1.314 이상에서 같은 입력의 종료 코드를 다시 본다 → 조용히 초록색이던 실패를 걸러낸다
  - 이 저장소의 `sandbox-lint`(10-29) → 새 키가 없거나 `false`인 설정을 알리는 규칙과 `excludedCommands`의 "모든 명령이 맞아야" 의미 변경을 반영한 설명을 한 줄씩 더한다 → 무인 작업 기준 점검이 최신 설정 키를 따라간다
  - Monitor 도구로 로그를 지켜보게 하는 팀 → Bash 대상 PreToolUse 훅이 Monitor가 만든 `tail *` 명령에도 도는지, `if: "Monitor(tail *)"` 조건으로 막아 보는 시험을 한다 → 훅이 우회되던 경로를 닫았는지 직접 확인한다
  - VS Code에서 하루 종일 한 대화를 이어 쓰는 개발자 → 점심 뒤 돌아와 첫 메시지를 보내고 `/context`로 토큰이 줄었는지 비교해 본다 → 캐시 만료 뒤 20만 토큰을 통째로 다시 쓰는 비용을 눈으로 확인한다

## 3. Messages API·Token Counting API 최대 요청 크기가 32MB에서 128MB로 — 1st-party Claude API 기준
- 날짜: 2026-10-28
- 출처: https://platform.claude.com/docs/en/release-notes/api
- 요약: Claude API의 Messages와 Token Counting 요청 본문 한도가 네 배로 늘었다. base64 이미지·PDF를 많이 실어 보내다 413을 만나던 호출이 같은 요청으로 통과할 수 있다. 문서의 요청 크기 한도 절에 정리되어 있고 이 변경은 직접 호출하는 Claude API에 해당한다.
- 현실 적용:
  - 스캔한 계약서 PDF를 40MB 단위로 쪼개 보내던 문서 처리 파이프라인 → 쪼개는 임계값을 설정 한 줄에서 120MB 아래로 올리고 쪼갠 조각 수가 줄었는지 로그로 본다 → 조각 사이에서 맥락이 끊기는 일을 줄인다
  - 이미지 100장을 한 번에 넣어 비교시키는 리뷰 도구 → 이미지를 base64로 인코딩한 총 크기(원본의 약 4/3배)를 계산해 128MB 안에 들어가는 최대 장수를 상수로 바꾼다 → 한도 계산이 옛 32MB 기준으로 남아 불필요하게 나누는 것을 막는다
  - Bedrock·Vertex로 같은 앱을 돌리는 팀 → 이 변경은 1st-party만이므로 클라우드별 최대 크기 표를 코드 주석이 아닌 설정으로 분리한다 → 플랫폼을 바꿔도 같은 요청이 413으로 터지지 않는다
  - `count_tokens`로 요청 전 크기를 가늠하는 개발자 → 큰 요청의 토큰 수를 먼저 세고 한도를 넘으면 오류를 내는 사전 점검을 128MB 기준으로 고친다 → 보내기 전에 실패를 안다
  - 이 저장소의 `apiver-lint`(10-22) 같은 점검기 → 소스에서 `32 * 1024 * 1024`·`33554432` 같은 요청 크기 상수를 찾아 알리는 규칙을 추가한다 → 오래된 가정이 코드에 남은 곳을 한 번에 찾는다

## 4. Sentry 이슈를 PR로 바꾸는 Managed Agents 퀵스타트 — 서명된 웹훅이 이슈마다 세션을 열고, PR은 에이전트가 아니라 호스트가 열며, 세션당 비용 상한과 보호된 기본 브랜치를 요구한다

- 요약: `managed-agents/sentry-autofix/` 퀵스타트는 Sentry 웹훅(서명 검증)이 오면 이슈 하나당 Managed Agents 세션을 시작한다. 에이전트는 Sentry MCP로 스택 트레이스와 원인 분석을 읽고, 실패하는 테스트와 수정 브랜치를 푸시한다. PR은 호스트가 맞춤 도구로 열고 끝나면 세션의 푸시 권한을 회수한다. 자격 증명은 샌드박스 밖 볼트에 두고, 세션당 상한 `AUTOFIX_MAX_USD`(기본 10)와 동시 수 `AUTOFIX_MAX_ACTIVE`(기본 3)를 환경 변수로 준다.
- 현실 적용:

  - 새벽 알람에 시달리는 온콜 → 웹훅을 받은 PR이 다음 날 아침 열려 있는지만 확인하는 체크리스트를 만든다 → 새벽에 스택 트레이스부터 읽는 시간을 줄인다
  - 에이전트에게 쓰기 권한을 주기 불안한 보안 담당 → 퀵스타트의 "PR은 호스트가 열고 푸시 권한을 회수" 구조를 내부 문서에 그대로 옮겨 우리 자동화의 체크 항목으로 삼는다 → 에이전트가 직접 병합·푸시하는 경로가 없음을 검토 항목으로 만든다
  - 세션 비용이 걱정인 개인 개발자 → 데모 앱의 `scripts/break.js`로 일부러 버그를 넣어 한 건의 실제 비용을 재 본다 → 상한값 10달러가 과한지 모자란지 숫자로 정한다

## 5. (10-29 3번의 후속) Claude Code deny 규칙은 `Read(.env)`를 막아도 `cat .env`·`grep -r`는 막지 않는다 — 7번 시험에서 Read 호출 2건만 거부되고 Bash 3건은 물음 없이 실행됐다
- 날짜: 2026-10-30
- 출처: https://dev.to/ji_ai/claude-code-deny-rules-block-readenv-but-not-cat-env-1of4
- 요약: 글쓴이는 `Read(./.env)` 거부 규칙이 내장 Read 도구에만 걸린다는 것을 시험으로 보였다. Bash 허용 목록에 `cat`·`grep` 계열이 있으면 `cat .env`와 `grep -r DATABASE_URL .`가 그대로 돌고, `Bash(cat .env)` 같은 거부 패턴은 접두사 매칭이라 `cat ./.env`로 비껴간다. 권고는 넓은 Bash 허용 제거, Bash 대상 PreToolUse 훅(`exit 2`), 샌드박스, 그리고 평문 비밀을 프로젝트와 셸 환경에서 없애는 것이다. 훅도 문자열 매칭일 뿐이라 완전한 경계는 아니라고 스스로 적는다.
- 현실 적용:
  - `.env`가 있는 저장소에서 `Bash(cat:*)`를 허용해 둔 개인 개발자 → 이 설정을 복사한 임시 폴더에서 `cat .env`, `cat ./.env`, `grep -r KEY .`를 각각 시켜 어느 것이 묻지 않고 실행되는지 표로 만든다 → 거부 규칙이 실제로 막는 범위를 추측이 아닌 결과로 안다
  - 비밀을 `.env`에 두는 스타트업 팀 → `.env`를 `direnv` 대신 OS 키체인이나 1Password CLI(`op run`)로 옮기고 프로젝트에는 `.env.example`만 둔다 → 에이전트가 어떤 명령으로도 읽을 평문이 없다
  - 사내 공통 `.claude/settings.json`을 관리하는 플랫폼 팀 → `Bash(cat:*)`·`Bash(grep:*)`·`Bash(head:*)`를 허용 목록에서 빼고 `Read`·`Grep` 도구로만 읽게 한다 → 파일 읽기 경로를 거부 규칙이 닿는 도구 쪽으로 모은다
  - Bash PreToolUse 훅을 쓰는 사람 → 훅 정규식이 `.env`, `./.env`, `$(pwd)/.env`, `.env*`, `env | grep KEY`를 모두 막는지 5개 입력으로 시험한다 → 훅이 문자열 하나만 막고 변형은 통과시키는 것을 먼저 안다
  - 이 저장소의 `sandbox-lint`(10-29) → `Read` 거부 규칙은 있는데 Bash 허용에 `cat`·`grep`이 넓게 있는 조합을 새 규칙으로 알린다 → 지금은 `denyRead`만 있고 Read 규칙이 없는 틈만 잡던 점검에 반대 방향 틈이 생긴다

## 6. Claude Code 훅이 에이전트를 조종하지 못하게 쓰는 법 — stdout의 JSON이 있으면 종료 코드보다 우선하고, `exit 2` 외의 비정상 종료는 매 호출마다 오류로 보이며, 안전한 훅은 stdout을 비우고 항상 exit 0으로 끝난다
- 날짜: 2026-10-29
- 출처: https://dev.to/bargan/how-to-write-a-claude-code-hook-that-cannot-steer-your-agent-3f83
- 요약: 훅의 출력을 Claude Code가 읽어 다음 동작이 바뀌면 그 훅은 에이전트를 조종하는 것이다. 유효한 JSON이 stdout에 있으면 필드가 허용·거부·재작성을 정하고, 실수로 찍은 `console.log`도 일부 이벤트에서 모델에게 읽힌다. `onFailure: "block"` 설정은 크래시나 타임아웃을 차단으로 바꾸고, HTTP 훅은 응답 본문으로 같은 일을 하므로 검증 없는 로컬 포트로 보내면 그 포트를 차지한 쪽에 조종권이 간다. 글쓴이는 stdout 무출력·항상 exit 0·짧은 시간 예산을 권하고, 테스트가 소스에서 stdout 쓰기와 비정상 종료를 검색하도록 한다.
- 현실 적용:
  - 로깅·알림용 훅(PostToolUse로 슬랙 전송 등)을 가진 개인 개발자 → 훅 스크립트에서 `console.log`/`print`/`echo`를 grep해 stdout으로 나가는 줄을 `>&2`나 로그 파일로 옮긴다 → 관측용 훅이 에이전트 판단을 바꾸는 일이 없다
  - `curl http://localhost:PORT`로 상태를 보내는 훅을 쓰는 팀 → 보내기 전에 서버가 무작위 값을 되돌려주는지 확인하는 호출을 넣고 틀리면 아무것도 하지 않고 exit 0 한다 → 같은 포트를 점유한 다른 프로세스에 응답 권한이 넘어가는 일을 막는다
  - 훅 타임아웃이 없는 팀 → 모든 훅에 `timeout`을 1~2초로 두고 느린 훅은 `async`가 아니라 백그라운드 큐로 보낸다 → 훅 하나가 모든 도구 호출을 느리게 하지 않는다
  - 차단용 훅과 관측용 훅을 한 파일에 섞어 둔 사람 → 차단은 `exit 2` 하나, 관측은 항상 exit 0으로 파일을 나눈다 → 관측 훅의 크래시가 차단으로 보이는 일이 없다
  - 이 저장소의 `hook-exit-audit`(10-19) → 훅을 실행했을 때 stdout에 유효한 JSON이 나오는지와 관측용 훅이 비정상 종료하는지를 새 검사로 더한다 → 종료 코드만 보던 점검에 "출력이 조종하는가"가 생긴다

## 7. 테스트 42개가 통과했는데 버그가 나갔다 — 검증 전에 번호를 예약해 거절된 요청이 번호를 소모한 사례, 회고를 CLAUDE.md 한 줄이 아니라 훅·회귀 테스트로 굳혔다
- 날짜: 2026-10-29
- 출처: https://dev.to/aidiveyt/claude-code-shipped-a-bug-with-42-tests-green-the-retro-said-the-session-was-smooth-c8c
- 요약: 글쓴이가 Claude Code에게 청구서 API의 연속 번호 대변 전표를 맡겼더니, 핸들러가 검증 전에 다음 번호를 잡아 거절된 요청이 번호를 소모했다. 테스트 42개와 타입 검사는 통과했는데 거절 뒤 번호를 검사하는 테스트가 없었다. 첫 회고는 "순조로웠다"였고, 실패를 구체적으로 적어 회고를 다시 하니 교훈이 나왔다. 교훈은 커밋 전 타입·테스트를 돌리는 pre-commit 훅, 거절 뒤 번호 회귀 테스트, 표준 문서 한 줄, 주석으로 굳혔고 새 세션이 5번 중 5번 통과했다.
- 현실 적용:
  - 순번·재고·쿠폰 같은 카운터를 다루는 서비스의 개발자 → "거절된 요청이 상태를 바꾸지 않는다"를 확인하는 테스트를 핸들러마다 한 건씩 추가한다 → 검증 전에 상태를 바꾸는 버그를 테스트 개수와 상관없이 잡는다
  - Claude Code 세션을 끝낸 뒤 회고하는 사람 → "이번에 잘못 나간 것은 무엇인가"를 먼저 한 줄 쓰고 그 줄을 근거로 회고를 시키는 프롬프트를 스킬로 둔다 → "순조로웠다"는 요약이 아니라 구체적 실패에서 교훈을 뽑는다
  - CLAUDE.md에 "검증 후에 번호를 부여할 것" 같은 문장이 쌓이는 팀 → 문장마다 이를 강제하는 훅·테스트가 있는지 표로 맞춰 보고, 없는 문장은 훅 후보로 표시한다 → 읽어도 지켜지지 않는 규칙을 실행되는 규칙으로 바꾼다
  - 커밋 전 `npm test`를 안 돌리는 개인 프로젝트 → PreToolUse 훅이 `git commit`을 감지해 타입 검사와 테스트를 먼저 돌리고 실패하면 `exit 2`로 막는다 → 모델이 깜빡해도 초록색이 아닌 커밋이 나가지 않는다
  - 이 저장소의 `idea-grader`(10-10) 같은 자기 점검 → "테스트 개수"가 아니라 "실패 경로를 건드리는 테스트가 있는가"를 폴더별로 세어 README 5절에 적는 규칙을 후속으로 쓴다 → 통과 수만 자랑하는 보고를 줄인다

## 8. Claude Code가 백그라운드 에이전트의 전체 대화 기록을 약 30초마다 모델에 보내 3~5단어 상태 요약을 만든다는 분석 — 전체 토큰의 15~20%라는 주장과 타이머만 막는 Bun 프리로드 우회책 (GeekNews 전달)
- 날짜: 2026-10-29
- 출처: https://news.hada.io/topic?id=36213
- 요약: GeekNews는 OpenTelemetry 데이터를 분석한 글을 전했다. 주장은 백그라운드 에이전트 패널의 상태 줄을 만들려고 전체 기록이 주기적으로 요약 호출에 쓰이고, 그 호출이 토큰의 15~20%를 차지한다는 것이다. 요약 결과는 작업 대화에는 들어가지 않는다. 완화책은 전역 `setTimeout`을 감싸 해당 타이머만 막는 Bun 프리로드 스크립트인데, 내부 코드 문자열에 의존해 업데이트마다 다시 확인해야 한다. 독립 측정 사례와 GitHub 이슈가 함께 언급되지만 Anthropic의 확인은 없다.
- 현실 적용:
  - 백그라운드 에이전트를 여러 개 띄워 두는 개인 개발자 → `CLAUDE_CODE_ENABLE_TELEMETRY=1`과 콘솔 OTel 내보내기로 한 시간 동안 `claude_code.api_request` 이벤트를 세어 입력 토큰이 큰 요청이 30초 간격으로 반복되는지 본다 → 주장이 내 환경에서도 나타나는지 확인한 뒤에 우회책을 고민한다
  - 한도가 빨리 닳는다고 느끼는 구독자 → 같은 작업을 백그라운드 에이전트 하나와 터미널 전경 세션 하나로 나눠 돌려 `/usage` 증가량을 비교한다 → 패널을 켜 둔 비용을 실측으로 가린다
  - 이 주장을 그대로 믿고 바이너리를 만지려는 팀 → 프리로드 스크립트를 쓰기 전에 업데이트로 깨지는 조건(내부 문자열 의존)을 이슈로 남기고 `claude --version`을 고정한다 → 비공식 우회책이 조용히 효력을 잃는 것을 막는다
  - 이 저장소의 `otel-tap`(10-15) → 같은 모델 호출이 일정 주기로 반복되는 요청 패턴을 찾는 `--periodic` 보기를 후속으로 둔다 → 요청이 몰린 시간이 아닌 "일정 주기 반복"이라는 모양으로 낭비를 찾는다
  - `cache-break`(10-24)를 쓰는 사람 → 서브에이전트·백그라운드 요청을 메인 요청과 분리해 보는 기존 표에서 입력이 크고 출력이 5단어 안팎인 요청을 따로 센다 → 출력 대비 입력이 비정상적으로 큰 호출을 숫자로 가려낸다
