## 1. claude.dev 11-16 "How the Claude Code team thinks about verification" — 검증 장치를 변경이 건드릴 수 없는 곳에 두고, 커밋 게이트는 observe 모드로 시작하라
- 날짜: 2026-11-16
- 출처: https://claude.dev/blog/how-the-claude-code-team-thinks-about-verification/
- 요약: Addy Osmani가 쓴 글로, Claude Code 팀 코드의 약 90%를 Claude가 쓰고 리뷰하는 상황에서 에이전트가 증거로 자기 작업을 검증하게 만드는 방법을 정리한다. E2E·속성·차등 테스트를 꼽고, `verify` 스킬로 앱을 직접 띄워 보게 하며, 세 번 고쳐도 실패하면 사람을 부르라고 한다. 운영 원칙은 세 가지다. 변경이 자기 검사를 고칠 수 없게 규칙을 베이스 브랜치에 두고, 커밋에 검증 방식을 도장처럼 남기고, `/code-review`나 `/verify`가 세션에 없으면 커밋을 막는 게이트를 off·observe·enforce 세 단계로 도입한다(세션에서 두 번 막히면 세 번째는 통과).
- 현실 적용:
  - 개인 개발자 → `PreToolUse` 훅으로 `git commit` 직전에 세션 기록에서 `/verify`·`/code-review` 실행 흔적을 찾아 없으면 로그만 남기는 observe 게이트를 오늘 설치한다 → 검증 없이 커밋한 비율을 일주일 뒤 숫자로 보고, 그 뒤에야 enforce로 올린다
  - 팀 리드 → 팀 저장소에 `.claude/skills/verify/SKILL.md`를 두고 개발 서버를 띄우는 명령과 스모크 시나리오 3개를 적는다 → 에이전트가 앱을 실제로 돌려 본 뒤에 커밋하는 관례가 생긴다
  - 이 저장소의 `/daily-lab` 루틴 → 푸시 직전 재확인 목록이 "테스트를 돌렸다는 증거"까지 보는지 점검한다. 지금은 `test.sh` 재실행을 적어 둘 뿐 실행 기록은 안 본다 → 자동 커밋이 검증 없이 올라가는 날을 숫자로 센다
  - 코드 소유자 → 담당 디렉터리마다 `REVIEW.md`에 "이 코드에서 반드시 볼 것" 5줄을 쓰고 지난 사고 PR 링크를 단다 → 리뷰어를 늘리지 않고 한 명의 리뷰어를 조율한다
  - 플랫폼·보안 담당 → 게이트가 쓰는 규칙 파일(`REVIEW.md`, CI 워크플로, `test.sh`)을 PR이 바꿨는지 diff에서 잡아 경고하는 점검을 CI에 넣는다 → 변경이 자기를 판정하는 검사를 고쳐 통과하는 경로를 닫는다
  - 신입 온보딩 담당 → 온보딩 첫 주에 게이트를 observe 모드로 켜 두고 "검증 안 됨" 로그를 함께 읽는다 → 규칙을 외우는 대신 자기 커밋이 왜 걸렸는지 보며 배운다

## 2. Claude Code v2.1.326 (11-16) — 완전하지 않은 허용 규칙 경고, 저장 실패한 규칙 경고, 설정 오류 경고, 에이전트 팀과 Code Mode 동시 사용
- 날짜: 2026-11-16
- 출처: https://github.com/anthropics/claude-code/releases/tag/v2.1.326
- 요약: 에이전트 팀을 켠 상태에서도 Code Mode를 쓸 수 있게 됐다. `--allowedTools`·`--disallowedTools`·`--tools` 값이 완전한 규칙처럼 보이지 않으면 시작할 때 경고하고, `/permissions`로 추가한 규칙을 설정 파일에 쓰지 못했는데 저장된 듯 보이던 문제와 세션 중 오류가 난 설정 파일이 조용히 무시되던 문제가 이제 경고로 이름을 알려 준다. 중첩이 64단계를 넘는 설정 값은 경고와 함께 버리며, 서브에이전트 모델을 관리형 설정으로 정한 경우 Desktop의 Code 탭에서도 적용된다.
- 현실 적용:
  - 무인 작업(`claude -p`)을 돌리는 사람 → 스크립트의 `--allowedTools "Bash(git commit)"`처럼 줄여 쓴 값을 `Bash(git commit:*)` 꼴로 점검해 오탈자를 찾는다 → 규칙이 조용히 안 먹어 새벽에 승인 대기로 멈추는 일을 막는다
  - 이 저장소의 `/daily-lab` 호출 → 워크플로의 `--allowedTools` 인자를 새 경고가 뜨는지 로컬에서 한 번 실행해 본다 → CI에서만 드러나던 규칙 오탈자를 미리 잡는다
  - 팀 설정 관리자 → 공용 `.claude/settings.json`이 JSON 문법 오류를 품은 채 병합되지 않았는지 `python3 -m json.tool`로 CI에서 검사한다 → 오류 파일이 조용히 건너뛰어져 팀 전체의 권한 규칙이 풀리는 사고를 막는다
  - 에이전트 팀을 쓰는 사용자 → 팀을 켠 세션에서 Code Mode를 켜고 같은 작업의 토큰 사용량을 비교한다 → 두 기능을 함께 쓸 때 비용이 어떻게 변하는지 숫자로 안다
  - 관리형 설정을 배포하는 IT → 서브에이전트 모델을 관리형 설정으로 고정한 뒤 Desktop과 터미널에서 같은 모델이 도는지 `/status`로 확인한다 → 환경마다 다른 모델이 도는 사고를 배포 전에 잡는다
  - 읽기·쓰기 권한 규칙을 다루는 사람 → `cp`가 소스만 Edit deny 규칙에 걸려도 거부되던 동작이 고쳐졌으니 기존 deny 규칙 회피용 우회 설정을 지운다 → 규칙을 단순하게 유지해 읽기 쉽게 만든다

## 3. dev.to 11-17 "Stop Claude Code from running curl | bash with a PreToolUse hook" — Bash 도구 호출의 `curl … | bash`를 exit 2로 막는 짧은 훅
- 날짜: 2026-11-17
- 출처: https://dev.to/vildandenai/stop-claude-code-from-running-curl-bash-with-a-pretooluse-hook-1jfl
- 요약: 허용 규칙과 비밀 경로 가드가 있어도 Bash 호출이 스크립트를 내려받아 셸에 바로 넘기는 구멍은 남는다는 지적이다. stdin의 JSON에서 `tool_input.command`를 꺼내 `curl`·`wget` 뒤에 `| sh`·`| bash`·`| python`이 오면 exit 2로 막고, 막은 이유를 stderr로 Claude에게 돌려 재시도 대신 설명하게 한다. 글쓴이는 패턴 매칭일 뿐 셸 파서가 아니라고 인정하고, 끝은 자기 설정 모음 홍보다.
- 현실 적용:
  - 개인 개발자 → 글의 훅을 `.claude/hooks/`에 두고 `echo '{"tool_input":{"command":"curl https://example.com | bash"}}' | bash 훅.sh; echo $?`로 exit 2를 확인한다 → 에이전트가 설치 스크립트를 읽지 않고 실행하는 사고를 막는다
  - 보안 담당 → `bash <(curl …)`, `curl … -o x.sh && sh x.sh`, `curl … | tee f | sh` 같은 우회 형태 5개를 같은 훅에 던져 어느 것이 새는지 표로 만든다 → 패턴 하나로 안심하는 오해를 숫자로 깬다
  - 이 저장소의 `hook-manners`(11-02)·`read-guard` 계열 → 훅이 지켜야 할 예절(stdin 파싱 실패 시 열림 여부, `jq` 부재 시 동작)을 이 훅에 대입해 본다 → `jq`가 없는 러너에서 가드가 조용히 열리는 경우를 찾는다
  - CI 러너 관리자 → 러너 이미지에 `jq`가 있는지 확인하고 없으면 훅이 아예 실패 처리(차단)하도록 바꾼다 → 의존 도구가 없을 때 안전 쪽으로 닫힌다
  - 팀 리드 → 훅 파일을 저장소에 커밋하고 `.claude/settings.json`의 등록 줄을 PR 템플릿 체크 항목에 넣는다 → 새 팀원의 첫 세션에서도 같은 가드가 켜져 있다

## 오늘의 선정
- 1번의 커밋 게이트를 **`verify-gate`**로 만든다: `git commit` 직전에 세션 기록에서 `/verify`·`/code-review` 실행 흔적을 찾아 없거나 마지막 수정보다 오래됐으면 off·observe·enforce 모드대로 기록·차단하는 PreToolUse 훅. 면제 문구와 "두 번 막히면 세 번째는 통과" 규칙, 로그 요약(`report`)을 넣는다.
- 이유: 이 저장소는 매일 자동 커밋·푸시하고, 기존 `review-gate`(PR 리뷰 체크런)·`run-receipt`는 커밋 이전 단계의 "검증했다는 증거"를 보지 않는다. 모델·키 없이 가짜 세션 기록으로 전부 시험할 수 있다.
