## 1. claude-cookbooks가 기본 모델을 Opus 5.5·Sonnet 5.5·Fable 5.1로 일괄 교체 — 모델 점검 명령·검증 스크립트에 "최신 / 구형이지만 서비스 중 / 퇴역" 3단계 표가 생겼다
- 날짜: 2026-10-24
- 출처: https://github.com/anthropics/claude-cookbooks/commit/bfe50e59dbb4f5546a0af9ca36ebb77e637c9ce1
- 요약: 쿡북 커밋 #924는 노트북·예제 116개 파일의 기본 모델을 `claude-opus-5-5`, `claude-sonnet-5-5`, `claude-fable-5-1`(Haiku는 `claude-haiku-4-5` 유지)로 바꾸고 CLAUDE.md의 모델 규칙을 다시 썼다. 날짜가 박힌 ID는 금지하고, Bedrock은 Messages API 엔드포인트용 접미사 없는 ID(`anthropic.claude-sonnet-5-5`)와 InvokeModel용 날짜 형식을 구분해 적는다. `validate_notebook.py`에는 최신·구형(Superseded)·퇴역(Retired) 세 표가 들어가 구형은 경고, 퇴역은 차단으로 나눠 보고한다. 같은 날 공식 퇴역 표에서 Sonnet 4.5는 11월 30일 퇴역 예정이고, Haiku 4.5의 가장 이른 퇴역일(10월 15일)은 이미 지났다.
- 현실 적용:
  - 프롬프트 노트북이나 예제 저장소를 운영하는 팀 → 쿡북 표를 따라 모델 ID를 "최신/구형/퇴역" 세 단계로 나눈 검사를 CI 한 줄로 두고, 구형은 경고·퇴역은 실패로 만든다 → 11월 30일에 Sonnet 4.5 예제가 한꺼번에 깨지는 날을 미리 막는다

  - `.env.example`에 `ANTHROPIC_MODEL=`을 적어 두는 오픈소스 메인테이너 → 예시 값을 쿡북처럼 날짜 없는 별칭으로 바꾸는 PR을 올린다 → 새로 클론한 사람이 퇴역한 모델로 첫 호출을 하는 일이 사라진다

## 2. 서브에이전트 worktree가 기능 브랜치를 못 본다 — 기본값 `worktree.baseRef: "fresh"`는 원격 기본 브랜치에서 갈라지니 `"head"`로 바꾸라는 dev.to 글
- 날짜: 2026-10-24
- 출처: https://dev.to/gabrielanhaia/your-claude-code-worktree-subagent-cant-see-your-feature-branch-set-baseref-to-head-4ljn
- 요약: `isolation: worktree`로 띄운 서브에이전트는 기본적으로 원격 기본 브랜치에서 worktree를 만들어, 내 로컬 기능 브랜치에만 있는 커밋을 보지 못한다. 증상은 방금 짠 함수가 없다고 서브에이전트가 말하는 것이고, `git merge-base --is-ancestor`가 1을 내면 확정이다. 해법은 설정의 `worktree.baseRef`를 `"head"`로 두는 것이며 개인용 `settings.local.json`, 팀용 `.claude/settings.json`, 사용자 설정 어디든 된다. 글은 이 설정이 어느 버전에서 생겼는지는 밝히지 않는다.
- 현실 적용:
  - 기능 브랜치에서 서브에이전트 리뷰어를 띄우는 개인 개발자 → `.claude/settings.local.json`에 `{"worktree":{"baseRef":"head"}}`를 넣고 미푸시 커밋을 리뷰시켜 본다 → "그 함수 없는데요" 식의 헛리뷰를 없앤다
  - 서브에이전트 병렬 작업을 CI 전에 돌리는 팀 → 작업 시작 훅에서 `git merge-base --is-ancestor HEAD <worktree 기준>`을 확인해 실패하면 중단하는 가드를 둔다 → 설정이 빠진 팀원 PC에서 조용히 낡은 코드로 일하는 것을 막는다
  - 모든 worktree에 설정이 적용되는 점이 걸리는 사람 → 무관한 작업은 `fresh`가 낫다는 글의 말대로, 저장소 설정이 아니라 `claude --worktree` 호출 전 임시 설정 파일로만 `head`를 쓴다 → 다른 작업에 로컬 변경이 새어 들어가지 않게 한다
  - 서브에이전트 비용을 줄이려는 사용자 → 되살린 서브에이전트가 낡은 베이스에서 헤매며 다시 읽는 파일 수를 `baseRef` 전후로 세어 본다 → 엉뚱한 코드를 읽느라 쓰는 토큰이 줄었는지 숫자로 본다
  - 이 저장소의 일일 루틴 → 제작 단계의 서브에이전트가 오늘 만든 미커밋 폴더를 못 볼 때를 가정해, 커밋 전에는 `isolation: worktree` 서브에이전트를 쓰지 않는다는 한 줄을 `daily-lab` 스킬 메모에 남기는 이슈를 쓴다 → 06:45 자동 실행에서 서브에이전트가 빈 저장소를 보고 "만들 게 없다"고 답하는 사고를 막는다

## 3. `claude -p` 무인 실행 가이드 — 조용한 권한 거부, 잊힌 `ANTHROPIC_API_KEY`가 구독 토큰을 이기는 문제, cron의 PATH, stdin 10MB 한도
- 날짜: 2026-10-24
- 출처: https://dev.to/aobaworks/claude-code-headless-mode-flags-auth-and-cost-2026-di2
- 요약: `claude -p`로 도는 무인 작업이 믿을 만하려면 브라우저 로그인이 아닌 자격 증명, 명시한 권한, 턴·예산 상한, 파싱 가능한 출력이 필요하다고 정리한 글이다. 수동 권한 모드에서 목록에 없는 도구는 조용히 거부돼 작업이 "성공"하고도 아무것도 안 할 수 있어 `permission_denials`를 봐야 하고, 남아 있는 `ANTHROPIC_API_KEY`가 구독 토큰을 이겨 의도치 않은 API 과금이 생긴다. `--max-turns`에 걸리면 비정상 종료하고, `--max-budget-usd`는 클라이언트 추정에 기반한 부드러운 상한이며, 파이프 입력이 10MB를 넘으면 종료한다. 가격 수치는 글쓴이가 적은 값이라 공식 가격표와 대조가 필요하다.
- 현실 적용:
  - 새벽 cron으로 `claude -p`를 돌리는 개인 개발자 → 실행 뒤 JSON 결과의 `permission_denials`가 비어 있지 않으면 종료 코드를 1로 바꾸는 래퍼 한 줄을 넣는다 → 아무것도 안 했는데 초록불인 "성공"을 잡는다
  - 구독 토큰(`CLAUDE_CODE_OAUTH_TOKEN`)으로 Actions를 돌리는 팀 → 워크플로 첫 단계에서 `ANTHROPIC_API_KEY`가 환경에 있으면 경고하고 지우는 단계를 둔다 → 구독으로 알고 돌렸는데 API 요금이 청구되는 사고를 막는다
  - cron의 `claude: command not found`를 겪은 사람 → crontab 맨 위에 `PATH=`를 쓰고 명령은 `which claude` 절대 경로로 박는다 → 환경 차이로 새벽 작업이 사라지는 일이 없어진다
  - 큰 로그를 `cat log | claude -p`로 요약시키는 운영자 → 10MB 넘는 입력은 파일로 저장해 경로만 넘기는 전처리 스크립트를 쓴다 → 큰 로그 날에만 터지는 비정상 종료를 없앤다
  - 이 저장소의 `loop-caps`·`spend-gate`·`ci-doctor` → "조용한 거부"와 "남은 API 키" 두 점검을 후속 이슈로 올려 각 도구가 이미 보는지 확인한다 → 무인 실행 점검 목록의 빈칸을 찾는다
