## 1. 서브에이전트를 메인 루프에 합칠 때 — 조직도대로 쪼갠 멀티 에이전트는 하나의 루프 + 스킬 + 도구 검색이 대개 더 빠르다 (한 고객은 약 2배). 도구 정의가 30~50개를 넘으면 선택이 나빠진다
- 날짜: 2026-10-22
- 출처: https://claude.com/blog/building-agents-when-to-fold-subagents-into-your-main-agent-loop
- 요약: 전문 서브에이전트를 여럿 둔 기업용 에이전트를, 필요할 때 불러오는 스킬과 검색으로 찾는 도구를 가진 단일 루프로 합치면 답이 낫고 비용·지연이 준다는 글이다. 한 고객은 다중 에이전트 구성을 단일 루프로 바꾸고 실행 시간이 약 절반이 됐다. 서브에이전트를 남길 기준은 컨텍스트 팽창으로 품질이 측정 가능하게 떨어질 때, 병렬 실행이 이득일 때, 도구 선택이 흔들리거나 시스템 프롬프트 지시가 충돌할 때다. 옮기는 절차는 작은 종단 평가(예: 정답 예시 10개)를 먼저 만들고, 가장 강하게 결합된 서브에이전트부터 하나씩 합쳐 점수를 비교하며, 합친 쪽이 나빠질 때만 남기는 것이다.
- 현실 적용:
  - 서브에이전트 정의를 `.claude/agents/`에 여덟 개쯤 쌓아 둔 개인 개발자 → 서로 같은 파일을 만지거나 항상 같이 호출되는 쌍을 찾아 그중 하나를 스킬로 옮긴다 → 넘겨받는 과정의 손실과 프롬프트 중복이 줄어 같은 일이 더 빨리 끝난다
  - 도구가 40개 넘는 MCP 서버를 여러 개 붙인 팀 → 서버별 도구 수를 세고 의도 단위(조회·변경·알림)로 묶어 불필요한 도구는 끈다 → 모델이 비슷한 도구 사이에서 헤매는 일이 줄어든다
  - 에이전트 품질을 "느낌"으로 판단하던 리드 → 실패했던 실제 요청 10개로 골든 예시를 만들고 같은 과제를 두 번씩 돌려 변경 전후를 비교한다 → 한 번 돌려 통과한 우연한 회귀를 잡는다
  - 부서별로 서브에이전트를 나눠 만든 회사 → 시스템 프롬프트와 종단 품질은 소수 중앙팀이 맡고, 부서는 자기 스킬·도구 설명과 평가만 올리게 한다 → 팀 경계가 곧 에이전트 경계가 돼 생기는 유지보수 중복을 끊는다
  - 이 저장소의 `agent-scope-lint`·`loop-caps` 옆 → 서브에이전트 정의 폴더를 훑어 "합칠 후보"(도구 목록 겹침, 프롬프트 길이)를 점수로 뽑는 점검을 다음 후보로 둔다 → 합치기 전에 어디부터 볼지 숫자로 고른다

## 2. 밤새 무인으로 돌린 Claude Code가 깨지는 여섯 가지 — 정시에 돌았는데 아무것도 안 했다(종료 코드 1이나 헤더만 있는 CSV), 사람을 기다렸다, 한도를 태웠다, 결과를 아침에 못 알아봤다
- 날짜: 2026-10-26
- 출처: https://dev.to/everydaylentils/what-breaks-when-claude-code-runs-overnight-with-nobody-watching-3ka8
- 요약: 야간 무인 실행의 실패를 여섯 갈래로 정리한 글이다. launchd 작업이 YAML 프런트매터의 `---`를 알 수 없는 옵션으로 읽어 이틀 밤 연속 1초 만에 종료 코드 1로 끝났고(프롬프트 앞에 `--`를 붙여 해결), 데이터가 없는 밤에 헤더만 쓴 CSV가 종료 코드 0으로 끝난 사례도 있다. 해결로 결과 파일이 있는지·오늘 것인지·내용이 있는지 확인하고, 필요한 도구만 미리 승인하며, 샌드박스와 에이전트별 worktree를 쓰고, 끝날 때 변경·가정·남은 요청을 적은 짧은 보고서를 쓰게 하라고 한다. 한 사용자는 `/usage`를 보고 한도 임계(5시간 창 80% 등)를 넘으면 밤을 멈추게 했다.
- 현실 적용:
  - launchd·cron으로 매일 `claude -p`를 돌리는 개인 개발자 → 프롬프트 파일 첫 글자가 `-`인지 검사하고 맞으면 `--`를 붙이게 하는 점검을 실행 전에 둔다 → 이틀 밤 연속 1초 만에 죽는데 모르는 일을 첫날 잡는다
  - 야간에 CSV·JSON 리포트를 만드는 데이터 담당 → 실행 뒤 "파일이 있나·오늘 수정됐나·헤더 아래 데이터 줄이 1줄 이상인가"를 확인해 아니면 실패로 처리한다 → "성공(종료 코드 0)"인데 빈 리포트를 아침 회의에 들고 가는 일을 막는다
  - 야간 이슈 처리 루프를 돌리는 팀 → 루프 앞에 보고서(`REPORT.md`)가 있고 `BLOCKED.md`가 없는지 확인하고, 막힘 파일이 있으면 사람 알림으로 보낸다 → 사람을 밤새 기다린 세션이 몇 개인지 아침에 한 줄로 안다
  - 아침마다 세션 기록을 일일이 열어 보던 운영자 → 보고서 항목(변경 파일·실행한 검증·가정·남은 요청)이 비어 있지 않은지만 기계로 먼저 걸러 문제 있는 밤만 연다 → 아침 점검이 30초로 줄어든다
  - 이 저장소의 매일 06:45 `daily-lab` 실행 → 실행 후 오늘 폴더·`SUMMARY.md`·`news/<오늘>.md`가 있고 비어 있지 않은지 확인하는 영수증 점검을 둔다 → 워크플로가 초록색인데 결과물이 없는 날을 알아챈다

## 3. 무인 에이전트용 CLAUDE.md 템플릿 — 짧게 쓰고, 자율 범위와 "끝났다"의 기준을 검사 가능하게 쓰고, 막히면 `BLOCKED.md`만 남기고 끝낸다. 지켜야 하는 것은 CLAUDE.md가 아니라 훅·deny 규칙에
- 날짜: 2026-10-26
- 출처: https://dev.to/aobaworks/claudemd-best-practices-a-template-for-unattended-agents-1d3j
- 요약: 사람이 지켜보지 않는 실행용 CLAUDE.md를 쓰는 규칙 모음이다. 모델이 코드에서 추론 못 하는 것만 쓰고, 자율 범위(스스로 결정할 것·멈추고 보고할 것·막혔을 때 할 것)와 "끝났다"의 기준(테스트 통과, 빌드 종료 코드 0, 변경 파일·실행 명령 보고서)을 적게 한다. 막히면 질문과 시도한 것을 `BLOCKED.md`에 쓰고 아무것도 커밋하지 않고 끝내며, 절대 하면 안 되는 일은 CLAUDE.md가 조언일 뿐이니 `PreToolUse` 훅이나 deny 규칙으로 막으라고 한다. 예시 기준은 변경 파일 약 10개 초과 시 멈춤, 불안정한 네트워크 단계는 재시도 1회다.
- 현실 적용:
  - 야간 `claude -p` 작업의 CLAUDE.md를 쓰는 개인 개발자 → "변경 파일 10개 초과면 멈추고 `BLOCKED.md`에 쓴다"와 "끝나면 `REPORT.md`에 변경 파일·실행 명령을 쓴다" 두 줄부터 넣는다 → 아침에 무엇이 바뀌었는지 보고서 하나로 파악한다
  - 팀 CI에 에이전트 PR 작성을 붙이려는 리드 → "완료 = 테스트 통과 + 빌드 종료 코드 0 + 보고서"를 CI 단계로 옮겨 보고서 없으면 실패시킨다 → CLAUDE.md의 권고가 실제 게이트가 된다
  - CLAUDE.md에 "푸시 금지"를 적어 둔 사람 → 같은 규칙을 `Bash(git push *)` deny 규칙이나 훅으로도 건다 → 조언이라 무시될 수 있는 규칙을 실제로 막힌 규칙으로 바꾼다
  - 규칙이 300줄 넘게 불어난 사람 → 줄마다 "빼면 모델이 실수하나?"를 묻고 아닌 줄을 지운 뒤, 실수가 난 날에만 한 줄 추가한다 → 지시가 묻히는 일이 줄고 매 턴 읽는 토큰이 준다
  - 이 저장소의 `daily-lab` 스킬 → 막혔을 때 "질문 대신 3절 실패 경로"라고 이미 쓰여 있는지 보고, `BLOCKED.md` 같은 막힘 기록 파일이 있는 경우 알림 메일이 그것을 집어 올리게 하는 후속 이슈를 쓴다 → 막힌 날의 원인이 메일 한 통에 들어온다

## 4. Claude Code 2.1.311 — 무인·서브에이전트 수정이 몰렸다: `SubagentStop` 훅이 분당 두 번 도는 문제, `-p` 기록 순서 뒤섞임, 시간 초과 셸 출력 보존, 재시도 감시 개선, 압축 직후 낡은 MEMORY.md
- 날짜: 2026-10-26
- 출처: https://github.com/anthropics/claude-code/releases/tag/v2.1.311
- 요약: 2.1.311은 새 기능이 적고 수정이 대부분이다. 서브에이전트 쪽으로는 `SubagentStop` 훅이 서브에이전트마다 분당 두 번씩 돌던 것을 끝날 때 한 번으로 고쳤고, 서브에이전트가 연결이 늦은 MCP 서버의 도구를 쓰지 못하던 것과 백그라운드 서브에이전트가 일하는 중 격리 worktree가 지워지던 것도 고쳤다. 무인 쪽으로는 `claude -p`·SDK 기록이 순서가 뒤섞이던 문제, API가 재시도하지 말라고 표시한 요청을 다시 시도해 `CLAUDE_CODE_RETRY_WATCHDOG` 모드에서 무한히 붙잡히던 문제, 시간 초과된 셸 명령이 이제 지금까지의 출력을 보여 주고 백그라운드에서 계속 도는 중임을 알리는 변경이 있다. CLAUDE.md에 아주 긴 목록 항목이 있으면 시작 때 멈추던 문제와 자동 압축 직후 낡은 MEMORY.md·CLAUDE.md를 보던 문제도 고쳤다.
- 현실 적용:
  - `SubagentStop` 훅으로 알림이나 로그를 남기던 개인 개발자 → 2.1.311로 올린 뒤 같은 작업의 훅 로그 줄 수를 전과 비교한다 → 분당 중복 실행으로 쌓이던 알림·로그가 사라졌는지 확인한다
  - `claude -p` 결과 기록(transcript)으로 감사나 재현을 하는 팀 → 업그레이드 뒤 한 세션을 돌려 메시지 순서와 되돌린 메시지가 섞이지 않았는지 확인한다 → 순서가 뒤섞인 기록으로 잘못된 사후 분석을 하는 일을 막는다
  - `CLAUDE_CODE_RETRY_WATCHDOG`로 무인 재시도를 켠 운영자 → 2.1.311에서 "재시도하지 말라는 응답은 다시 안 보낸다"가 반영됐는지 야간 로그로 본다 → 밤새 같은 거부 요청을 반복해 한도를 태우는 일을 줄인다
  - 서브에이전트마다 격리 worktree를 쓰는 사람 → 백그라운드 서브에이전트가 도는 동안 worktree가 지워지는 문제가 고쳐졌으니, 이전에 우회로 넣어 둔 "worktree 삭제 막기" 코드를 걷어 낸다 → 우회 코드의 유지 부담이 사라진다
