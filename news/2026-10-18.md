## 1. 모드는 샌드박스 밖에서 내 권한으로 돈다 — `/plugin install`은 이제 `npm install`이고, 설치 전 `claude plugin validate`의 두 줄을 봐야 한다
- 날짜: 2026-10-17
- 출처: https://dev.to/gabrielanhaia/claude-code-mods-run-unsandboxed-with-your-permissions-plugin-install-is-npm-install-now-2c3m
- 요약: 2.1.287부터 기본으로 켜진 모드는 플러그인이 싣고 오는 JS/TS 코드로, Claude Code 프로세스 안에서 세션 내내 떠 있다. 샌드박스는 Claude의 Bash 명령만 가두므로 모드가 띄운 프로세스는 밖에서 돌고, 모드의 승인은 내 권한 규칙과 `PreToolUse` 훅을 덮을 수 있다. 글쓴이는 설치 전 `claude plugin validate`가 찍는 `hooks:`(처리하는 이벤트)와 `calls:`(쓰는 API) 두 줄을 모드가 주장하는 기능과 대조하라고 권하고, 서드파티 마켓플레이스는 자동 갱신을 끄고 태그로 고정하라고 한다. 댓글은 태그 고정이 런타임에 받아오는 패키지(`npx -y 패키지`로 띄우는 MCP 서버)까지는 얼리지 못한다고 지적한다.
- 현실 적용:
  - 커뮤니티 마켓플레이스에서 플러그인을 자주 설치하는 개인 개발자 → 설치 전에 `claude plugin validate --json ./플러그인`을 돌려 `$.process.run`·`$.http.fetch`·`$.env.get` 같은 위험 호출이 있는 모드를 걸러내는 스크립트를 쓴다 → 날씨 알림 모드가 환경 변수의 API 키를 읽는 경우를 설치 전에 본다
  - 사내 플러그인 마켓플레이스를 운영하는 플랫폼팀 → 플러그인 PR마다 모드가 요청하는 기능 목록(훅 이벤트·`$.` 호출)을 뽑아 이전 버전과 비교하는 CI 단계를 둔다 → 패치 버전 하나에 `$.http.fetch`가 슬쩍 추가돼도 리뷰어가 본다
  - 플러그인이 번들한 MCP 서버가 있는 저장소 → `.mcp.json`·`plugin.json`의 `mcpServers` 명령에서 `npx -y 패키지`처럼 버전이 없는 줄을 찾아 `패키지@1.2.3`으로 고정한다 → 태그를 고정해도 세션 시작마다 새 버전을 받아오는 공급망 구멍을 막는다
  - 보안 담당자 → `tool.check`·`tool.call` 훅으로 도구 호출을 승인하는 모드를 허용 목록에 이름이 있는 것으로만 제한하는 점검표를 만든다 → 모드가 deny 규칙을 덮는 경우를 한 번에 센다
  - 이 저장소의 `turn-notify` 모드 → 새 점검 도구로 자기 모드를 먼저 돌려 `$.command.register`·`$.ui.notify`만 쓰는지 확인하고 README에 그 출력을 붙인다 → 직접 만든 모드도 같은 기준으로 신뢰 근거를 남긴다

## 2. 작업 폴더 밖 편집을 막는 모드 30줄 — 훅이 던지거나 시간 초과하면 건너뛰므로 `.catch`로 실패 시 거부하게 해야 한다
- 날짜: 2026-10-17
- 출처: https://dev.to/gabrielanhaia/your-first-claude-code-mod-block-edits-outside-the-tasks-worktree-in-30-lines-6k
- 요약: `tool.call` 훅을 `Edit`·`Write`에만 걸고 `e.file_path`가 세션 시작 디렉터리(`$.session.root()`) 안인지 확인해, 밖이면 거부 사유를 Claude에게 쓰는 지시문으로 돌려준다. 훅이 예외를 던지거나 시간 초과가 나면 그냥 건너뛰어 편집이 통과하므로, 호출 체인에 `.catch`를 붙여 실패 시 거부(fail closed)로 만든다. 경로 비교는 `/work/app-old`가 `/work/app`으로 오인되지 않게 끝의 `/`까지 본다. Bash의 `sed -i`·`echo >`, `NotebookEdit`, MCP 도구, 심볼릭 링크는 막지 못한다고 글쓴이가 적었다.
- 현실 적용:
  - 병렬 워크트리로 여러 Claude를 돌리는 개발자 → 작업 폴더 밖 쓰기를 막는 모드와 같은 규칙을 `PreToolUse` 훅(Python)으로도 만들어 둘을 비교한다 → 한 워크트리의 Claude가 형제 브랜치 폴더를 고쳐 놓는 사고를 막는다
  - 모드를 처음 만드는 팀 → 승인·거부 훅이 있는 모드마다 `.catch` 유무를 검사하는 린트를 `claude plugin validate`와 함께 CI에 넣는다 → 훅이 시간 초과로 건너뛰어져 가드가 조용히 꺼지는 일을 막는다
  - 이 저장소의 daily-lab 루틴 → 오늘 폴더(`days/<오늘>-*`) 밖 쓰기를 거부하는 가드의 경로 비교(끝 `/` 포함)를 테스트 케이스로 먼저 만든다 → "다른 날짜 폴더 수정 금지" 규칙을 사람이 아니라 코드가 지킨다
  - 모노레포 한 패키지만 맡기는 팀 → 가드가 막지 못하는 `sed -i`·MCP 쓰기 경로를 표로 정리해 훅 규칙 보강 목록으로 쓴다 → 모드 하나로 충분하다고 믿고 비는 구멍을 알고 시작한다
  - 심볼릭 링크를 쓰는 저장소 → 링크가 폴더 밖을 가리키는 경로를 점검하는 스크립트를 따로 돌린다 → 경로 문자열은 안쪽인데 실제로는 밖을 고치는 우회를 찾는다

## 3. 세션 로그는 30일 뒤 지워진다 — 지워지기 전에 gzip으로 묶고 해시를 확인한 뒤에만 원본을 지우는 백업 방식
- 날짜: 2026-10-17
- 출처: https://dev.to/haoli/session-archive-back-up-claude-code-session-logs-before-the-30-day-auto-delete-17a8
- 요약: Claude Code는 `~/.claude/projects/*.jsonl` 세션 로그를 기본 30일 뒤 지운다고 글쓴이는 쓴다. 그가 만든 `session-archive`는 보존 기간이 지난 세션을 `YYYY-MM/<세션ID>.jsonl.gz`로 압축하고, 복사본을 바이트 단위로 확인한 뒤에야 원본을 지우며, 세션 ID·메시지 수·미리보기·sha256을 JSON 색인에 남겨 검색·복원한다. 홍보성 글이라 주장은 글쓴이의 테스트 11개 외에는 검증되지 않았다.
- 현실 적용:
  - Claude Code를 하루 종일 쓰는 개인 개발자 → 한 달 전 세션에서 "그때 왜 이 설계를 골랐지"를 찾을 수 있게 매주 cron으로 오래된 세션을 압축·색인한다 → 30일이 지나 조사 근거가 사라지는 일을 막는다
  - 감사 요구가 있는 팀 → 아카이브 색인에 sha256을 넣고 월별 폴더를 읽기 전용 저장소에 올린다 → 에이전트가 무엇을 했는지 석 달 뒤에도 증거로 낸다
  - 비용 분석을 하는 사람 → 압축 전에 세션별 토큰 사용량을 한 줄 CSV로 뽑아 둔다 → 로그가 지워진 뒤에도 월별 비용 추세를 그린다
  - 야간 배치를 돌리는 서버 → 세션 로그에서 API 키 형태 문자열을 가린 뒤 보관하는 단계를 둔다 → 보관한 로그가 비밀값 유출 경로가 되는 일을 막는다
  - 이 저장소의 daily-lab 루틴 → Actions 러너는 매번 새로 뜨므로 실행이 끝날 때 세션 로그를 아티팩트로 올리는 단계를 추가한다 → 결과물이 없는 날 왜 실패했는지 로그로 거슬러 간다

## 4. claude-cookbooks에 에이전트 보안 검토 쿡북 — 에이전트에게 허용한 범위를 먼저 글로 쓰고, 끝난 세션 로그를 규칙 60개로 거른 뒤 Claude가 순위 보고서를 쓴다
- 날짜: 2026-10-17
- 출처: https://github.com/anthropics/claude-cookbooks/commit/a162e0184e71b60290808a43961a6cbc8060123c
- 요약: `managed_agents/CMA_agent_security_review.ipynb`와 `log_review_utils.py`가 추가됐다. 에이전트가 할 수 있는 일(`allowed_hosts` 같은 허용 필드와 "알려진 구멍")을 템플릿으로 적고, Managed Agents·Messages API·Agent SDK 로그를 공통 대화 기록 형식으로 바꾼 뒤, 코드로 짠 규칙(예제에 60개)이 수상한 행동을 먼저 표시하고, 마지막에만 모델(기본 Haiku 5.5)이 검토해 근거 인용이 달린 순위 보고서를 낸다. 예제 세션 20개를 검토하는 비용은 Haiku 5.5로 약 0.09달러, Opus 5.5로 약 2.79달러라고 적혀 있다. 노트북 코드는 읽지 못해 정확한 API 호출은 확인하지 못했다.
- 현실 적용:
  - Claude Code를 CI에서 돌리는 팀 → 세션 로그에서 `.github/`·`.env` 쓰기, 허용 목록 밖 호스트 접속을 잡는 결정적 규칙 20개를 먼저 짠다 → 모델 호출 없이도 하루 수백 세션 중 사람이 볼 것만 남긴다
  - 에이전트 권한을 정할 때 → 허용 호스트·허용 경로·"알려진 구멍"을 한 장짜리 설명 파일로 먼저 쓰고 이후 설정을 그 파일에서 파생시킨다 → 권한 설정이 늘 코드와 따로 노는 문제를 줄인다
  - 보안 담당자 → 지난달 Claude Code 세션 로그를 위 규칙에 통과시켜 위반 건수를 주 단위로 센다 → "에이전트가 선을 넘었나"를 느낌이 아니라 숫자로 답한다
  - 야간 에이전트를 운영하는 개인 → 아침에 규칙 위반 세션만 요약해 메일로 받는다 → 밤새 돈 작업을 전부 읽지 않고도 이상 행동을 놓치지 않는다

### 1. design-bounce ← 2. 훅이 예외·시간 초과로 건너뛰면 가드가 꺼진다 (fail closed)
- 근거: `hooks/spec-gate.sh`·`hooks/screenshot-gate.sh`가 `PreToolUse`에 배선되는 강제 게이트이고(`hooks/install.md`), 상태는 `hooks/lib/state.sh`로 읽는다. `test/test-hooks.sh`와 `test/fixtures/state-design-approved.json`·`state-design-unapproved.json`·`state-loop-step2.json`만 있어 상태 파일이 깨지거나 없는 경우 테스트는 없다. README는 `jq`가 없으면 경고만 하고 설치를 계속한다고 적었다.
- 할 일: `test/fixtures/`에 손상된 JSON·빈 파일·상태 파일 없음 케이스를 추가하고, `test/test-hooks.sh`에서 두 게이트가 이 경우에 승인이 아니라 차단으로 끝나는지 검사한다. 필요하면 `hooks/lib/state.sh`에서 `jq` 실패를 차단으로 처리하게 고친다. `hooks/install.md`에는 훅 오류가 나면 건너뛰어지는지 확인하는 절차를 한 줄 덧붙인다.
- 이득: `jq` 누락이나 상태 파일 손상 때문에 명세 선승인 게이트가 조용히 꺼져 승인 전 소스 수정이 통과하는 일을 막는다.
- 크기: 30분
