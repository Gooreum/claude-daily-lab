# idea-grader — "현실 적용 아이디어"를 채점하는 작은 eval

## 1. 무엇을 만들었나

Python CLI `idea_grader.py`(표준 라이브러리만). `news/*.md`의 항목마다 붙는 `- 현실 적용:` 목록을 RULES 1절 기준으로 채점해 Markdown 표와 "고칠 줄" 목록을 낸다.

- **규칙 채점(결정적, 키 불필요)**: 항목당 5개 이상(중복 변주는 하나로), 줄마다 `어디에 → 무엇을 → 왜 이득` 화살표 2개와 20~220자, "활용 가능"·"도움이 될 것" 같은 막연한 말 없음, 맥락 3종 이상 섞임(repo/team/product/personal 키워드), 같은 아이디어의 변주 없음(앞 두 구간의 문자 바이그램 Jaccard ≥ 0.55). 0~100점.
- **모델 판정(`--judge`, 선택)**: Haiku 5.5에 항목당 `claude -p --json-schema` 1회로 줄마다 구체성 0~2·이득 0~2를 받는다. 합계는 규칙 70 : 판정 30.
- **힐클라이밍 비교(`--compare`)**: 같은 번호 항목끼리 전·후 점수 차. 평균이 오르고 내린 항목이 없을 때만 `✅ 채택`, 아니면 `⚠ 되돌리기 검토`.
- 5개 미만 항목이 있으면 exit 1이라 CI 게이트로 쓸 수 있다.

## 2. 왜 만들었나

10월 7일 claude.dev 블로그 "eval 설계와 힐클라이밍 자동화"(10월 수집 6번)의 현실 적용 3번이 "이 저장소 → 수집 단계의 현실 적용 아이디어 품질을 채점하는 작은 eval → 루틴 프롬프트를 힐클라이밍"이었다. 오늘 RULES 1절에 "현실 적용 5개 이상, 어디에→무엇을→왜 이득, 막연한 말 금지, 맥락 섞기, 변주 금지" 규칙을 넣었는데 지키는지 확인하는 수단이 없었다. 블로그가 말한 eval의 네 조건(실제 작업을 닮고, 어려운 사례가 있고, 100% 아래 여유가 있고, 분산이 낮다)을 이 저장소의 실제 산출물로 시험해 보고 싶었다.

## 3. 어떻게 만들었나

1. **파싱**: `## N. 제목` 아래 `- 현실 적용:` 블록의 `  - ` 줄만 아이디어로 본다. 블록이 없거나 다른 최상위 불릿이 나오면 닫는다.
2. **줄 검사 `check_line`**: 화살표 개수, 길이, 막연한 말(목록에서 더 긴 매치에 포함되는 짧은 매치는 제외), `→` 앞 "어디에" 구간의 키워드로 맥락 분류.
3. **항목 점수 `rule_score`**: 개수 30(유효 개수/5), 형식 30, 막연한 말 없음 20, 맥락 다양성 10(3종이면 만점), 중복 없음 10.
4. **판정 `run_judge`**: 시스템 프롬프트에 채점 기준을 두고 `--json-schema`로 `{ideas:[{index, concrete, benefit, note}]}`를 받는다. `--max-turns 3`(구조화 출력은 턴을 하나 더 쓴다), `--tools ""`, `--effort low`. 실패는 `판정 실패: …` 한 줄로 남기고 표는 그대로 낸다.
5. **샘플**: 4절(폴더 밖 참조 금지)대로 오늘 news의 1·2번 항목을 `samples/news-sample.md`에 복사하고, 채점기가 잡아야 할 문제를 모은 3번(막연한 말 2줄, 화살표 1개짜리 1줄, 변주 1쌍, 총 4개)을 붙였다. `news-sample-fixed.md`는 3번을 고친 판이라 `--compare`의 "채택" 경로를 보여 준다.

## 4. 사용법

```bash
cd days/2026-10-10-idea-grader
python3 idea_grader.py ../../news/2026-10-10.md                 # 오늘 수집 채점
python3 idea_grader.py ../../news/2026-10-october-all.md --worst 10
python3 idea_grader.py ../../news/2026-10-10.md --judge --items 1,5   # Haiku 판정 (항목당 1호출, 0.3센트)
python3 idea_grader.py before.md --compare after.md            # 프롬프트 수정 전·후
python3 idea_grader.py samples/news-sample.md --json

bash test.sh   # unittest 17건 + 샘플 채점 + 비교 (키 불필요)
bash e2e.sh    # 실제 Haiku 판정 3회, 1센트 미만
```

## 6. 한계와 다음 아이디어

- **규칙 채점은 포화됐다.** 실제 파일 평균 95~98점이라 블로그가 말한 "100% 아래 여유"가 없다. 형식은 이미 다 지키고 있어서 규칙만으로는 프롬프트 개선을 못 잰다. 여유는 모델 판정 쪽에 있다(같은 93점 항목이 75 대 35). 힐클라이밍을 하려면 `--judge`를 기본으로 켜고 분산(같은 입력 반복 시 점수 흔들림)을 먼저 재야 한다.
- 맥락 분류는 키워드라 "외국어 사용자"처럼 목록에 없는 주어는 `other`로 빠진다. 변주 탐지는 앞 두 구간만 봐서 "왜 이득"만 다른 변주는 못 잡는다(의도).
- 판정 프롬프트가 채점기 편향(같은 모델이 쓴 글을 후하게)을 안 피한다. 수집은 Fable, 판정은 Haiku라 모델은 다르지만 검증한 건 아니다.
- 다음: 아침 루틴 끝에 `python3 idea_grader.py news/$(date +%F).md`를 넣어 5개 미만이면 푸시 전에 멈추기. train/test 분리(10월 33개 항목을 반으로)로 수집 프롬프트 두 판을 `--compare --judge`로 비교. `/claude-api hillclimb` 스킬과 같은 입력 형식으로 맞추기.
